**Tokenizer（分词器）算法**。在现代 NLP 和大语言模型中，主流方案可以分为以下几类。

## 1. 词级分词：Word-level Tokenization

直接把完整单词作为 token。

```text
I love machine learning
→ ["I", "love", "machine", "learning"]
```

**优点：**

* token 序列较短
* 每个 token 的语义相对完整

**缺点：**

* 词表非常大
* 容易出现未登录词 `UNK`
* 对拼写变化、词形变化和中日韩等无空格语言不友好

目前很少作为通用 LLM 的核心方案，更多用于传统 NLP。

---

## 2. 字符级分词：Character-level Tokenization

每个 Unicode 字符作为一个 token。

```text
tokenizer
→ ["t", "o", "k", "e", "n", "i", "z", "e", "r"]

中国
→ ["中", "国"]
```

**优点：**

* 词表小
* 基本不会出现未登录词
* 对拼写错误和生僻词较稳健

**缺点：**

* 序列明显变长
* Transformer 的计算开销随序列长度增长
* 单个 token 携带的语义较少

---

## 3. BPE：Byte Pair Encoding

BPE 是当前最主流的**子词分词算法**之一。

训练时通常从字符或字节开始，不断寻找语料中频率最高的相邻 token 对，并将它们合并：

```text
初始：
l o w
l o w e r

可能依次合并：
l + o  → lo
lo + w → low
e + r  → er
```

最终可能得到：

```text
lower → ["low", "er"]
```

高频词可能被保留为一个 token，低频词会被拆成多个子词。BPE 因而兼顾了词表大小和序列长度，并能通过子词组合表示罕见词。([ACL Anthology][1])

**特点：**

* 训练和推理相对简单
* 分词通常是确定性的
* 对高频字符串压缩效果好
* 合并规则不一定符合语言学词素边界

### Byte-level BPE

Byte-level BPE 先把文本转换为 UTF-8 字节，再执行 BPE。

```text
文本 → UTF-8 bytes → BPE tokens
```

理论上任何输入都可以由基础字节表示，因此不需要因为生僻字符而使用普通的 `UNK` token。OpenAI 的 `tiktoken` 就是 BPE tokenizer 的实现。([GitHub][2])

常见于：

* GPT 系列 tokenizer
* RoBERTa 类模型
* 许多现代 decoder-only LLM

---

## 4. WordPiece

WordPiece 是 BERT 系模型中最具代表性的子词算法。BERT 使用约 30,000 个 WordPiece token。([arXiv][3])

编码时通常采用 **Longest Match First（最长匹配优先）**：

```text
unaffable

词表中存在：
un
aff
able
a
...

结果：
["un", "aff", "able"]
```

在经典 BERT 表示中，非词首片段经常带有 `##`：

```text
playing → ["play", "##ing"]
```

WordPiece 的词表学习目标与 BPE 不完全相同：BPE 主要按相邻对频率合并，而 WordPiece 更偏向选择能够改善语料概率建模的子词；编码阶段则通常使用从左到右的最长匹配。([ACL Anthology][4])

**特点：**

* 推理阶段简单、确定
* 适合 BERT 类 encoder 模型
* 未找到完整覆盖路径时可能产生 `UNK`
* 对词表和预分词规则较敏感

---

## 5. Unigram Language Model

Unigram 的训练方向与 BPE 相反：

* BPE 从小词表开始，不断合并
* Unigram 从一个很大的候选词表开始，不断删除不重要的 token

它为每个 token 学习概率，并选择整体概率最高的分词路径：

[
\operatorname*{argmax}_{x_1,\ldots,x_n}
\prod_i P(x_i)
]

例如：

```text
unigram
```

可能存在多种切分：

```text
["uni", "gram"]
["un", "i", "gram"]
["u", "ni", "gram"]
```

编码时可通过动态规划或 Viterbi 算法选择概率最高的路径；训练时也可以随机采样不同切分，用于 subword regularization。([ACL Anthology][5])

**特点：**

* 能自然表示多种候选切分
* 适合子词正则化和数据增强
* 在多语言模型中很常见
* 训练过程比标准 BPE 更复杂

---

## 6. SentencePiece

严格来说，**SentencePiece 不是单一的分词算法，而是一套 tokenizer 框架和实现**。

它主要支持：

* BPE
* Unigram
* Character
* Word

SentencePiece 的重要特征是可以直接从原始文本训练，不要求先按空格完成预分词；空格也会被当作普通符号处理，通常显示成 `▁`：

```text
Hello world
→ ["▁Hello", "▁world"]
```

这使它对中文、日文以及多语言语料较方便。([ACL Anthology][6])

因此：

```text
SentencePiece-BPE
```

表示使用 SentencePiece 框架训练和执行 BPE；而：

```text
SentencePiece-Unigram
```

表示使用 SentencePiece 框架运行 Unigram 模型。

---

## 7. 纯字节分词：Byte-level Tokenization

直接把 UTF-8 字节作为 token，不再学习 BPE 合并。例如：

```text
A → [65]
```

一个中文字符在 UTF-8 中通常对应多个字节，因此会产生多个 token。

**优点：**

* 固定词表，通常只有 256 个基础字节加特殊 token
* 完全开放词表
* 能处理任意 Unicode、乱码片段和混合编码文本

**缺点：**

* token 序列很长
* 训练和推理成本较高
* 模型需要自己学习字节到字符、词语和语义的组合关系

这类方案在 byte-level 或 token-free 模型中使用，但在通用 decoder-only LLM 中，**字节级 BPE**通常比完全不合并的纯字节方案更常见。

## 主流方案对比

| 算法             | 基础单位       | 词表学习方式        | 编码方式    | 代表场景          |
| -------------- | ---------- | ------------- | ------- | ------------- |
| Word-level     | 单词         | 统计词频          | 查词表     | 传统 NLP        |
| Character      | Unicode 字符 | 字符集合          | 逐字符     | 字符模型          |
| BPE            | 字符或字节      | 反复合并高频相邻对     | 按合并规则编码 | GPT 类模型       |
| Byte-level BPE | UTF-8 字节   | 对字节序列执行 BPE   | 字节映射后合并 | 现代 LLM        |
| WordPiece      | 子词         | 基于概率增益构建词表    | 最长匹配优先  | BERT 类模型      |
| Unigram        | 候选子词       | 从大词表逐步剪枝      | 最大概率路径  | 多语言模型         |
| SentencePiece  | 原始文本       | BPE 或 Unigram | 由所选模型决定 | 多语言、无空格语言     |
| Pure Byte      | UTF-8 字节   | 通常无须学习        | 逐字节     | Token-free 模型 |

## 实际上最需要掌握的三种

现代 NLP 中，核心的三种子词算法是：

1. **BPE / Byte-level BPE**：现代生成式 LLM 中非常常见
2. **WordPiece**：BERT 系模型的典型方案
3. **Unigram**：通常结合 SentencePiece，用于多语言和概率化分词

其中容易混淆的一点是：

> **SentencePiece 和 tiktoken 是实现框架或库；BPE、WordPiece、Unigram 才是分词算法。**
