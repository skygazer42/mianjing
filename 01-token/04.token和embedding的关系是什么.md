# 04. token 和 embedding 的关系是什么？

文字 → tokenizer 切成 tokens  
→ tokens 查词表变成 token ids  
→ token ids 查 embedding table  
→ 得到 embedding 向量  
→ 进入 Transformer  

基本理解对了，但有两个地方要修正一下。  

你现在的理解是：  
文字 → tokenizer → token → embedding → 向量空间坐标  

这个大方向是对的。  

但更准确应该是：  
文字  
→ tokenizer 切成 tokens  
→ tokens 查词表变成 token ids  
→ token ids 查 embedding table  
→ 得到 embedding 向量  
→ 进入 Transformer  

1. 不是“每一个字都算 token”  
这个要注意。  

有些 tokenizer 可以是字符级的：  
我 / 爱 / A / I  

但大模型一般不是简单按字切，而是按“常见片段”切。  

比如：  
我爱人工智能  

可能切成：  
["我", "爱", "人工智能"]  

也可能切成：  
["我", "爱", "人工", "智能"]  

也可能更碎：  
["我", "爱", "人", "工", "智", "能"]  

这取决于 tokenizer 和它的词表。  

所以更准确地说：  
token 是 tokenizer 切出来的最小处理单位，不一定是一个字，也不一定是一个词。  

2. tokenizer 不是负责“向量化”的  
这个很关键。  

tokenizer 做的是切分和编号。  

比如：  
I love AI  

tokenizer 做：  
["I", " love", " AI"]  

然后查词表：  
"I"     → 1  
" love" → 2  
" AI"   → 3  

得到：  
[1, 2, 3]  

到这里还是整数编号。  

3. embedding 才是负责“向量化”的  
embedding table 做：  
1 → [0.12, -0.33, 0.91, ...]  
2 → [0.78,  0.10, -0.22, ...]  
3 → [-0.45, 0.66, 0.31, ...]  

所以：  
token id → embedding 向量  

这一步才是真正进入数学空间。  

4. 你可以这样改写你的理解  
更准确版本是：  
词表里不是每一个字，而是 tokenizer 学出来的一堆 token 片段。tokenizer 负责把文本切成 token 并转换成 token id；embedding table 负责把 token id 转成向量，也就是模型数学空间里的坐标。  
5. 不同 tokenizer 会影响什么？  
不同 tokenizer 会影响：  
同一句话怎么切  
token 数量多少  
每个 token 对应什么 id  
词表里有哪些 token  
比如模型 A：  
"人工智能" → 一个 token  

模型 B：  
"人工" / "智能" → 两个 token  

模型 C：  
"人" / "工" / "智" / "能" → 四个 token  

但是 tokenizer 本身不是 embedding。  

流程一定是：  
tokenizer：文字 → token ids  
embedding：token ids → 向量  

一句话最终版：  
tokenizer 是“切词和编号器”，embedding 是“编号到向量坐标的查表器”。token 是模型词表里的文字片段，不一定是一个字。
