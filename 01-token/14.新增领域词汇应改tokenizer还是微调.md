# 14. 如果新增领域词汇，应该改 tokenizer 还是只做微调？

## 回答

大多数情况下先不改 tokenizer，而是用领域数据继续预训练、微调、RAG 或提示词约束。只要术语还能被现有 tokenizer 拆出，模型通常可以通过上下文学习其含义，成本也远低于重训 tokenizer。

当领域语料规模大、术语长期高频、现有切分极度碎片化并显著拉高成本时，才值得评估扩充或重训 tokenizer。例如大量专有编码、化学式、基因序列或内部 DSL 在每次输入中都占很大比例。

改 tokenizer 后需要调整并重新训练 embedding 和输出层，且会破坏原 token ID 的兼容性；仅添加 token 而不充分训练其参数，也未必有效。

## 面试要点

决策依据是领域词出现频率、token 膨胀比例、数据规模、模型重训预算和兼容性要求，而不是“看到新词就加词表”。


---

**通常先不改 tokenizer，优先做领域继续预训练，再做任务微调。**

原因是大多数现代 tokenizer（BPE、WordPiece、SentencePiece）即使没有完整收录某个领域词，也能把它拆成多个子词。模型仍然可以通过训练学会该术语的含义。直接修改 tokenizer 会带来额外成本：

* 词表大小和 token ID 发生变化
* 需要扩展输入 embedding 和输出层
* 新 token 的向量没有经过预训练
* 原模型权重、检查点和部署链路可能不再完全兼容
* 仅做少量监督微调时，新 token 往往学不充分

#### 推荐路径

1. **领域术语只是模型“不理解”**

   保持原 tokenizer，使用领域语料做：

   * 领域继续预训练，Domain-Adaptive Pretraining
   * 再进行 SFT、LoRA 或具体任务微调

2. **领域词被切得很碎，导致序列明显变长**

   可以考虑扩充 tokenizer。例如大量化学式、基因序列、医学缩写、代码符号或特殊编号，每个概念都被拆成很多 token。

3. **出现无法稳定表示的字符或特殊结构**

   例如专用控制符、结构化标记、特殊模态占位符，可以新增 token。

#### 判断标准

可以先统计领域语料：

* 每个领域术语平均被拆成几个 token
* 领域语料的平均 token 数是否显著高于通用语料
* 高频术语是否普遍被拆成 5～10 个以上 token
* 上下文长度和推理成本是否因此明显增加

若只是少量新词被拆成 2～4 个子词，**没有必要改 tokenizer**。

若大量高频术语被严重碎片化，造成明显的长度、速度或效果问题，才考虑：

> 扩充词表 → 初始化新 token embedding → 使用足够规模的领域语料继续预训练 → 再进行任务微调。

**结论：语义问题靠继续预训练或微调；分词效率和表示问题才改 tokenizer。**


可以把它理解成两个不同问题：

* **Tokenizer 决定：一句话被切成哪些小块。**
* **微调决定：模型怎么理解这些小块，以及怎么回答。**

下面用一个完整例子说明。

---

## 例子：训练一个医疗领域客服模型

假设基础模型没怎么见过这个术语：

> 经导管主动脉瓣置换术

Tokenizer 可能把它切成：

```text
经 / 导 / 管 / 主动脉 / 瓣 / 置换 / 术
```

也可能切成：

```text
经导 / 管 / 主动 / 脉 / 瓣 / 置 / 换 / 术
```

注意：**它虽然没有把整个术语当成一个 token，但仍然能表示这句话。**

---

# 情况一：模型认识字，但不懂术语

用户问：

> 经导管主动脉瓣置换术适合哪些患者？

模型回答：

> 这是一种导管检查方法，主要用于观察血管。

这个回答错了。

问题不在 tokenizer。因为 tokenizer 已经成功把这句话切出来了，模型也能读取这些 token。

真正的问题是：

> 模型不知道“经导管主动脉瓣置换术”具体是什么。

这时应该做的是**领域训练或微调**。

训练数据可以是：

```text
问题：什么是经导管主动脉瓣置换术？

回答：经导管主动脉瓣置换术，简称 TAVR 或 TAVI，是一种通过导管植入人工主动脉瓣的治疗方式，主要用于部分主动脉瓣狭窄患者。
```

再增加一些任务数据：

```text
问题：哪些患者可能考虑 TAVR？

回答：通常需要结合患者的主动脉瓣狭窄程度、症状、年龄、手术风险以及多学科评估结果综合判断。
```

经过微调后，模型可能正确回答：

> 经导管主动脉瓣置换术主要用于治疗严重主动脉瓣狭窄，尤其适用于部分传统外科手术风险较高的患者，具体需要心脏团队评估。

这里 tokenizer 完全没改，但模型已经学会了术语。

所以：

> **模型能切出来，但不理解含义，应该微调，不应该先改 tokenizer。**

---

# 情况二：词被切得太碎，严重浪费上下文

再看一个特殊领域，例如化学。

假设数据中反复出现：

```text
2,2'-azobis(2-methylpropionitrile)
```

这是一个高频化学名称。

原 tokenizer 可能把它切成：

```text

-

-

```

假设一个词被切成了 **16 个 token**。

而你的每篇化学文档中，这个名称出现 100 次，那么单是这个词就消耗：

```text
16 × 100 = 1600 tokens
```

假如将它加入 tokenizer，变成一个独立 token：

```text
[2,2'-azobis(2-methylpropionitrile)]
```

那么 100 次只需要：

```text
1 × 100 = 100 tokens
```

节省了 1500 个 token。

这种情况下，修改 tokenizer 可能有价值，因为它解决的是：

* 文本过长
* 推理速度变慢
* 上下文空间浪费
* 某些专有符号被异常拆分

但仅仅把新词加入 tokenizer 还不够。

新 token 加进去之后，它的 embedding 一开始基本是“空白知识”。模型并不知道这个 token 是什么。

完整流程应该是：

```text
1. 给 tokenizer 增加新 token
2. 扩展模型的 embedding 矩阵
3. 初始化新 token 的 embedding
4. 使用大量化学领域文本继续预训练
5. 再进行具体任务微调
```

所以，**改 tokenizer 并不能代替训练**。

---

# 情况三：新增的是特殊控制符

假设你要训练一个医学报告生成模型，输入中需要明确标记不同区域：

```text
<症状>胸痛、呼吸困难</症状>
<检查>主动脉瓣重度狭窄</检查>
<诊断>主动脉瓣狭窄</诊断>
```

这里的：

```text
<症状>
</症状>
<检查>
</检查>
<诊断>
</诊断>
```

最好作为特殊 token 加入 tokenizer。

原因不是模型不理解“症状”这两个字，而是你希望这些标记具备稳定的结构意义：

```text
<症状> = 症状区域开始
</症状> = 症状区域结束
```

这种属于**结构控制需求**，适合新增 token。

然后仍然需要微调，让模型学会这些 token 的使用规则。

# 一个更直观的比喻

把模型想成一个学生。

## Tokenizer 像“断句和认字方式”

看到：

> 经导管主动脉瓣置换术

学生可能按下面方式读：

```text
经导管 / 主动脉瓣 / 置换术
```

也可能读成：

```text
经 / 导 / 管 / 主动脉 / 瓣 / 置换 / 术
```

只要他能把字都读出来，就不代表必须给整句话造一个新字。

## 微调像“学习专业知识”

学生虽然会读：

> 经导管主动脉瓣置换术

但他不知道是什么意思。

这时需要给他上医学课，而不是修改字典。

所以：

* **读不出来或切得极其低效**：考虑 tokenizer。
* **读得出来但不知道意思**：做微调或继续预训练。

---

# 实际判断方法

假设新增了 1 万个医疗术语。

先拿真实领域语料跑一次原 tokenizer，统计每个术语被切成多少 token。

例如：

| 术语                  | 切分结果                      | token 数 | 建议              |
| ------------------- | ------------------------- | ------: | --------------- |
| 心房颤动                | 心房 / 颤动                   |       2 | 不改 tokenizer    |
| 主动脉瓣狭窄              | 主动脉 / 瓣 / 狭窄              |       3 | 不改 tokenizer    |
| 经导管主动脉瓣置换术          | 经 / 导管 / 主动脉 / 瓣 / 置换 / 术 |       6 | 通常仍不必改          |
| 特殊化学长名称             | 被切成十几个片段                  |      15 | 可以考虑增加 token    |
| `<DIAGNOSIS_START>` | 被切成很多符号和字母                |       8 | 建议作为特殊 token 加入 |

不能只看某一个词，还要看它出现得多不多。

例如，一个术语被切成 12 个 token，但整个训练集只出现 20 次，没有必要专门修改 tokenizer。

另一个术语被切成 8 个 token，但在训练集出现 100 万次，就值得考虑。

---

# 最常见的正确方案

例如要做医疗问答模型，通常这样做：

```text
基础模型
    ↓
保持原 tokenizer
    ↓
用医疗书籍、指南、病例做领域继续预训练
    ↓
用医疗问答数据做 SFT 或 LoRA 微调
    ↓
评估医疗术语理解和回答能力
```

只有评估发现：

```text
大量高频术语被切得非常碎
平均文本长度明显增加
上下文容量和训练成本受到明显影响
```

才改成：

```text
扩充 tokenizer
    ↓
扩展 embedding
    ↓
大量领域语料继续预训练
    ↓
任务微调
```

## 最核心的一句话

> 新词不等于必须新增 token。
> 模型“不懂这个词”，主要靠训练；模型“切这个词切得太碎”，才考虑改 tokenizer。
