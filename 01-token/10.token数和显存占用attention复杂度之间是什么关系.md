# 10. token 数和显存占用、attention 复杂度之间是什么关系？

# 10. Token 数、显存占用和 Attention 复杂度是什么关系？

先给出最重要的结论：

| 场景                                      | Token 数从 (N) 变成 (2N) 时 |
| --------------------------------------- | ---------------------: |
| 输入隐藏状态显存                                |            约变为 **2 倍** |
| KV Cache 显存                             |            约变为 **2 倍** |
| 普通全量 Attention 矩阵显存                     |            约变为 **4 倍** |
| Prompt Prefill 的 Attention 计算量          |            约变为 **4 倍** |
| MLP、线性投影计算量                             |            约变为 **2 倍** |
| 整个 Transformer 的计算量                     |        通常在 **2～4 倍之间** |
| 逐 token 解码时，生成下一个 token 的 Attention 计算量 |            约变为 **2 倍** |

因此，“上下文翻倍，计算量一定四倍”这个说法并不完整：

* 对 **Attention 部分的 Prompt Prefill**，接近四倍；
* 对 **KV Cache 显存**，是两倍；
* 对 **整个 Transformer**，需要同时考虑线性层和 MLP，通常介于两倍和四倍之间；
* 对 **生成阶段的单个新 token**，Attention 计算量是线性增长，而不是平方增长。

# 一、先明确 Transformer 中的几个参数

后面统一使用这些符号：

| 符号       | 含义                    |
| -------- | --------------------- |
| (B)      | Batch Size，同时处理的序列数量  |
| (N)      | 每条序列的 token 数         |
| (L)      | Transformer 层数        |
| (d)      | 模型隐藏维度，hidden size    |
| (h_q)    | Query Head 数量         |
| (h_{kv}) | Key/Value Head 数量     |
| (d_h)    | 每个 Attention Head 的维度 |
| (d_{ff}) | MLP 中间层维度             |
| (V)      | 词表大小                  |
| (s)      | 每个数值占用的字节数            |

通常：

```text
d = h_q  ×  d_h
```

例如：

```text
隐藏维度 d       = 4096
Query Head 数    = 32
每个 Head 维度   = 128
```

满足：

```text
32  ×  128 = 4096
```

常见数值类型占用：

| 数据类型       |     每个元素占用 |
| ---------- | ---------: |
| FP32       |    4 bytes |
| FP16       |    2 bytes |
| BF16       |    2 bytes |
| FP8 / INT8 |   约 1 byte |
| INT4 权重    | 约 0.5 byte |

实际显存还会包含量化比例因子、对齐空间、内存碎片和临时工作区。

---

# 二、LLM 中 Transformer 的完整结构

现代大语言模型通常采用 **Decoder-only Transformer**。

整体数据流可以表示为：

```text
文本
  ↓
Tokenizer
  ↓
Token IDs
  ↓
Token Embedding
  ↓
位置编码 / RoPE
  ↓
┌───────────────────────────────┐
│ Transformer Block 1           │
│                               │
│  Norm                         │
│    ↓                          │
│  Self-Attention               │
│    ↓                          │
│  Residual Connection          │
│    ↓                          │
│  Norm                         │
│    ↓                          │
│  MLP / FFN                    │
│    ↓                          │
│  Residual Connection          │
└───────────────────────────────┘
  ↓
重复 L 层
  ↓
Final Norm
  ↓
LM Head
  ↓
词表上的 Logits
  ↓
选择下一个 Token
```

一层典型的 Pre-Norm Transformer 可以写为：

```text
Y = X + Attention(Norm(X))
```

```text
Z = Y + MLP(Norm(Y))
```

其中：

* (X) 是这一层的输入；
* Attention 负责不同 token 之间的信息交换；
* MLP 负责对每个 token 的表示独立进行非线性变换；
* Residual Connection 保留原始信息并改善训练稳定性；
* Norm 通常是 LayerNorm 或 RMSNorm。

# 三、输入 Token 如何变成矩阵

假设：

```text
Batch Size B = 1
Token 数 N   = 4
隐藏维度 d   = 6
```

四个 token 经过 Embedding 后，会形成矩阵：

```text
X  ∈  R^(4  ×  6)
```

可以理解为：

```text
             隐藏维度
Token 1  [x11 x12 x13 x14 x15 x16]
Token 2  [x21 x22 x23 x24 x25 x26]
Token 3  [x31 x32 x33 x34 x35 x36]
Token 4  [x41 x42 x43 x44 x45 x46]
```

更完整地包含 Batch 维度：

```text
X  ∈  R^(B  ×  N  ×  d)
```

因此，单个隐藏状态张量的元素数量是：

```text
B  ×  N  ×  d
```

它的显存占用为：

```text
M_(hidden) = BNd  ×  s
```

这里 token 数 (N) 是一次关系。

所以：

```text
N  →  2N
```

会使隐藏状态显存：

```text
M_(hidden)  →  2M_(hidden)
```

也就是线性增长。

---

# 四、Self-Attention 的内部结构

## 4.1 生成 Q、K、V

输入矩阵 (X) 经过三个线性变换：

```text
Q = XW_Q
```

```text
K = XW_K
```

```text
V = XW_V
```

其中：

* (Q)：Query，当前 token 想查询什么；
* (K)：Key，每个 token 可以被如何匹配；
* (V)：Value，每个 token 实际提供的信息。

在普通 Multi-Head Attention 中：

```text
Q,K,V  ∈  R^(B  ×  h  ×  N  ×  d_h)
```

并且：

```text
h  ×  d_h = d
```

---

## 4.2 计算 Attention Score

每一个 Query 都要与所有 Key 做点积：

```text
S = (QK^T) / (√(d_h))
```

对于单个 Attention Head：

```text
Q  ∈  R^(N  ×  d_h)
```

```text
K^T  ∈  R^(d_h  ×  N)
```

所以：

```text
QK^T  ∈  R^(N  ×  N)
```

这就是 Attention 出现平方复杂度的根本原因。

因为每一个 token 都需要和每一个 token 建立关系：

```text
                 Key
             1   2   3   4
Query 1      ●   ●   ●   ●
Query 2      ●   ●   ●   ●
Query 3      ●   ●   ●   ●
Query 4      ●   ●   ●   ●
```

一共有：

```text
N  ×  N = N^2
```

个 Attention Score。

---

# 五、为什么自回归模型仍然是平方复杂度

Decoder-only 模型使用 Causal Mask。

第 (i) 个 token 只能查看自己和前面的 token，不能查看未来 token。

对于四个 token：

```text
                 Key
             1   2   3   4
Query 1      ✓   ×   ×   ×
Query 2      ✓   ✓   ×   ×
Query 3      ✓   ✓   ✓   ×
Query 4      ✓   ✓   ✓   ✓
```

有效关系数量是：

```text
1 + 2 + 3 + … + N
```

即：

```text
(N(N+1)) / (2)
```

虽然大约只有完整矩阵的一半，但复杂度仍然是：

```text
O(N^2)
```

例如：

| Token 数 | 有效 Attention 关系数 |
| ------: | ---------------: |
|       4 |               10 |
|       8 |               36 |
|      16 |              136 |
|      32 |              528 |
|      64 |             2080 |

从 4 增加到 8，关系数从 10 增加到 36。

随着 (N) 增大，token 数翻倍时，关系数越来越接近四倍：

```text
((2N)^2) / (N^2)=4
```

# 六、Attention 的计算复杂度

## 6.1 (QK^T) 的计算量

单个 Head 中：

```text
Q  ∈  R^(N  ×  d_h)
```

```text
K^T  ∈  R^(d_h  ×  N)
```

矩阵乘法需要大约：

```text
O(N^2d_h)
```

多个 Head 合起来：

```text
O(h_qN^2d_h)
```

因为：

```text
h_qd_h=d
```

所以：

```text
O(N^2d)
```

---

## 6.2 Attention 权重乘以 V

经过 Softmax：

```text
A = softmax(S)
```

然后：

```text
O = AV
```

其中：

```text
A  ∈  R^(N  ×  N)
```

```text
V  ∈  R^(N  ×  d_h)
```

因此这部分也是：

```text
O(N^2d_h)
```

所有 Head 合起来：

```text
O(N^2d)
```

所以完整 Attention 的主要计算量是：

```text
O(N^2d)
```

更具体地，如果把一次乘法和一次加法分别视为一个 FLOP：

```text
QK^T  ≈  2N^2d
```

```text
AV  ≈  2N^2d
```

合计约为：

```text
C_(attention)  ≈  4N^2d
```

这是完整稠密 Attention 的计算口径。高效 Causal Kernel 跳过上三角区域后，实际有效计算量可以接近：

```text
2N^2d
```

但复杂度仍然是 (O(N^2d))。

---

# 七、Transformer 不只有 Attention

Transformer 每层还包含：

1. Q、K、V 线性投影；
2. Attention 输出投影；
3. MLP；
4. Norm；
5. Residual；
6. 激活函数。

其中线性投影和 MLP 对 token 数通常是线性的。

---

## 7.1 Q、K、V 和输出投影

对于标准 Multi-Head Attention，近似有四个 `(d × d)` 矩阵：

```text
W_Q, W_K, W_V, W_O
```

每个 token 的矩阵乘法计算量与 (d^2) 成正比。

所有 token 的复杂度为：

```text
O(Nd^2)
```

按 FLOP 计算，大约是：

```text
8Nd^2
```

---

## 7.2 MLP 的计算量

传统 Transformer MLP 通常是：

```text
d  →  4d  →  d
```

即：

```text
H = σ(XW_1)
```

```text
Y = HW_2
```

两个矩阵乘法的计算量约为：

```text
16Nd^2
```

所以一个标准 Transformer 层可以粗略表示为：

```text
C_(layer)
 ≈
24Nd^2 + 4N^2d
```

其中：

* (24Nd^2)：线性投影与 MLP；
* (4N^2d)：Attention Score 和 Attention × Value。

实际模型使用 SwiGLU、GQA、不同的 (d_{ff}) 后，常数会改变，但关于 (N) 的关系不变：

```text
C_(layer)
=

O(Nd^2 + N^2d)
```

整个 (L) 层模型：

```text
C_(model)
=

O(LNd^2 + LN^2d)
```

---

# 八、为什么上下文翻倍，整个模型不一定正好慢四倍

假设：

```text
C(N)=24Nd^2+4N^2d
```

当 (N) 变成 (2N)：

```text
C(2N)=48Nd^2+16N^2d
```

其中：

* 线性层计算变为两倍；
* Attention 计算变为四倍。

因此整个模型的增长比例是：

```text
(C(2N)) / (C(N))
=

(48Nd^2+16N^2d) / (24Nd^2+4N^2d)
```

当 (N) 相对于 (d) 较小时，MLP 和投影占比更高，整体更接近两倍。

当 (N) 非常大时，(N^2d) 项占主导，整体逐渐接近四倍。

---

## 一个具体例子

设：

```text
d=4096
```

按上述近似公式计算每层前向计算量：

| Token 数 (N) |      线性层和 MLP |      Attention |         每层总计算量 |
| ----------: | ------------: | -------------: | -------------: |
|        4096 |  1.649 TFLOPs |   0.275 TFLOPs |   1.924 TFLOPs |
|        8192 |  3.299 TFLOPs |   1.100 TFLOPs |   4.398 TFLOPs |
|       32768 | 13.194 TFLOPs |  17.592 TFLOPs |  30.786 TFLOPs |
|      131072 | 52.777 TFLOPs | 281.475 TFLOPs | 334.252 TFLOPs |

从 4096 token 增加到 8192 token：

* token 数：2 倍；
* Attention 部分：4 倍；
* 线性部分：2 倍；
* 总计算量：约 2.29 倍。

从 4096 token 增加到 32768 token：

* token 数：8 倍；
* Attention 部分：64 倍；
* 线性部分：8 倍；
* 总计算量：约 16 倍。

这说明在较短序列中，MLP 和线性层可能仍占据大量计算；在超长上下文中，Attention 会逐渐成为主要计算瓶颈。

# 九、Token 数和显存占用的关系

GPU 显存主要由以下部分组成：

```text
显存
=

模型参数
+
梯度
+
优化器状态
+
激活值
+
Attention 临时张量
+
KV Cache
+
工作区和内存碎片
```

不同阶段的主要显存来源不同。

---

# 十、模型参数显存与 Token 数基本无关

假设模型有 (P) 个参数。

仅权重显存为：

```text
M_(weights)=P ×  s
```

例如 70 亿参数模型，使用 BF16：

```text
7 × 10^9 × 2
=

14 × 10^9bytes
```

约为 14 GB，或者约 13.0 GiB。

无论输入是：

* 100 token；
* 4000 token；
* 128000 token；

模型权重本身大小不变。

但运行时激活值和 KV Cache 会随 token 数变化。

---

# 十一、隐藏状态显存是线性增长

每层隐藏状态形状为：

```text
[B,N,d]
```

单个隐藏状态张量显存为：

```text
M_(hidden)=BNds
```

例如：

```text
B = 1
d = 4096
BF16 = 2 bytes
```

则每个 token 的单个隐藏状态占：

```text
4096 × 2=8192bytes
```

即 8 KiB。

| Token 数 | 单个隐藏状态张量 |
| ------: | -------: |
|    4096 |   32 MiB |
|   32768 |  256 MiB |
|  131072 |    1 GiB |

这只是一个隐藏状态张量，不是整个模型的激活显存。

训练时还需要保存：

* 每层输入；
* Q、K、V；
* MLP 中间结果；
* 激活函数输入；
* Norm 相关信息；
* Dropout Mask；
* 反向传播所需张量。

因此训练激活显存通常远大于上表。

---

# 十二、普通 Attention 矩阵显存是平方增长

Attention Score 的形状为：

```text
[B,h_q,N,N]
```

显存为：

```text
M_(score)
=

Bh_qN^2s
```

设：

```text
B   = 1
h_q = 32
BF16/FP16 = 2 bytes
```

则：

| Token 数 | 单层、单个 Attention Score 张量 |
| ------: | -----------------------: |
|    4096 |                    1 GiB |
|   32768 |                   64 GiB |
|  131072 |                    1 TiB |

计算过程如下。

### 4096 token

```text
1 × 32 × 4096^2 × 2
=

1,073,741,824bytes
```

即：

```text
1GiB
```

### 32768 token

```text
1 × 32 × 32768^2 × 2
=

68,719,476,736bytes
```

即：

```text
64GiB
```

### 131072 token

```text
1 × 32 × 131072^2 × 2
=

1,099,511,627,776bytes
```

即：

```text
1TiB
```

而这还只是：

* 一层；
* 一个 Score 或 Probability 张量；
* Batch Size 为 1；
* 没有计算其他激活值；
* 没有算梯度；
* 没有算模型权重。

所以传统实现无法直接为超长上下文保存完整 Attention 矩阵。

---

# 十三、FlashAttention 解决了什么？

FlashAttention 的核心不是取消 Attention，也不是将复杂度变为线性。

它仍然计算：

```text
softmax(QK^T)V
```

它使用分块计算和在线 Softmax：

```text
从显存读取一小块 Q
从显存读取一小块 K、V
在 GPU 片上 SRAM 中计算局部结果
更新 Softmax 统计量和输出
处理下一块
```

这样就不需要把完整的：

```text
[N,N]
```

Attention 矩阵写入 GPU HBM 显存。

因此：

| 项目             | 普通 Attention | FlashAttention |
| -------------- | ------------ | -------------- |
| Attention 临时显存 | (O(N^2))     | 接近 (O(Nd))     |
| Attention 计算量  | (O(N^2d))    | 仍为 (O(N^2d))   |
| 结果             | 精确 Attention | 精确 Attention   |
| 主要收益           | 无            | 减少显存读写和峰值显存    |

所以 FlashAttention 主要解决：

* Attention 矩阵显存爆炸；
* GPU HBM 读写开销；
* Kernel 调度效率。

它没有从根本上消除所有 token 两两交互带来的平方计算量。

---

# 十四、训练阶段的显存关系

训练时需要执行：

1. 前向传播；
2. 保存反向传播所需激活；
3. 计算梯度；
4. 保存优化器状态；
5. 更新参数。

如果使用传统 Attention 实现，训练激活显存可以粗略写为：

```text
M_(activation)
=

O(BLNd)
+
O(BLNd_(ff))
+
O(BLh_qN^2)
```

其中：

* 隐藏状态和 MLP 激活：线性增长；
* Attention Score：平方增长。

使用 FlashAttention 后，可以避免保存完整 (N^2) Attention 矩阵，峰值显存更接近：

```text
O(BLNd)+O(BLNd_(ff))
```

再配合 Activation Checkpointing，可以只保存部分层的激活值，在反向传播时重新计算其他激活。

代价是：

```text
显存减少
但计算量增加
```

训练的前向加反向计算量通常可以粗略视为前向计算量的约三倍，因为矩阵乘法通常需要：

* 一次前向；
* 一次输入梯度；
* 一次权重梯度。

具体比例还会受到 Softmax、Norm、激活函数和重计算策略影响。

---

# 十五、推理需要分成 Prefill 和 Decode

这是理解 Token 数影响的关键。

## 15.1 Prefill 阶段

用户输入一个完整 Prompt：

```text
Token 1, Token 2, ..., Token N
```

模型一次并行处理所有输入 token，建立每一层的 K 和 V。

这一阶段称为：

* Prefill；
* Prompt Encoding；
* Prompt Processing。

Prefill 的 Attention 需要处理输入 token 之间的关系：

```text
1+2+…+N
```

所以 Attention 计算量是：

```text
O(LN^2d)
```

KV Cache 的存储量则是：

```text
O(LN)
```

所以 Prefill 阶段：

* Attention 计算量平方增长；
* KV Cache 显存线性增长。

---

## 15.2 Decode 阶段

Prefill 完成后，模型逐个生成新 token。

假设已有 (N) 个 token，现在要生成第 (N+1) 个 token。

新 token 只产生一个新的 Query：

```text
Q_(new) ∈ R^(1 ×  d_h)
```

它需要与过去所有 Key 计算：

```text
Q_(new)K_(cache)^T
```

其中：

```text
K_(cache)^T ∈ R^(d_h ×  N)
```

输出形状：

```text
[1,N]
```

因此生成一个新 token 时，Attention 计算量是：

```text
O(Nd)
```

而不是：

```text
O(N^2d)
```

原因是过去 token 的 K 和 V 已经被缓存，不需要重新计算过去所有 token 之间的关系。

---

# 十六、KV Cache 是什么？

每层 Attention 都需要过去 token 的 Key 和 Value。

如果不保存 K 和 V，那么每生成一个新 token，都要重新计算整个历史序列。

KV Cache 会保存：

```text
第 1 层：过去所有 token 的 K 和 V
第 2 层：过去所有 token 的 K 和 V
...
第 L 层：过去所有 token 的 K 和 V
```

不需要保存过去 token 的 Query，因为历史 Query 只在历史 token 生成时使用。

KV Cache 显存公式是：

```text
M_(KV)
=

B
 ×  L
 ×  N
 ×  2
 ×  h_(kv)
 ×  d_h
 ×  s
```

这里的 2 表示：

```text
一个 K
一个 V
```

如果有 Beam Search，还需要乘以 Beam 数量，除非推理框架进行了共享优化。

---

# 十七、KV Cache 的详细数值例子

假设一个模型配置为：

```text
层数 L               = 32
隐藏维度 d           = 4096
Query Head 数 h_q    = 32
KV Head 数 h_kv      = 8
Head 维度 d_h        = 128
Batch Size B         = 1
KV 数据类型          = BF16，每个元素 2 bytes
```

这是 GQA，也就是 Grouped-Query Attention。

每个 token 的 KV Cache 为：

```text
32 × 2 × 8 × 128 × 2
```

计算得：

```text
131072bytes
```

即：

```text
128KiB/token
```

因此：

|        上下文长度 | KV Cache |
| -----------: | -------: |
|   4096 token |  512 MiB |
|  32768 token |    4 GiB |
| 131072 token |   16 GiB |

这只是一个请求。

如果同时处理 4 个 128K 请求：

```text
4 × 16=64GiB
```

只 KV Cache 就需要 64 GiB，还没有算模型权重、临时激活和工作区。

---

# 十八、MHA、GQA、MQA 对 KV Cache 的影响

## 普通 Multi-Head Attention

```text
h_(kv)=h_q
```

假设：

```text
h_q  = 32
h_kv = 32
```

每个 Query Head 都有自己独立的 K 和 V Head。

上面同样的模型配置中，每个 token 的 KV Cache 会变成：

```text
32 × 2 × 32 × 128 × 2
=

524288bytes
```

即：

```text
512KiB/token
```

|  上下文长度 | MHA KV Cache |
| -----: | -----------: |
|   4096 |        2 GiB |
|  32768 |       16 GiB |
| 131072 |       64 GiB |

---

## Grouped-Query Attention

多个 Query Head 共享一组 KV Head。

例如：

```text
32 个 Query Head
8 个 KV Head
```

KV Cache 缩小为普通 MHA 的：

```text
(8) / (32)=() / ()14
```

---

## Multi-Query Attention

所有 Query Head 共享同一个 K Head 和 V Head：

```text
h_(kv)=1
```

相对于 32 Head 的 MHA，KV Cache 可以缩小到：

```text
() / ()132
```

但是 GQA 和 MQA 主要降低的是：

* KV Cache 显存；
* KV Cache 带宽；
* K、V 投影开销。

它们没有直接消除 Query 与所有历史位置交互所需要的计算。

Attention Score 在数学上仍然与：

```text
h_qN^2
```

相关。

---

# 十九、完整的 4K 到 32K 对比

仍然使用：

```text
L = 32
d = 4096
h_q = 32
h_kv = 8
d_h = 128
BF16
B = 1
```

上下文从 4096 token 增加到 32768 token，相当于增加 8 倍。

| 项目                           |      4K |     32K |     增长 |
| ---------------------------- | ------: | ------: | -----: |
| Token 数                      |    4096 |   32768 |    8 倍 |
| 单个隐藏状态                       |  32 MiB | 256 MiB |    8 倍 |
| GQA KV Cache                 | 512 MiB |   4 GiB |    8 倍 |
| 单层完整 Attention Score         |   1 GiB |  64 GiB |   64 倍 |
| Attention 计算部分               |     1 倍 |    64 倍 |   64 倍 |
| MLP 和线性投影                    |     1 倍 |     8 倍 |    8 倍 |
| 示例中的整层计算量                    |     1 倍 |  约 16 倍 | 约 16 倍 |
| Decode 单个新 token 的 Attention |     1 倍 |     8 倍 |    8 倍 |

这个表揭示了三个不同关系：

```text
KV Cache  ∝  N
```

```text
Attention Matrix  ∝  N^2
```

```text
Prefill Attention Compute  ∝  N^2
```

# 二十、生成多个 token 时的总复杂度

假设初始 Prompt 有 (N) 个 token，需要生成 (T) 个 token。

第一个生成 token 需要关注约 (N) 个历史位置。

第二个生成 token 需要关注约 (N+1) 个历史位置。

最后一个需要关注约 (N+T-1) 个历史位置。

Attention 工作量之和为：

```text
N+(N+1)+(N+2)+…+(N+T-1)
```

等于：

```text
TN+(T(T-1)) / (2)
```

因此 Decode 阶段的 Attention 计算量约为：

```text
O(Ld[TN + T(T-1)/2])
```

与此同时，每个新 token 还要通过所有线性层和 MLP，所以还有：

```text
O(LTd^2)
```

总 Decode 计算量可以概括为：

```text
O(
LTd^2
+
LdTN
+
LdT^2
)
```

如果初始上下文 (N) 很大而输出 (T) 较短，主要是：

```text
O(LdTN)
```

如果连续生成非常长的内容，(T^2) 项也会逐渐明显。

---

# 二十一、KV Cache 是用显存换计算

如果完全不使用 KV Cache，生成每个 token 时都需要重新处理整个历史：

```text
生成第 1 个 token：重新处理 N 个 token
生成第 2 个 token：重新处理 N+1 个 token
生成第 3 个 token：重新处理 N+2 个 token
...
```

这会重复计算过去 token 的：

* Q、K、V；
* MLP；
* Attention；
* 所有 Transformer 层。

使用 KV Cache 后：

```text
过去 token 的 K、V 保存在显存中
新 token 只计算自己的 Q、K、V
新 Query 直接访问历史 K、V
```

因此它本质上是：

```text
增加显存占用
换取更少的重复计算
```

对于自回归推理，这是极其关键的优化。

---

# 二十二、Batch Size 对显存和计算量的影响

前面的公式都包含 (B)。

KV Cache：

```text
M_(KV) ∝  BN
```

隐藏状态：

```text
M_(hidden) ∝  BN
```

普通 Attention Score：

```text
M_(score) ∝  BN^2
```

所以：

* Batch Size 翻倍，KV Cache 约翻倍；
* Batch Size 翻倍，激活值约翻倍；
* Batch Size 翻倍，Attention Score 约翻倍；
* 序列长度翻倍，Attention Score 约四倍。

这也是推理服务中长上下文会显著压缩并发量的原因。

例如一张 GPU 原本可以同时容纳 16 个短上下文请求；如果每个请求的 KV Cache 增加 8 倍，在其他条件不变时，可容纳的并发请求数可能下降到约原来的八分之一。

---

# 二十三、训练中的 Padding 也会造成浪费

假设同一个 Batch 中有四条序列：

```text
序列 A：1000 token
序列 B：1200 token
序列 C：1500 token
序列 D：8000 token
```

如果全部 Padding 到 8000：

```text
四条序列都按 8000 token 计算
```

普通 Attention 的矩阵元素数是：

```text
4 × 8000^2
```

但真正有内容的计算量更接近：

```text
1000^2+1200^2+1500^2+8000^2
```

因此错误的 Batch 组织会浪费大量计算和显存。

常见优化包括：

* 按长度分桶；
* Sequence Packing；
* Variable-Length FlashAttention；
* 避免长短序列混在同一 Padding Batch。

---

# 二十四、不同长上下文技术分别解决什么问题

| 技术                       | 主要作用                               | 是否消除 (N^2) Attention 计算 |
| ------------------------ | ---------------------------------- | ----------------------- |
| FlashAttention           | 不保存完整 Attention 矩阵，降低显存和内存访问       | 否                       |
| GQA                      | 减少 KV Head 数，降低 KV Cache           | 否                       |
| MQA                      | 所有 Query Head 共享 KV，进一步降低 KV Cache | 否                       |
| KV Cache 量化              | 降低每个 KV 元素的字节数                     | 否                       |
| PagedAttention           | 改善 KV Cache 分配和碎片问题                | 否                       |
| Activation Checkpointing | 训练时减少激活显存，反向时重算                    | 否                       |
| Sliding-Window Attention | 每个 token 只看附近 (w) 个 token          | 是，变为约 (O(Nw))           |
| Sparse Attention         | 只计算部分 token 关系                     | 可以降低                    |
| Linear Attention         | 使用核函数等改写 Attention                 | 可以降低，但模型行为不同            |
| Tensor Parallel          | 将权重和计算分到多张 GPU                     | 总计算量不变                  |
| Context Parallel         | 将序列维度分到多张 GPU                      | 总计算量不变，降低单卡压力           |

其中：

* FlashAttention 解决“不能存下完整矩阵”的问题；
* GQA/MQA 解决“KV Cache 太大”的问题；
* Sliding Window 和 Sparse Attention 才会改变两两交互数量；
* 多 GPU 并行主要是分摊压力，不会凭空减少总工作量。

# 二十五、最后归纳

Token 数影响 Transformer 的三条主线是：

## 1. 线性张量

隐藏状态、Q/K/V、MLP 激活、KV Cache通常满足：

```text
M ∝  N
```

Token 翻倍，显存约翻倍。

---

## 2. Attention 矩阵

每个 Query 与每个 Key 形成一个分数：

```text
[N,d_h] × [d_h,N]=[N,N]
```

所以：

```text
M_(attention) ∝  N^2
```

Token 翻倍，完整 Attention 矩阵显存约变为四倍。

FlashAttention 可以避免将该完整矩阵存入显存。

---

## 3. Attention 计算量

Prefill 中，所有输入 token 同时参与 Attention：

```text
C_(prefill-attention) ∝  N^2d
```

Token 翻倍，Attention 计算量约变为四倍。

但整个 Transformer 还包含：

```text
O(Nd^2)
```

的投影和 MLP，因此整体计算增长一般处于两倍到四倍之间。

---

## 4. 逐 token 解码

有 KV Cache 时，生成一个新 token 只需要让新 Query 访问过去的 (N) 个 Key：

```text
C_(decode-one-token) ∝  Nd
```

所以历史上下文翻倍，生成下一个 token 的 Attention 工作量约翻倍，而不是四倍。

---

可以用一句话概括：

> **Token 数决定序列长度；隐藏状态和 KV Cache 随序列长度线性增长，而完整 Self-Attention 需要建立 token 两两之间的关系，因此它的矩阵规模和 Prefill 计算量随 token 数平方增长。**
