# 01. token、word、character 三者分别是什么？

## 结论先行

- **character（字符）**是字符串或编码层面的基本符号，例如 `A`、`中`、`🙂`。但要注意，用户肉眼看到的一个“字符”不一定只对应一个 Unicode code point，例如带组合音标的字母和家庭 emoji 可能由多个 code point 组成。
- **word（词）**是语言学和人类理解层面的单位，例如英文的 `playing`、中文的“人工智能”。词的边界依赖语言：英文常有空格，中文通常没有天然空格，德语还会出现很长的复合词。
- **token** 是 tokenizer 根据固定词表与规则得到的离散单元，也是模型真正接收和计数的单位。一个 token 可能是一个词、半个词、一个汉字、几个字节、空格加单词，甚至标点或换行。

最适合面试开场的一句话是：**character 是文本编码视角的符号，word 是人类语言视角的词，token 是模型视角的基本文本单位。三者没有固定的一一对应关系。**

## 三者为什么不能画等号

以英文单词 `unbelievable` 为例：

```text
character: u | n | b | e | l | i | e | v | a | b | l | e
word:      unbelievable
token:     un | believable           # 只是一种可能切法
```

这里有 12 个英文字母、1 个词，却可能是 2 个 token。换一个词表，它也可能被切成 `un | believe | able`，甚至更多片段。

中文也一样：

```text
原文：机器学习很好用
word：机器学习 | 很 | 好用          # 取决于语言学分词标准
token：机器 | 学习 | 很 | 好 | 用    # 取决于具体 tokenizer
```

tokenizer 并不承诺遵守语言学上的词边界。它优化的通常是有限词表下的压缩效率、覆盖能力和模型训练效果，而不是输出最符合人类直觉的“词”。

## 从文本到模型输入发生了什么

典型流程可以写成：

```text
原始字符串
  -> normalization（可选，如 Unicode 规范化或大小写处理）
  -> pre-tokenization（可选，如按空格、标点切出候选片段）
  -> BPE / WordPiece / Unigram 等算法切成 token
  -> 词表查找得到 token id
  -> embedding 查表得到连续向量
```

例如：

```text
"Tokenization!"
-> ["Token", "ization", "!"]
-> [3146, 928, 0]
-> 三个 d_model 维向量
```

Transformer 实际接收的是 token id 对应的向量序列，而不是 Python 字符串，也不是“词”这个抽象概念。模型上下文长度、位置编号、attention 计算以及 API 计费通常都按 token 统计。

## token 粒度为什么通常介于字符和词之间

纯 word-level 词表会遇到严重的未登录词问题。姓名、拼写变化、新术语和代码变量名几乎不可能全部收入有限词表。纯 character-level 虽然覆盖强，但序列会很长，attention 和 KV cache 成本随之增加，单个输入单元携带的语义也较弱。

subword token 在两者之间折中：

- 高频词或高频片段尽量整体保留，缩短序列；
- 低频词退化为较小子词、字符或字节，避免无法编码；
- 用固定大小的词表覆盖开放世界文本。

因此，token 不是语言里天然存在的单位，而是**训练语料、分词算法、词表预算和工程目标共同决定的表示单位**。

## 两个容易忽略的细节

第一，Unicode code point 不完全等于用户看到的字符。`é` 既可能是一个预组合 code point，也可能是 `e` 加组合重音；某些 emoji 由多个人物、连接符和肤色修饰符组成。是否规范化会直接影响 token 序列。

第二，token 不只表示可见文字。很多 tokenizer 会把前导空格编码进 token，还会为换行、缩进、控制字符以及 `<bos>`、`<eos>`、`<pad>` 等特殊标记分配 token id。因此“原文有几个字”无法可靠推出“模型会看到几个 token”。

## 面试回答要点

回答时至少说清四层关系：

1. character 属于字符串/编码层；word 属于语言学层；token 属于模型输入层。
2. token 由具体 tokenizer 决定，不必等于一个字或一个词。
3. token 会先变成 id，再通过 embedding 进入模型。
4. subword 是覆盖率、序列长度和词表大小之间的折中。

不要回答成“英文一个单词就是一个 token，中文一个字就是一个 token”。这只是某些文本在某些 tokenizer 下偶尔出现的结果，不是定义。
