# 18. BPE、WordPiece、Unigram、SentencePiece 的核心区别分别是什么？

## 回答

- BPE：从细粒度符号开始，按相邻对频率不断合并；规则直观、实现常见。
- WordPiece：同样构造子词词表，但通常以提升语言模型似然的准则选择片段；编码失败时常使用 `[UNK]`。
- Unigram：先准备较大的候选子词集合，再用概率模型逐步删除贡献较小的片段；同一句子可存在多种切分候选。
- SentencePiece：更准确地说是 tokenizer 训练与编码框架，而不是单独一种切分准则；它常实现 BPE 或 Unigram，并把空格当作普通符号处理，适合不依赖预分词的多语言场景。

## 面试要点

面试中要区分“算法”与“工具框架”：SentencePiece 可训练 BPE 或 Unigram 模型，不能简单与三种算法并列为完全同一层级的概念。





最关键的区别是：**BPE、WordPiece、Unigram 是子词词表的学习/切分算法；SentencePiece 是一套 tokenizer 训练与实现框架**，它可以使用 BPE 或 Unigram。

## 核心对比

| 维度     | BPE           | WordPiece     | Unigram                 | SentencePiece           |
| ------ | ------------- | ------------- | ----------------------- | ----------------------- |
| 类型     | 合并算法          | 子词算法          | 概率模型                    | tokenizer 框架            |
| 起点     | 小单位，如字符或字节    | 小单位，通常先按词预切分  | 大量候选子词                  | 原始文本                    |
| 训练过程   | 不断合并高频相邻片段    | 选择更有利于语言建模的片段 | 从大词表逐步删除低贡献片段           | 可运行 BPE 或 Unigram       |
| 编码方式   | 按学习到的合并规则切分   | 常用最长匹配优先      | 选择概率最大的完整切分路径           | 取决于所选模型                 |
| 多种切分   | 通常唯一          | 通常唯一          | 天然支持                    | 使用 Unigram 时支持          |
| 空格处理   | 取决于具体实现       | 通常先预切词        | 取决于实现                   | 可把空格作为普通符号处理            |
| 未知字符处理 | 字节级 BPE 可完全避免 | 可能产生 `[UNK]`  | 取决于字符覆盖率或 byte fallback | 支持字符覆盖与可选 byte fallback |

## 1. BPE：从小到大不断合并

BPE（Byte Pair Encoding）的基本思路是：

1. 从字符、字节或其他小单位开始。
2. 统计相邻 token 对。
3. 合并最高频的相邻对。
4. 重复合并，直到达到目标词表大小。

假设语料中某两个片段经常连续出现，BPE 就可能把它们合成一个新 token。

### 特点

* 训练逻辑简单、速度快。
* 高频字符串容易成为整体 token。
* 编码通常根据训练时得到的合并顺序执行。
* 结果稳定、确定性强。
* 合并依据主要是频率，不保证符合词根、词缀或语义边界。

### 需要区分两类 BPE

* **字符级 BPE**：从字符开始。
* **Byte-level BPE**：从字节开始，原则上可以表示任意输入，不需要普通意义上的未知字符。

GPT 系列常见的是 byte-level BPE 或其演化形式，而不是最初用于文本压缩的原始 BPE。

## 2. WordPiece：强调片段的区分能力

WordPiece 与 BPE 类似，也从较小单位构建子词，但选择新片段时不只是看相邻组合的原始出现次数，而是偏向能更好解释训练数据的组合。

在常见实现中，它倾向于避免仅因为两个片段各自都非常高频，就机械地把它们合并。历史上的 WordPiece 训练细节在不同实现中并不完全一致，因此不能用一个统一的合并公式描述所有 WordPiece tokenizer。

编码时通常采用：

1. 对文本进行预切词。
2. 从一个词的开头出发。
3. 贪心选择词表中最长的可匹配子串。
4. 继续处理剩余部分。

BERT 风格的词表常用 `##` 表示一个 token 位于词内部，例如概念上可能出现：

```text
play + ##ing
```

这里仅说明表示方式；实际切分必须查看具体模型的词表和 tokenizer 配置。

### 特点

* 常与 BERT 一类编码器模型关联。
* 一般使用“最长匹配优先”进行编码。
* 经常依赖空格、标点等预切词规则。
* 如果一个预切分单词无法完全由词表覆盖，某些实现会把整个词变成 `[UNK]`。
* `##` 是特定 WordPiece 词表的约定，不是所有子词 tokenizer 的通用标记。

## 3. Unigram：从大到小进行概率筛选

Unigram Language Model 的方向与 BPE 基本相反：

* BPE 从很小的词表开始，不断添加合并结果。
* Unigram 从一个较大的候选子词集合开始，不断删除价值较低的 token。

Unigram 为每个 token 学习一个概率，并假设一种切分的概率由其中各 token 的概率共同决定。训练过程中会反复：

1. 计算各候选 token 的概率。
2. 估计删除某个 token 对语料似然的影响。
3. 删除影响较小的候选 token。
4. 重新估计概率。
5. 直到达到目标词表大小。

编码时，一段文本通常存在多种合法切分。Unigram 可以使用动态规划，例如 Viterbi，选择整体概率最高的路径，而不是只做局部贪心选择。

### 特点

* 从整条切分路径进行全局选择。
* 同一段文本可以存在多个合理切分。
* 容易实现 subword regularization：训练时随机采样不同切分，提高模型鲁棒性。
* 训练和编码比简单 BPE 更复杂。
* 是否能覆盖任意字符，取决于字符覆盖配置或是否启用字节回退。

## 4. SentencePiece：把完整文本直接交给 tokenizer

SentencePiece 不是与 BPE、WordPiece、Unigram 平级的第四种算法。它是一套用于训练和运行 tokenizer 的工具框架，主要支持：

* BPE
* Unigram
* 字符级模型
* 词级模型

它的重要设计是：**不要求调用者先按空格切词**。SentencePiece 可以直接处理原始句子，并将空格转换成可见的元符号，通常显示为 `▁`。

例如在概念上：

```text
Hello world
```

可能对应包含以下形式的片段：

```text
▁Hello
▁world
```

`▁` 表示前面存在空格。这让分词和还原过程更统一，也更适合没有显式空格边界的语言。

### SentencePiece 负责的内容

* 文本规范化
* 空格编码
* 词表训练
* BPE 或 Unigram 模型运行
* token 与 ID 映射
* detokenization
* 字符覆盖率配置
* 可选 byte fallback
* 特殊 token 配置

因此，“某模型用了 SentencePiece”还不能说明它的具体切分策略，还需要查看它采用的是 `BPE` 还是 `Unigram`，以及规范化、字符覆盖和字节回退等配置。

## 三种算法的本质差异

可以概括为：

```text
BPE：
小词表 → 合并高频相邻片段 → 得到大词表
编码时遵循合并规则

WordPiece：
小词表 → 选择更有建模价值的片段
编码时通常使用最长匹配

Unigram：
大候选词表 → 概率建模 → 删除低贡献片段
编码时寻找全局最优或采样切分路径
```

## 如何选择

* 追求简单、快速、确定性切分：**BPE**
* 使用 BERT 体系或需要兼容现有 `##` 词表：**WordPiece**
* 希望使用概率切分、切分采样和 subword regularization：**Unigram**
* 希望直接处理原始文本，并统一训练、编码、解码流程：**SentencePiece + BPE/Unigram**

实际模型的 tokenization 结果还受词表、normalizer、pre-tokenizer、空格规则、特殊 token 和 byte fallback 配置影响。仅知道算法名称，无法精确推出某段文本会被切成哪些 token。
