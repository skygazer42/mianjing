# 13. BERT、GPT 和 LLaMA 的 tokenizer 设计有什么典型差异？

## 结论先行

典型 BERT、GPT-2 和早期 LLaMA 分别代表三种常见组合：**BERT 常见 BasicTokenizer + WordPiece，GPT-2 使用 byte-level BPE，LLaMA 1/2 使用基于 SentencePiece 的 BPE**。它们在是否预分词、未知字符覆盖、空格表示、大小写处理和特殊 token 设计上不同，因此不能只看“都把文本切成子词”就认为行为相同。

这里说的是这些模型家族的经典实现，不是永久规则。后续版本可能更换词表规模、实现库或特殊 token；判断某个具体 checkpoint 时，应以它发布的 tokenizer 配置文件为准。

## 典型差异对照

| 维度 | BERT（典型 uncased） | GPT-2 | LLaMA 1/2 |
| --- | --- | --- | --- |
| 主要方法 | WordPiece | byte-level BPE | SentencePiece BPE |
| 输入起点 | 先做 basic tokenization | UTF-8 字节映射 | 直接处理原始文本 |
| 子词边界 | 后续片段常带 `##` | 前导空格常编码进 token | 空格常显示为 `▁` |
| 大小写 | uncased 版本会小写化 | 通常保留 | 通常保留 |
| 未知输入 | 词内无法匹配可能整词 `[UNK]` | 字节回退保证覆盖 | 常配 byte fallback 或 `<unk>`，依配置而定 |
| 主要训练目标 | 双向编码理解 | 自回归生成 | 自回归生成 |

表中的标记只是可视化约定：`##ing` 表示“不是词首的 ing”，`Ġhello` 或类似形式表示 token 前有空格，`▁hello` 表示 SentencePiece 视角的词边界。它们不是原始文本中真的出现了这些字符。

## BERT：预分词与 WordPiece 最长匹配

经典 BERT tokenizer 往往先做清理、大小写和标点处理，再在每个候选词内部进行 WordPiece 最长匹配：

```text
playing -> play | ##ing
```

`##` 告诉解码器该片段接在前一片段后面，不应插入空格。若一个候选词从某个位置开始找不到任何合法子词，经典实现可能把整个词变成 `[UNK]`。BERT 还常自动加入 `[CLS]`、`[SEP]`，并用 `[MASK]` 支持掩码语言模型训练。

uncased 模型的小写化能提高有限词表的复用率，但会丢失 `Apple` 与 `apple` 的表面差异；代码、实体识别等大小写敏感任务可能更适合 cased 版本。

## GPT-2：byte-level BPE 与空格敏感

GPT-2 先将 UTF-8 字节映射到一组可打印符号，再应用 BPE merge rules。因为 256 种字节都可表示，理论上任意 UTF-8 文本都有编码路径，不必因生僻字符直接产生 `<unk>`。

空格通常与其后的英文片段一起参与合并，所以：

```text
"hello"
" hello"
```

开头的 `hello` 与带前导空格的 ` hello` 很可能是不同 token。这个设计适合自回归模型严格重建原文，也能处理代码和任意符号；代价是词表覆盖弱的非 ASCII 文本可能退回多个字节片段，token 效率较低。

## LLaMA 1/2：SentencePiece BPE

SentencePiece 的重要特点是把空格也当作普通符号处理，可直接从未按词切分的原始语料训练。可视化时常用 `▁` 表示空格或词边界：

```text
"hello world" -> ▁hello | ▁world
```

这对没有天然空格边界的语言和统一多语言流水线很方便。LLaMA 1/2 的经典词表规模与 GPT-2、BERT 不同，训练语料分布也不同，所以即使正文相同，切分长度和 id 都不会一致。

要特别避免把“LLaMA tokenizer”当成永远不变的规范。模型家族升级时完全可以重训词表。例如新的版本可能扩大多语言和代码覆盖，并采用不同实现或特殊 token 集合。**tokenizer 属于具体 checkpoint 的接口契约，而不只是架构名称的属性。**

## 为什么这些差异会影响模型行为

1. **序列长度不同**：切得更碎会增加 attention、KV cache 和计费成本。
2. **信息是否保留不同**：小写化、重音处理和空白清理可能使编码不严格可逆。
3. **稀有文本覆盖不同**：byte-level 方法通常覆盖稳，但不保证压缩率好。
4. **特殊 token 不兼容**：`[CLS]`、`<bos>`、消息边界和工具调用 token 的语义由训练约定决定。
5. **embedding 完全绑定词表**：token id 100 在三个模型中对应不同内容，不能互换。

## 实际比较应该怎么做

不要只拿一条英文句子调用 `len(encode(text))`。合理的比较方式是：

- 使用各 checkpoint 官方 tokenizer 与默认配置；
- 分开统计裸文本和应用 chat template 后的长度；
- 在真实业务语料上按语言、代码、数字、URL、emoji 分桶；
- 比较 token/字符、token/UTF-8 字节以及相同语义翻译的 token 数；
- 检查 encode/decode 往返、未知 token 比例和 P50/P95/P99 长度。

## 面试回答要点

可以先给出经典映射：BERT 常见 WordPiece，GPT-2 是 byte-level BPE，LLaMA 1/2 是 SentencePiece BPE；再说明它们对预分词、空格、大小写和未知字符的处理不同。最后补一句版本边界：真正工程判断要读取具体 checkpoint 的 tokenizer 配置，模型架构相同不代表 tokenizer 相同。
