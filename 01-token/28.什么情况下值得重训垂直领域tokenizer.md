# 28. 什么情况下值得为垂直领域重新训练 tokenizer？

## 结论先行

只有当目标领域文本被现有 tokenizer **长期、系统性地切得过碎**，造成显著的训练/推理成本或任务质量问题，并且你有足够数据和预算同步处理 embedding、输出层、checkpoint 兼容与重新训练时，才值得重训。若只是新增少量术语，优先考虑继续训练、词表小规模扩展、检索或提示词方案。

## 先区分三种改动

1. **不改 tokenizer，只微调模型**：成本最低，完全兼容原 checkpoint。模型可以通过多个已有子词学习新术语，很多场景已经足够。
2. **在原词表追加少量 token**：保留原 id，扩展 embedding/输出层，并用领域语料充分训练新行。适合少量高频且切分极差的术语或控制标记。
3. **重新训练整个 tokenizer**：旧 token 的 id 和边界都可能变化，原 embedding 语义不再对齐，通常需要从头训练或昂贵的迁移/继续预训练。

“训练一个新 tokenizer 文件”本身不贵，真正昂贵的是让模型参数适应这套新离散接口。

## 值得重训的信号

### 1. 领域语料压缩率持续很差

例如基因序列、化学式、医学术语、日志、源代码或某种低资源语言在现有词表中大量退化为字符/字节。真实数据的 P95/P99 token 长度显著偏高，导致文档截断、batch 变小、KV cache 膨胀或 API 成本不可接受。

### 2. 目标分布与基础模型语料差异极大

如果计划从头预训练领域模型，且训练 token 规模足够大，重训 tokenizer 可以在最开始优化词表资源分配。相反，只有几万条微调样本时，新词表项很可能得不到足够梯度。

### 3. 现有 tokenizer 存在硬性能力缺口

例如无法无损覆盖关键字符、会丢失大小写/格式、产生大量 `[UNK]`，或者 special token 协议无法支持任务。这类问题比“切分看起来不自然”更有重训价值。

### 4. 节省的总成本能覆盖迁移成本

可粗略估算：

$$
\text{净收益} \approx \text{未来减少的训练与推理 token 成本}
- \text{重训、迁移、验证与兼容成本}
$$

如果模型每天处理巨量固定领域流量，序列缩短 20% 可能很有价值；若只是一次小规模微调，收益通常不足以抵消风险。

## 不足以重训的理由

- 某几个专业词被拆成三四段，但整体 token 分布正常；
- 希望 token 边界更符合人类语言学直觉；
- 认为“一个术语一个 token”模型就一定理解得更好；
- 没有足够领域语料训练新 embedding；
- 必须继续兼容已有模型、量化权重、LoRA、缓存与下游系统。

子词组合本来就用于表达新词。术语被拆分不等于模型无法学会概念，概念学习主要来自上下文和训练目标。

## 评估与决策流程

1. 用目标 checkpoint 的完整 tokenizer 对真实语料分桶，统计 token/byte、P95/P99 长度、`<unk>` 和截断率。
2. 找出成本来自少量术语，还是整个字符系统/数据格式覆盖不足。
3. 建立三组候选：原词表、追加少量 token、全量重训词表。
4. 比较词表参数增长、训练 token 减少、上下文有效容量和 encode 速度。
5. 做等计算量继续预训练或小模型实验，验证 loss 与下游任务，而不是只比较切分示例。
6. 评估部署迁移：旧 checkpoint、LoRA、量化、服务端计数、数据缓存和 chat template 是否全部要更新。

## 追加新 token 的隐藏风险

新增 token 必须扩展输入 embedding；若输出层不共享，还要扩展 LM head。新向量可用随机值、已有子词向量平均等方式初始化，但初始化不是学习，仍需足量训练。若新 token 与旧切分重叠，编码大量历史文本的边界也可能改变；因此追加时要验证 added-token 匹配规则并做回归测试。

## 面试回答要点

回答不要停在“领域词多就重训”。先量化现有 tokenizer 在真实语料上的压缩、OOV、截断和成本，再根据改动规模选“保持不变—小幅扩词—全量重训”。最后强调 tokenizer 与 embedding/LM head 强绑定，重训往往意味着大规模继续预训练或从头训练。
