# 10. 单独深入理解 Transformer Attention

Attention 的核心可以概括为五个步骤：

```text
【投影 Q/K/V
 →
计算匹配分数
 →
应用 Mask
 →
Softmax
 →
加权汇总 V】
```

Multi-Head Attention 则是：

```text
【并行执行多个 Attention Head
 →
拼接各 Head 输出
 →
通过输出投影融合】
```

---

## 一、先区分 Head、Attention 层和 Transformer Block

这三个概念容易混淆。

### 1. Attention Head

一个 Attention Head 独立完成：

```text
QK^(T)
 →
softmax
 →
AV
```

一个 Head 会为每个 Query token 产生一套“应该从哪些 token 读取信息”的权重。

---

### 2. Multi-Head Attention

多个 Head 并行运行：

```text
Head 1 ─┐
Head 2 ─┤
Head 3 ─┼→ 拼接 → 输出投影 W_O
...     │
Head h ─┘
```

每个 Head：

* 有自己的 Query 投影；
* 有自己的 Key 投影；
* 有自己的 Value 投影；
* 产生自己的 Attention 权重矩阵；
* 可以学习不同的信息交互模式。

---

### 3. Transformer Block

Attention 只是 Transformer Block 的一部分。

典型 Decoder-only Transformer Block 是：

```text
输入 X
  │
  ├── RMSNorm / LayerNorm
  │
  ├── Multi-Head Self-Attention
  │
  ├── Residual Add
  │
  ├── RMSNorm / LayerNorm
  │
  ├── MLP / FFN
  │
  └── Residual Add
```

本节只讨论中间的 Multi-Head Self-Attention。

---

## 二、Attention 的输入是什么？

假设一段文本经过 tokenizer 后得到 (N) 个 token。

每个 token 经过 Embedding 和前面若干 Transformer 层后，都对应一个 `d_(model)` 维向量。

整个输入可以写成：

```text
X ∈ R^(B ×  N ×  d_(model))
```

其中：

| 符号                 | 含义         |
| ------------------ | ---------- |
| (B)                | Batch Size |
| (N)                | Token 数量   |
| `d_(model)` | 模型隐藏维度     |

暂时忽略 Batch 维度：

```text
X ∈ R^(N ×  d_(model))
```

假设有 3 个 token，隐藏维度为 4：

```text
X=
[
1  0  1  0
0  1  0  2
1  1  3  1
]
```

每一行对应一个 token：

```text
X=
[
x_1
x_2
x_3
]
```

其中：

```text
x_i ∈ R^(d_(model))
```

需要注意：这里的向量已经不是 token ID，而是模型当前层对该 token 的内部表示。

---

## 三、为什么需要 Q、K、V？

Attention 不直接使用同一个 (X) 完成所有工作，而是将每个 token 投影成三种表示：

```text
Q=XW_Q
```

```text
K=XW_K
```

```text
V=XW_V
```

它们分别是：

| 名称    | 直观作用                        |
| ----- | --------------------------- |
| Query | 当前 token 想查找什么信息            |
| Key   | 当前 token 可以通过什么特征被匹配        |
| Value | 当前 token 真正向其他 token 提供什么信息 |

可以用数据库检索类比：

```text
Query：查询条件
Key：索引或匹配字段
Value：匹配成功后真正读取的数据
```

但这个类比只用于帮助理解。实际的 Q、K、V 都是模型训练得到的向量。

---

### 一个非常重要的区别

Attention 使用：

```text
QK^(T)
```

决定“从哪里读取”。

但真正被汇总的是：

```text
V
```

也就是说：

> **Key 负责匹配，Value 负责传递内容。**

高 Query-Key 相似度不会直接把 Key 向量输出，而是让对应的 Value 获得更高权重。

---

## 四、单个 Attention Head 的维度

假设一个 Head 的维度为：

```text
d_h=2
```

那么：

```text
W_Q,W_K,W_V
 ∈
R^(d_(model) ×  d_h)
```

在当前例子中：

```text
d_(model)=4,  d_h=2
```

因此：

```text
W_Q,W_K,W_V ∈ R^(4 × 2)
```

为了方便手算，设置：

```text
W_Q=
W_K=
[
1  0
0  1
0  0
0  0
]
```

以及：

```text
W_V=
[
0  0
0  0
1  0
0  1
]
```

于是：

```text
Q=XW_Q
=

[
1  0
0  1
1  1
]
```

```text
K=XW_K
=

[
1  0
0  1
1  1
]
```

```text
V=XW_V
=

[
1  0
0  2
3  1
]
```

这里可以看出：

* (Q) 和 (K) 取出了输入向量前两个维度；
* (V) 取出了输入向量后两个维度；
* 真实模型中的权重不会如此简单，而是训练得到的稠密矩阵。

---

## 五、第一步：计算 Query-Key 匹配分数

Attention Score 的公式是：

```text
S=(QK^(T)) / (√(d_h))
```

其中：

```text
Q ∈ R^(N ×  d_h)
```

```text
K^(T) ∈ R^(d_h ×  N)
```

所以：

```text
S ∈ R^(N ×  N)
```

在例子中：

```text
Q=
[
1  0
0  1
1  1
]
```

```text
K^(T)=
[
1  0  1
0  1  1
]
```

先计算：

```text
QK^(T)
=

[
1  0  1
0  1  1
1  1  2
]
```

因为：

```text
d_h=2
```

所以除以：

```text
√(2) ≈ 1.414
```

得到：

```text
S=
[
0.707  0  0.707
0  0.707  0.707
0.707  0.707  1.414
]
```

---

## 六、Attention Score 中每个位置是什么意思？

矩阵元素：

```text
S_(ij)
=

(q_i ·  k_j) / (√(d_h))
```

表示：

> 第 (i) 个 token 的 Query，与第 (j) 个 token 的 Key 的匹配程度。

行表示 Query，列表示 Key：

```text
                    被读取的 Key
                Token 1  Token 2  Token 3
Query Token 1     S11      S12      S13
Query Token 2     S21      S22      S23
Query Token 3     S31      S32      S33
```

例如：

```text
S_(31)=0.707
```

表示：

> Token 3 作为查询者，对 Token 1 的匹配分数是 0.707。

而：

```text
S_(33)=1.414
```

表示 Token 3 与自己的 Key 匹配得更强。

注意：

```text
S_(ij) ≠  S_(ji)
```

在一般情况下，Attention Score 不一定对称，因为：

```text
W_Q ≠  W_K
```

即使是同一批 token，Query 和 Key 也来自不同的投影空间。

---

## 七、为什么要除以 `√(d_h)`？

点积：

```text
q_i ·  k_j
=

Σ_(r=1)^(d_h)q_(ir)k_(jr)
```

假设 Q、K 各维度：

* 均值接近 0；
* 方差接近 1；
* 各维度大致独立。

那么 (d_h) 项相加后，点积的方差大约是：

```text
Var(q_i ·  k_j) ≈  d_h
```

标准差大约是：

```text
√(d_h)
```

如果 Head 维度很大，未经缩放的点积绝对值也会变大。

例如 Softmax 输入为：

```text
[1,2,3]
```

Softmax 仍较平缓。

如果输入扩大十倍：

```text
[10,20,30]
```

Softmax 会非常接近：

```text
[0,0,1]
```

这样容易导致：

* Softmax 过度饱和；
* 大部分位置权重接近 0；
* 梯度变小；
* 训练不稳定。

因此除以：

```text
√(d_h)
```

将分数尺度控制在更稳定的范围。

这就是 **Scaled Dot-Product Attention** 中 “Scaled” 的含义。

---

## 八、第二步：应用 Causal Mask

Decoder-only 大语言模型不能让当前 token 看到未来 token。

例如：

```text
Token 1 只能看到 Token 1
Token 2 可以看到 Token 1、Token 2
Token 3 可以看到 Token 1、Token 2、Token 3
```

因此构造因果 Mask：

```text
M=
[
0  -∞  -∞
0  0  -∞
0  0  0
]
```

把它加到 Score 上：

```text
S_(masked)=S+M
```

得到：

```text
S_(masked)
=

[
0.707  -∞  -∞
0  0.707  -∞
0.707  0.707  1.414
]
```

为什么使用 `-∞`？

因为：

```text
e^(-∞)=0
```

经过 Softmax 后，被遮挡位置的概率会变为 0。

实际浮点计算中，框架可能使用：

* 负无穷；
* 数据类型能够表示的极小值；
* 足够大的负数。

它们的目的相同：让相应位置经过 Softmax 后权重为 0。

---

## 九、第三步：逐行执行 Softmax

Attention 权重为：

```text
A=
softmax(S_(masked))
```

Softmax 是对每一个 Query 的整行分别计算：

```text
A_(ij)
=

(e^(S_(ij))) / (Σ_(k)e^(S_(ik)))
```

因此，对固定的 Query (i)：

```text
Σ_j A_(ij)=1
```

---

### Token 1 的权重

第一行是：

```text
[0.707,-∞,-∞]
```

只有 Token 1 可以被访问，所以：

```text
A_1=[1,0,0]
```

---

### Token 2 的权重

第二行有效分数是：

```text
[0,0.707]
```

计算指数：

```text
e^0=1
```

```text
e^(0.707) ≈ 2.028
```

归一化：

```text
A_(21)
=

(1) / (1+2.028)
 ≈ 0.330
```

```text
A_(22)
=

(2.028) / (1+2.028)
 ≈ 0.670
```

所以：

```text
A_2=[0.330,0.670,0]
```

---

### Token 3 的权重

第三行是：

```text
[0.707,0.707,1.414]
```

指数值约为：

```text
[2.028,2.028,4.113]
```

总和约为：

```text
8.169
```

因此：

```text
A_3
 ≈
[0.248,0.248,0.503]
```

最终得到：

```text
A=
[
1  0  0
0.330  0.670  0
0.248  0.248  0.503
]
```

这就是该 Head 的 Attention 权重矩阵。

---

## 十、第四步：使用 Attention 权重汇总 Value

计算：

```text
O=AV
```

其中：

```text
A ∈ R^(N ×  N)
```

```text
V ∈ R^(N ×  d_h)
```

所以：

```text
O ∈ R^(N ×  d_h)
```

每个输出：

```text
o_i=Σ_(j=1)^(N)A_(ij)v_j
```

也就是根据 Attention 权重，对所有可访问 token 的 Value 做加权求和。

---

### Token 1 的输出

```text
o_1
=

1v_1+0v_2+0v_3
```

```text
o_1=[1,0]
```

---

### Token 2 的输出

```text
o_2
=

0.330v_1+0.670v_2
```

代入：

```text
v_1=[1,0]
```

```text
v_2=[0,2]
```

得到：

```text
o_2
=

0.330[1,0]+0.670[0,2]
```

```text
o_2
 ≈
[0.330,1.340]
```

---

### Token 3 的输出

```text
o_3
=

0.248v_1+0.248v_2+0.503v_3
```

代入：

```text
v_1=[1,0]
```

```text
v_2=[0,2]
```

```text
v_3=[3,1]
```

得到：

```text
o_3
=

0.248[1,0]
+
0.248[0,2]
+
0.503[3,1]
```

第一维：

```text
0.248+0+0.503 × 3
 ≈ 1.759
```

第二维：

```text
0+0.248 × 2+0.503
 ≈ 1.000
```

所以：

```text
o_3 ≈ [1.759,1.000]
```

完整输出：

```text
O=
[
1  0
0.330  1.340
1.759  1.000
]
```

## 十一、单个 Head 的完整公式

一个 Self-Attention Head 可以完整写成：

```text
head(X)
=

softmax
(
((XW_Q)(XW_K)^(T)) / (√(d_h))
+
M
)
(XW_V)
```

分解后就是：

```text
Q=XW_Q
```

```text
K=XW_K
```

```text
V=XW_V
```

```text
S=(QK^(T)) / (√(d_h))
```

```text
A=softmax(S+M)
```

```text
O=AV
```

可以记成：

```text
Q：决定我想找什么
K：决定我能否被匹配
QKᵀ：决定去哪里读取
Softmax：把匹配分数变成权重
V：实际被读取和汇总的信息
```

---

## 十二、为什么需要多个 Head？

假设模型只有一个 Attention Head。

对于某个 Query token，它只能产生一组 Attention 权重：

```text
[a_1,a_2,…,a_N]
```

这组权重会用于该 Head 的所有 Value 维度。

也就是说，一个 Head 在一次计算中只有一套主要的信息路由模式。

但自然语言中，一个 token 可能需要同时关注多种关系，例如：

* 局部相邻关系；
* 主语和谓语关系；
* 代词和指代对象；
* 开括号和闭括号；
* 函数调用和函数定义；
* 当前变量和此前赋值位置；
* 文档标题和当前段落；
* 特殊分隔符和消息边界。

Multi-Head Attention 允许模型同时产生多组独立的 Attention 权重矩阵：

```text
A^((1)),A^((2)),…,A^((h))
```

不同 Head 可以使用不同的投影空间：

```text
W_Q^((i)),W_K^((i)),W_V^((i))
```

因此它们可能学习不同的匹配关系。

这里的“可能”很重要：Head 的功能不是人工预先规定的，而且不同 Head 可能存在冗余。

---

## 十三、一个 Head 并不是只处理部分 Token

这是一个常见误解。

假设有 32 个 Head，并不是：

```text
Head 1 处理 Token 1～100
Head 2 处理 Token 101～200
```

在标准完整 Self-Attention 中，每个 Head 都可以处理整个 token 序列：

```text
Head 1：所有 token 对所有可见 token
Head 2：所有 token 对所有可见 token
...
Head 32：所有 token 对所有可见 token
```

各 Head 的不同之处主要是：

* 使用不同的投影矩阵；
* 在不同的向量子空间中比较 token；
* 形成不同的 Attention 权重；
* 汇总不同的 Value 表示。

---

## 十四、Multi-Head Attention 的完整计算

假设：

```text
d_(model)=4096
```

Query Head 数：

```text
h=32
```

每个 Head 的维度：

```text
d_h=(4096) / (32)=128
```

对于第 (i) 个 Head：

```text
Q_i=XW_Q^((i))
```

```text
K_i=XW_K^((i))
```

```text
V_i=XW_V^((i))
```

```text
head_i
=

softmax
(
(Q_iK_i^(T)) / (√(128))
+
M
)V_i
```

每个 Head 的输出形状是：

```text
[B,N,128]
```

32 个 Head 拼接后：

```text
Concat
(
head_1,…,head_(32)
)
 ∈
R^(B ×  N × 4096)
```

然后经过输出投影：

```text
Y=
Concat
(
head_1,…,head_(32)
)W_O
```

其中：

```text
W_O ∈ R^(4096 × 4096)
```

最终：

```text
Y ∈ R^(B ×  N × 4096)
```

输出维度重新回到模型隐藏维度，才能继续进行：

* 残差相加；
* 下一层计算；
* MLP 计算。

## 十五、Multi-Head 的张量形状变化

假设：

```text
B = 2
N = 1024
d_model = 4096
h = 32
d_head = 128
```

输入：

```text
X:[2,1024,4096]
```

完成 Q 投影后，最初通常是：

```text
Q:[2,1024,4096]
```

然后重新解释为 32 个 Head：

```text
Q:[2,1024,32,128]
```

转置维度后：

```text
Q:[2,32,1024,128]
```

同理：

```text
K:[2,32,1024,128]
```

```text
V:[2,32,1024,128]
```

计算：

```text
QK^(T)
```

得到：

```text
S:[2,32,1024,1024]
```

含义是：

```text
2 个 Batch
× 32 个 Head
× 1024 个 Query 位置
× 1024 个 Key 位置
```

Softmax 后：

```text
A:[2,32,1024,1024]
```

然后：

```text
AV:[2,32,1024,128]
```

转置并拼接：

```text
[2,1024,32,128]
 →
[2,1024,4096]
```

最后乘以 (W_O)：

```text
[2,1024,4096]
 →
[2,1024,4096]
```

## 十六、工程实现中通常不会真的创建 32 个独立模块

数学上可以写成：

```text
W_Q^((1)),W_Q^((2)),…,W_Q^((32))
```

但工程实现通常使用一个大矩阵：

```text
W_Q ∈ R^(d_(model) × (hd_h))
```

因为：

```text
hd_h=d_(model)
```

所以标准 MHA 中：

```text
W_Q ∈ R^(4096 × 4096)
```

一次矩阵乘法：

```text
Q=XW_Q
```

然后把最后一个维度拆成：

```text
32 × 128
```

K 和 V 通常也采用相同方式。

有些实现还会把 Q、K、V 三个投影融合到一个矩阵中：

```text
W_(QKV)
 ∈
R^(d_(model) × 3d_(model))
```

一次矩阵乘法同时得到 Q、K、V，再切分：

```text
QKV = X · W_QKV
Q, K, V = split(QKV)
```

数学结果不变，主要是为了提升 GPU 执行效率。

---

## 十七、为什么还需要输出投影 (W_O)？

多个 Head 拼接后，各 Head 的结果只是并排放置：

```text
[head_1 |
head_2 |
… |
head_h]
```

如果没有 (W_O)，不同 Head 的信息不会在 Attention 模块末尾进行充分混合。

输出投影：

```text
W_O
```

负责：

* 混合各 Head 的结果；
* 将不同 Head 的信息重新组合；
* 将拼接后的空间映射回模型隐藏空间；
* 为后续残差连接提供正确维度。

所以 Multi-Head Attention 不是简单地把多个 Head 的结果求平均，而是：

```text
【拼接后进行可学习的线性融合】
```

---

## 十八、单个大 Head 和多个小 Head 有什么区别？

假设隐藏维度均为 4096。

### 一个大 Head

```text
1 个 Head
Head 维度 = 4096
```

每个 Query token 只产生一套 Attention 分布：

```text
A_i=[a_(i1),a_(i2),…,a_(iN)]
```

然后这套权重用于整个 4096 维 Value。

---

### 32 个小 Head

```text
32 个 Head
每个 Head 维度 = 128
```

每个 Query token 可以产生 32 套不同的 Attention 分布：

```text
A_i^((1)),A_i^((2)),…,A_i^((32))
```

例如某个位置在不同 Head 中可能形成：

```text
Head 1：主要关注前一个 token
Head 2：主要关注句子开头
Head 3：主要关注某个分隔符
Head 4：主要关注同名变量
...
```

这些不是人工指定的规则，只是训练过程中可能形成的行为。

Multi-Head 的关键价值不只是“把维度拆小”，而是：

> **允许同一个 token 同时使用多套不同的信息寻址与汇总方式。**

---

## 十九、位置是如何进入 Attention 的？

只看：

```text
QK^(T)
```

Attention 本身主要比较向量内容。

如果完全没有位置编码，模型无法天然区分：

```text
A B C
```

和：

```text
C B A
```

中 token 的绝对或相对顺序。

因此必须引入位置信息。

---

### 1. 经典绝对位置编码

经典 Transformer 会把位置向量加到 token embedding 上：

```text
X_i=E_(token,i)+E_(position,i)
```

然后再计算 Q、K、V。

这样 Q 和 K 中自然包含位置信息。

---

### 2. RoPE

现代 LLM 经常使用 Rotary Position Embedding。

基本做法是：

```text
q_i'=R_iq_i
```

```text
k_j'=R_jk_j
```

其中：

* (R_i) 是由位置 (i) 决定的旋转变换；
* Query 和 Key 会根据各自位置旋转；
* Value 通常不应用同样的旋转。

之后计算：

```text
q_i'^(T)k_j'
```

可以写成与相对位置有关的形式：

```text
q_i^(T)R_i^(T)R_jk_j
```

其中：

```text
R_i^(T)R_j
```

与位置差 (j-i) 有关。

因此 Attention Score 同时包含：

* token 内容匹配；
* Query 和 Key 之间的相对位置关系。

典型计算顺序是：

```text
X
↓
线性投影得到 Q、K、V
↓
对 Q、K 应用 RoPE
↓
计算 QKᵀ
↓
Mask
↓
Softmax
↓
乘 V
```

---

## 二十、Attention Mask 不只有 Causal Mask

### 1. Causal Mask

防止当前位置看到未来 token：

```text
j>i ⇒  M_(ij)=-∞
```

用于自回归语言模型。

---

### 2. Padding Mask

当不同长度的序列被补齐时：

```text
序列 A：真实真实真实 PAD PAD
序列 B：真实真实真实真实真实
```

模型不应关注 PAD 位置，所以这些位置会被遮挡。

---

### 3. Segment 或 Block Mask

某些模型和推理系统会限制不同片段之间的信息访问，例如：

* 不允许不同样本互相看到；
* Packed Sequence 中隔离不同文档；
* 特定 Prefix 可以双向访问；
* 后续部分仍保持因果访问；
* Sliding Window 只允许查看附近位置。

Mask 的共同计算形式通常是：

```text
A=
softmax
(
(QK^(T)) / (√(d_h))+M
)
```

重点是：

> **Mask 必须在 Softmax 之前应用。**

---

## 二十一、MHA、GQA 和 MQA

现代 LLM 不一定让 Query、Key、Value 拥有相同数量的 Head。

定义：

| 符号       | 含义                |
| -------- | ----------------- |
| (h_q)    | Query Head 数量     |
| (h_{kv}) | Key/Value Head 数量 |

---

### 1. Multi-Head Attention，MHA

```text
h_q=h_(kv)
```

例如：

```text
32 个 Query Head
32 个 Key Head
32 个 Value Head
```

每个 Query Head 都有自己对应的 Key 和 Value Head。

张量形状：

```text
Q:[B,32,N,d_h]
```

```text
K:[B,32,N,d_h]
```

```text
V:[B,32,N,d_h]
```

---

### 2. Grouped-Query Attention，GQA

```text
h_q>h_(kv)>1
```

例如：

```text
32 个 Query Head
8 个 KV Head
```

通常可以理解为：

```text
每 4 个 Query Head 共享 1 组 K、V
```

形状：

```text
Q:[B,32,N,d_h]
```

```text
K,V:[B,8,N,d_h]
```

计算 Attention 时，每组 K、V 在逻辑上提供给对应的多个 Query Head。

例如：

```text
Query Head 0～3   共享 KV Head 0
Query Head 4～7   共享 KV Head 1
...
Query Head 28～31 共享 KV Head 7
```

每个 Query Head 仍有不同的 Q，所以它们产生的 Attention Score 仍可以不同。

---

### 3. Multi-Query Attention，MQA

```text
h_(kv)=1
```

例如：

```text
32 个 Query Head
1 个 Key Head
1 个 Value Head
```

所有 Query Head 共享同一套 K、V。

---

### 三者对比

| 类型  | Query Head | KV Head | 主要特点                  |
| --- | ---------: | ------: | --------------------- |
| MHA |         32 |      32 | 每个 Query Head 有独立 K、V |
| GQA |         32 |       8 | 若干 Query Head 共享 K、V  |
| MQA |         32 |       1 | 所有 Query Head 共享 K、V  |

GQA/MQA 主要减少：

* K、V 投影参数；
* KV Cache 显存；
* 解码时读取 KV Cache 的带宽。

它们不会取消每个 Query Head 自己的 Attention 权重计算。

---

## 二十二、Prefill 时 Attention 如何计算？

假设输入有 (N) 个 token。

Prefill 阶段会一次处理全部输入：

```text
Q,K,V:[B,h,N,d_h]
```

Attention Score：

```text
S:[B,h,N,N]
```

对 Decoder-only 模型使用下三角因果 Mask。

虽然模型一次并行计算所有 Query，但每个位置只能访问自己及此前位置：

```text
Query 1 → Key 1
Query 2 → Key 1, 2
Query 3 → Key 1, 2, 3
...
Query N → Key 1, 2, ..., N
```

其有效关系数量为：

```text
1+2+…+N
=

(N(N+1)) / ()2
```

所以 Prefill Attention 的复杂度是：

```text
O(N^2d_(model))
```

---

## 二十三、逐 Token 解码时如何计算？

Prefill 后，过去 token 的 K、V 会保存在 KV Cache 中。

假设目前已有 (N) 个 token，模型正在生成下一个 token。

新 token 只需计算：

```text
q_(new),k_(new),v_(new)
```

其中：

```text
q_(new):[B,h_q,1,d_h]
```

历史 Key Cache：

```text
K_(cache):[B,h_(kv),N,d_h]
```

新 Query 与历史全部 Key 做点积：

```text
q_(new)K_(cache)^(T)
```

得到：

```text
S_(new):[B,h_q,1,N]
```

Softmax 后乘历史 Value：

```text
A_(new)V_(cache)
```

得到：

```text
O_(new):[B,h_q,1,d_h]
```

接着把新 token 的：

```text
k_(new),v_(new)
```

追加到 KV Cache，供下一次生成使用。

因此 Decode 时不是重新计算完整的：

```text
[N,N]
```

而是只计算新 Query 对历史 Key 的：

```text
[1,N]
```

这就是为什么有 KV Cache 时，生成一个新 token 的 Attention 计算量对历史长度是线性的。

---

## 二十四、Attention 的计算复杂度

对于一个完整 MHA 层：

### 1. Q、K、V 投影

标准 MHA 中：

```text
Q=XW_Q,  K=XW_K,  V=XW_V
```

复杂度约为：

```text
O(BNd_(model)^2)
```

---

### 2. 计算 `QK^(T)`

每个 Head：

```text
[N,d_h] × [d_h,N]
```

复杂度：

```text
O(N^2d_h)
```

所有 Head：

```text
O(hN^2d_h)
```

因为：

```text
hd_h=d_(model)
```

所以：

```text
O(N^2d_(model))
```

---

### 3. 计算 (AV)

同样是：

```text
O(N^2d_(model))
```

因此 Attention 中与 token 两两交互有关的部分为：

```text
O(BN^2d_(model))
```

---

### 4. Attention 权重矩阵显存

如果显式保存完整 Attention 矩阵：

```text
A:[B,h,N,N]
```

元素数量为：

```text
BhN^2
```

所以显存是：

```text
O(BhN^2)
```

FlashAttention 会通过分块和在线 Softmax 避免把完整的 `N ×  N` 矩阵写入显存，但计算的数学目标仍然是：

```text
softmax
(
(QK^(T)) / (√(d_h))
)V
```

它没有改变标准完整 Attention 的数学结果，也没有把所有计算都变成线性复杂度。

---

## 二十五、对应的简化代码

下面代码定义：

* `x`：输入，形状为 `[B, N, D]`
* `num_heads`：Query Head 数量
* `w_q`、`w_k`、`w_v`、`w_o`：投影矩阵
* 使用标准 MHA，即 Q、K、V Head 数量相同

```python
import math

import torch
from torch import Tensor


def causal_multi_head_attention(
    x: Tensor,
    w_q: Tensor,
    w_k: Tensor,
    w_v: Tensor,
    w_o: Tensor,
    num_heads: int,
) -> Tensor:
    """
    x:   [B, N, D]
    w_q: [D, D]
    w_k: [D, D]
    w_v: [D, D]
    w_o: [D, D]

    返回:
        [B, N, D]
    """
    if x.ndim != 3:
        raise ValueError("x 必须具有 [B, N, D] 三个维度")

    batch_size, sequence_length, model_dim = x.shape

    if model_dim % num_heads != 0:
        raise ValueError("model_dim 必须能被 num_heads 整除")

    head_dim = model_dim // num_heads

    # 1. 线性投影
    q = x @ w_q  # [B, N, D]
    k = x @ w_k  # [B, N, D]
    v = x @ w_v  # [B, N, D]

    # 2. 拆分 Head，并将 Head 维度移到前面
    q = q.reshape(
        batch_size,
        sequence_length,
        num_heads,
        head_dim,
    ).transpose(1, 2)  # [B, H, N, Dh]

    k = k.reshape(
        batch_size,
        sequence_length,
        num_heads,
        head_dim,
    ).transpose(1, 2)  # [B, H, N, Dh]

    v = v.reshape(
        batch_size,
        sequence_length,
        num_heads,
        head_dim,
    ).transpose(1, 2)  # [B, H, N, Dh]

    # 3. 计算缩放点积
    scores = q @ k.transpose(-2, -1)
    scores = scores / math.sqrt(head_dim)
    # scores: [B, H, N, N]

    # 4. 创建因果 Mask
    future_positions = torch.triu(
        torch.ones(
            sequence_length,
            sequence_length,
            dtype=torch.bool,
            device=x.device,
        ),
        diagonal=1,
    )

    scores = scores.masked_fill(
        future_positions,
        float("-inf"),
    )

    # 5. 对 Key 维度执行 Softmax
    attention_weights = torch.softmax(scores, dim=-1)
    # attention_weights: [B, H, N, N]

    # 6. 对 Value 加权求和
    context = attention_weights @ v
    # context: [B, H, N, Dh]

    # 7. 合并 Head
    context = context.transpose(1, 2).contiguous()
    context = context.reshape(
        batch_size,
        sequence_length,
        model_dim,
    )
    # context: [B, N, D]

    # 8. 输出投影
    output = context @ w_o
    # output: [B, N, D]

    return output
```

真实实现还可能包含：

* RoPE；
* Attention Dropout；
* Padding Mask；
* GQA/MQA；
* KV Cache；
* FlashAttention；
* 张量并行；
* 数值稳定处理；
* 融合 QKV 投影。

但核心数学逻辑就是上述过程。

## 二十六、几个容易误解的地方

### 误解一：Attention 权重就是 token 的绝对重要性

不是。

Attention 权重具有以下限定：

* 它属于某一层；
* 它属于某一个 Head；
* 它针对某一个 Query；
* 它受到 Mask 和位置编码影响；
* 它只是该层信息路由的一部分；
* 最终结果还经过输出投影、残差、MLP 和后续层。

因此不能简单地说：

```text
某 token 的 Attention 权重大
→ 它对整个模型最终答案一定最重要
```

---

### 误解二：每个 Head 对应固定语言功能

没有这种硬性规定。

有些 Head 可能表现出相对稳定的模式，但：

* 功能是训练产生的；
* 不同模型不同；
* 不同层不同；
* 多个 Head 可能冗余；
* 同一个 Head 也可能处理多种关系。

---

### 误解三：Value 也参与匹配

匹配主要由：

```text
QK^(T)
```

完成。

Value 不决定 Softmax 权重，而是在权重确定之后被汇总：

```text
AV
```

---

### 误解四：Multi-Head 是把 token 分给不同 Head

不是。

标准 MHA 中，每个 Head 都能看到完整的可见序列，只是在不同投影子空间中计算不同的关系。

---

### 误解五：Attention 输出是对原始 token embedding 加权平均

更准确地说，是对：

```text
V=XW_V
```

进行加权求和。

而 (X) 本身可能已经包含：

* 词义；
* 位置；
* 上下文；
* 前面多层 Transformer 的处理结果。

---

### 误解六：Attention 只在第一层执行一次

每个 Transformer Block 都会重新执行 Attention。

第 (l) 层使用上一层的输出：

```text
X^((l))
```

重新计算：

```text
Q^((l)),K^((l)),V^((l))
```

所以同一 token 在不同层：

* Query 不同；
* Key 不同；
* Value 不同；
* Attention 权重也不同。

较低层、较高层可以形成完全不同的信息交互。

---

## 二十七、最终把整个逻辑连起来

对于输入：

```text
X ∈ R^(B ×  N ×  d_(model))
```

第一个 Head：

```text
Q_1=XW_Q^((1))
```

```text
K_1=XW_K^((1))
```

```text
V_1=XW_V^((1))
```

计算：

```text
A_1=
softmax
(
(Q_1K_1^(T)) / (√(d_h))+M
)
```

汇总：

```text
H_1=A_1V_1
```

其余 Head 同理：

```text
H_i=
softmax
(
(Q_iK_i^(T)) / (√(d_h))+M
)V_i
```

最后：

```text
MHA(X)
=

Concat(H_1,H_2,…,H_h)W_O
```

完整流程是：

```text
每个 token 的隐藏向量 X
          ↓
分别投影成 Q、K、V
          ↓
每个 Query 与所有可见 Key 点积
          ↓
除以 √d_head 控制数值尺度
          ↓
加入 Causal / Padding Mask
          ↓
逐 Query 执行 Softmax
          ↓
得到从各位置读取信息的权重
          ↓
对 Value 进行加权求和
          ↓
得到一个 Head 的输出
          ↓
拼接所有 Head
          ↓
通过 W_O 融合不同 Head
          ↓
进入残差连接和后续 Transformer 结构
```

Attention 最本质的作用是：

> **为每一个 token 动态计算一套信息路由规则，使它能够根据当前内容和位置，从其他可见 token 的 Value 中读取并组合所需信息。**
