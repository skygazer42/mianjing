## 5. 需求 A：29-agent-loop 新专题

### 5.1 定位与去重边界
主题：**单个 Agent 循环的运行时内核**——loop 每一步「怎么转、怎么记、怎么走、怎么停」的微观机制。刻意回避已被占据的领域：多 Agent 协作细节、MCP、Saga 事务、工具 schema/发现、持久化事件溯源、安全代码 VM、记忆三层分类。

显式交叉引用去重（写入 README）：
- 题 5「loop step 幂等」≠ 智能代理「工具调用幂等键」（循环步级 vs 工具级）；
- 题 11/12「循环内上下文动态演化」≠ 智能代理「按预算一次性选 context」（推进中演化 vs 单次选择）；
- 题 26/27「loop step 粒度可回放 trace + 确定性重放」≠ 21「成本归因 trace」、≠ 智能代理「trace 分层评分」；
- 题 19/20「循环自身停止信号」≠ 智能代理「终态 grader」。

### 5.2 30 题主题大纲

**A. 循环骨架与状态机（loop 怎么"转"）**
1. Agent Loop 最小运行时骨架：一个 step 的阶段划分与状态机定义
2. ReAct 式 Thought–Action–Observation 交织 vs 直接函数调用循环
3. 单步决策粒度：一步产出一个还是一组动作，往返成本 vs 错误定位
4. 循环主控制器：驱动循环、注入观察、判断继续/停止的确定性外壳
5. 循环 step 级幂等：同一步被重试重复执行时 loop 状态怎么不被污染
6. 循环状态对象设计：goal/history/scratchpad/step/budget 的最小 schema
7. 同步循环 vs 事件驱动循环：何时让出控制权等待外部事件
8. 单步可测：把一步做成纯函数以支持单测与回放

**B. 观察 · 上下文 · 工作记忆的循环内演化（loop 怎么"记"）**
9. Observation 规范化：环境返回怎么裁剪/结构化/去噪后回喂
10. 超大 observation 的选择性读取与分页
11. 循环历史滚动窗口：保留/丢弃哪些步、按什么信号
12. 循环历史摘要压缩：何时触发、压缩什么、不丢关键决策依据
13. Scratchpad/working memory 的循环内维护与失效
14. Context 中毒：一条错误观察污染后续决策，怎么隔离与回滚
15. 跨步指代一致性：前几步产出的实体/ID 怎么稳定引用
16. 循环内 token 预算记账：每步消耗估算与逼近上限时的降级

**C. 决策 · 行动 · 推进控制（loop 怎么"走"）**
17. 每步 action 合法性约束：结构化输出/受控解码
18. 无进展检测（loop stall）：识别重复动作/语义打转/震荡并打破
19. 终止条件设计：完成/无进展/超预算/超时四类停止信号的优先级
20. 完成判定：模型自称完成 vs 客观后置验证，防「假完成」
21. 提前终止 vs 过度执行：premature stop 与 overrun 的成因与防护
22. Backtrack/换策略：失败后回退到哪个检查点、换什么策略
23. Look-ahead 试探：不产生真实副作用地预演下一步
24. 探索 vs 利用：给循环一个探索预算，避免过早收敛或无限试探

**D. 稳健性 · 可观测 · 评测（loop 怎么"稳"和"验"）**
25. 子循环嵌套（sub-loop）：内层 loop 的深度/预算/结果回传与隔离
26. 循环级 trace：每步记录什么才能支持回放与因果定位
27. 确定性重放：固定模型输出与观察后让整条 loop 可复现
28. 循环失败注入测试：工具失败/观察缺失/超预算/乱序返回
29. 循环成本与延迟模型：端到端 = Σ每步成本，怎么压缩步数
30. 循环级发布门禁：固定任务集评测一次 loop 改动的成功率/步数/成本回归

## 7. 格式与验收约定

### 7.1 md 答案
对齐 `29-智能代理` 现有样式；结论先行 5–8 句可直接复述；真实案例含脱敏小数据与不可外推边界；附权威原始资料链接。

### 7.2 notebook 硬要求（来自 `scripts/validate_teaching_notebooks.py`，逐条卡）
- Markdown 必含四章节关键词：**真实案例 / 基线 / 结果解读 / 失败案例**。
- ≥6 代码单元、≥4 次 `print`/`display`/`pprint`、≥3 个有输出单元、保存输出总量 ≥200 字符。
- 每个有效代码物理行**带中文同行注释**；一行一语句、无分号、无省略号 Ellipsis 占位。
- `assert` ≤8 条且**只在最后一个代码单元**。
- 每个代码单元有 `execution_count`、保存确定性输出、不保存异常/秘密/PII/超大二进制。
- 只用**标准库 + NumPy** 从零实现，不用 Agent 框架/一站式 API 替代循环内核；含 baseline→主算法→失败反例→修正。

### 7.3 实现与验收流程（每本 notebook 强制）
```
写 .ipynb（cell 结构 + 中文行注释）
  → jupyter nbconvert --execute --inplace 真跑，填充 execution_count + 输出
  → python3 scripts/validate_teaching_notebooks.py <file> 必须 PASS
  → 不过则修复重跑
```
环境已确认可行：Python 3.10.14、numpy 1.26.4、nbformat 5.9.2、nbconvert 7.16.4、nbclient 0.10.0、ipykernel 6.29.5；现有 notebook 跑校验 PASS。
