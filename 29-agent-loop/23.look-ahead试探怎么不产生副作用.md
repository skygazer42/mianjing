# Look-ahead 试探：不产生真实副作用地预演下一步？

## 结论先行

有时循环需要在真正执行前**预演**一个动作看看会发生什么，但预演绝不能产生真实副作用（不能真的发一笔退款去"试试"）。做法是 **dry-run / 影子执行**：用一个不改变真实状态的模拟，基于当前状态推断动作结果（或调用工具的 dry-run 模式），据此判断是否值得真执行、或在多个候选动作里选优。核心区分是**预演（无副作用、可丢弃）vs 真执行（有副作用、不可回退）**：预演在一个状态副本或纯预测函数上进行，真执行才作用于权威状态。适用场景：高风险不可逆动作前的可行性校验、多候选动作的比较选优。反面是「直接执行来试」——把不可逆副作用当探针，或者完全不预演、盲目执行高风险动作导致透支/越权/数据损坏。

## 真实案例

一个转账 agent，转账前先 dry-run 检查余额是否足够：预演在状态副本上模拟扣款，发现会透支就不真转。Notebook 对比无 dry-run（直接转导致余额变负/透支）与 dry-run（预演发现余额不足、拒绝执行、真实余额不变）。数据为教学账户，不代表真实支付系统。

## 工程取舍与常见坑

- **预演必须无副作用**：在状态副本或纯预测函数上做，绝不能碰权威状态或真实外部系统。
- **dry-run 的保真度是关键**：预演结果要足够接近真执行，否则「预演通过但真执行失败」更危险。
- **预演也有成本**：模拟/dry-run 调用消耗步数和 token（题 16），不是免费的，别对每个动作都预演。
- **高风险才值得预演**：可逆的只读动作直接做即可，预演优先用于不可逆副作用（转账、删除、发货）。

## 延伸追问

「dry-run 和多步 look-ahead 搜索什么关系？」答：单步 dry-run 是「预演一个动作的直接后果」；多步 look-ahead 是把 dry-run 串起来在状态副本上模拟一条动作序列，评估整条路径——后者更贵，只在分支关键、代价高时才做。
