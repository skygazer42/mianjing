# 无进展 loop stall 怎么检测重复动作/震荡并打破？

## 结论先行

循环可能陷入无进展：**重复同一动作**（反复查同一个不存在的订单）、**状态震荡**（A→B→A→B 来回切）、或**语义打转**（换个说法做同样的事）。只靠 `max_steps` 兜底会白白烧完所有预算才停，且分不清「在推进」和「在打转」。所以要有独立的 stall 检测：记录最近 K 步的（动作 + 状态签名），检测「同一动作连续重复 N 次」「状态签名成环」「状态连续无变化」。检测到 stall 后**主动打破**——换策略（题 22）、升级人工、或提前终止返回当前最佳结果。关键是 stall 检测是独立于完成判定的**额外停止/干预信号**（题 19），它回答的是「还在有效前进吗」而不是「做完了吗」。反面是没有 stall 检测，循环在原地打转直到耗尽步数，既浪费预算又延迟失败暴露。

## 真实案例

一个 agent 反复对同一个不存在的订单执行 `lookup`，状态签名每步都不变。Notebook 维护最近动作与状态签名历史，检测「同一(动作,签名)连续 3 次」判定为 stall 并打破，对比无检测（一直重复到 `max_steps=8`）与有检测（第 3 次重复就停）；再用一个「动作相同但每步读不同页」的有进展 agent，证明检测器不会把它误判为 stall。数据为教学循环，不代表真实 agent。

## 工程取舍与常见坑

- **状态签名要能反映实质进展**：对关键状态字段做签名，签名不变说明没前进，而不是只看动作名。
- **区分「重复但有进展」与「重复且无进展」**：同一动作若每次观察不同（分页读下一页）是进展，不算 stall。
- **打破不等于放弃**：优先换策略或升级，其次才是返回部分结果（呼应题 21 过度执行）。
- **阈值要可调**：连续重复几次算 stall 取决于任务，需用回归集校准（题 30）。

## 延伸追问

「震荡（A→B→A→B）怎么检测？」答：不能只看「连续相同」，要在最近 K 步的状态签名里检测环——出现重复签名且中间没有引入新签名，就是震荡；打破方式是禁止刚访问过的状态转移或强制探索新动作（呼应题 24）。
