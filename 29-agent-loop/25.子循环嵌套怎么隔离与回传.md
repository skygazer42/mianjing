# 子循环嵌套（sub-loop）：内层 loop 的深度/预算/结果回传与隔离？

## 结论先行

复杂任务里某个子任务可能需要开一个内层循环（sub-loop）。嵌套必须解决四件事：(1) **深度控制**——限制嵌套层数，防止无限递归/栈溢出；(2) **预算隔离**——父循环把总预算的一部分分给子循环，子循环在自己的子预算内运行，超支只影响自己、不拖垮父循环；(3) **状态隔离与结果回传**——子循环只把最终结果/摘要回传给父循环，其完整内部状态（scratchpad、中间步）不泄漏到父上下文，避免污染（题 14）；(4) **失败隔离**——子循环失败作为父循环的「一个动作失败」处理（可 backtrack/换策略，题 22），而不是直接崩掉父循环。反面：子循环无深度限制（无限嵌套）、与父共享预算无隔离（子循环烧光父预算）、或内部状态泄漏污染父上下文。

## 真实案例

主任务「写报告」中的子任务「检索资料」开一个子循环。父分配子预算（如父预算的 40%）和深度上限，子循环只回传检索结果摘要而非全部中间步。Notebook 对比无深度限制（嵌套一直下探到安全上限）与有限制（到达 `max_depth` 即停），并展示子预算隔离使父预算不被透支。数据为教学循环，不代表真实系统。

## 工程取舍与常见坑

- **深度上限是硬约束**：每进入一层子循环深度 +1，超过 `max_depth` 直接拒绝，防栈溢出/无限嵌套。
- **子预算不能透支父预算**：分配后隔离核算，子循环超支返回部分结果，不动用父的剩余预算。
- **只回传摘要**：子循环的内部 history/scratchpad 不进父上下文，只回传结构化结果（呼应题 12 摘要）。
- **失败当动作失败**：子循环失败是父的一个可处理事件，不是致命异常（呼应题 21/22）。

## 延伸追问

「和多 Agent 什么区别？」答：sub-loop 是同一控制体系内的嵌套循环，共享父的调度和预算体系、只是隔离子预算/状态；多 Agent 是独立主体间的协作（各有身份、消息传递）。这里只谈单控制体系内的循环嵌套，不涉及跨 Agent 通信。
