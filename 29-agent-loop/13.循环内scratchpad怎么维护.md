# Scratchpad/working memory 在循环内怎么维护与失效？

## 结论先行

scratchpad 是循环的工作记忆，存放当前的中间结论、计划和**假设**——它是推测，不是事实。三条维护原则：(1) **推测与事实分离**——scratchpad 存推测，history 存事实（回读/工具结果），两者不能混（呼应题 06、14）；(2) **假设可失效**——每个 scratchpad 条目带来源和依据，当新观察推翻它时要**失效或更新**该条目，而不是把新旧假设一起堆着；(3) **有界清理**——已确认（升格为事实）或已失效的条目要清出 scratchpad，防止无限增长。最大的坑是把推测当事实用（"我之前假设用户要退款"就直接退款），以及旧假设不失效、导致基于过期判断决策。scratchpad 的价值是让循环"带着可修正的当前理解"前进，而不是"一次假设定终身"。

## 真实案例

客服 agent 先根据第一句话假设「用户意图=退款」（低置信），随后用户补充「我想换一个尺码」。好的 scratchpad 用新观察失效旧假设、更新为「换货」；坏的 scratchpad 保留两个矛盾假设，可能仍按退款执行。Notebook 对比失效机制开/关时的最终决策。数据为教学事件，不代表真实客服系统。

## 工程取舍与常见坑

- **假设要带置信度和来源**：低置信假设不能驱动不可逆动作，得先被观察确认（呼应题 01 以回读为准）。
- **冲突要失效不是叠加**：新证据与旧假设冲突时更新旧条目，别让 scratchpad 同时留着「退款」和「换货」。
- **别让推测升格为事实**：只有被权威观察确认的假设才能写入 history，否则一直留在 scratchpad。
- **有界**：scratchpad 也占预算（题 16），要清理已解决的假设。

## 延伸追问

「怎么知道一个假设该失效？」答：给假设标注它依赖的观察；当有新观察与该依赖冲突（同一字段的更权威回读）时触发失效。这与「智能代理」专题里温度冲突驱动的记忆更新思路一致，但这里作用在单循环的工作记忆上。
