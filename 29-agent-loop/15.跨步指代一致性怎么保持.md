# 跨步指代一致性：前几步产出的实体/ID 怎么稳定引用？

## 结论先行

循环多步执行时，前面步骤产出的实体——一个创建的资源 id、一次检索到的文档、一个中间结果——需要在后续步骤被稳定引用。风险在于模型习惯用自然语言指代（「那个订单」「刚才查到的用户」），当存在多个同类实体时极易指错，或模型重新描述时描述漂移导致引用失败。正确做法是给每个产出的实体分配**稳定的 handle/ref**（如 `ref://order/1`），循环维护一个 ref 表（handle → 实体），后续步骤一律用 handle 引用而不是自然语言描述。这把「靠语义猜是哪一个」变成「靠 id 精确取」。handle 由确定性外壳在实体产出时分配并登记，不由模型即兴命名，否则命名本身也会漂移。

## 真实案例

一个循环先后创建了两个订单 order A 和 order B，随后要给 A 发货。用自然语言「第一个订单」在模型看来可能指向 B（顺序记混）；用 `ref://order/a` 则精确无误。Notebook 对比自然语言指代（多实体时指错）与 handle 引用（稳定命中）。数据为教学实体，不代表真实订单系统。

## 工程取舍与常见坑

- **handle 由外壳分配**：实体产出时立即登记稳定 id，不让模型自己起名（模型命名会漂移）。
- **自然语言指代在多实体时必错**：一旦同类实体 >1，「那个/第一个」就有歧义。
- **ref 表要可序列化**：它是循环状态的一部分（题 06），崩溃恢复后仍要能解析 handle。
- **handle 要校验存在**：引用不存在的 handle 应报错而不是静默取到错误实体（呼应题 17 动作合法性）。

## 延伸追问

「handle 和外部系统真实 id 什么关系？」答：handle 是循环内的稳定引用，可以映射到外部真实 id，也可以是循环本地别名；关键是循环内引用稳定、可校验，外部 id 变化时只需更新映射，不影响已产出的推理链。
