# 提前终止 vs 过度执行：premature stop 与 overrun 的成因与防护？

## 结论先行

这是一对**对称的失败**：premature stop（提前终止——没做完就停，把未完成当完成）和 overrun（过度执行——做完了还继续，浪费预算甚至破坏已完成的工作，比如重复退款）。premature 的成因：模型误判完成（题 20 假完成）、遇到一个错误就放弃、stall 检测过于激进。overrun 的成因：完成判定缺失或太弱、根本没有 done 信号、模型停不下来。防护也对称：防 premature 用**客观完成验证**（题 20）+ 区分「可恢复错误」与「致命错误」（一次工具报错不等于任务失败，可重试/换路）；防 overrun 用**明确的 done 判定**+ 完成后禁止进一步副作用动作。关键认识是这两个风险此消彼长：完成判定调太严会滑向 overrun，调太松会滑向 premature，必须同时守两边。

## 真实案例

一个退款任务。premature 场景：第一个工具调用报了一个可重试的超时错误，循环就放弃了（其实重试能成功）。overrun 场景：订单已经退款成功，循环没有 done 检查，又执行了一次退款（重复退款）。Notebook 对比「遇错即停 vs 区分可恢复错误后继续」和「无 done 检查重复退款 vs 有 done 检查停止」。数据为教学状态，不代表真实系统。

## 工程取舍与常见坑

- **错误 ≠ 任务失败**：区分可恢复（超时、限流）与致命（参数非法、权限拒绝），前者重试/换路，别一遇错就 premature。
- **完成后要「封闭」**：done 之后禁止再执行有副作用的动作，防 overrun 破坏已完成工作。
- **两个风险要一起测**：只测「能不能停下来」会忽略「该不该停」，反之亦然。
- **幂等是 overrun 的安全网**：即使多执行一次，工具幂等能减轻重复副作用。

## 延伸追问

「怎么量化这两个风险的平衡点？」答：在回归集（题 30）上同时统计「未达成就停止的比例（premature 率）」和「达成后多余步数/重复副作用（overrun 率）」，调完成判定阈值时看两条曲线的交叉，而不是只优化一个。
