# 30. 不同长度、模态和部署约束下如何选择位置机制？

## 决策维度

位置方案应由序列结构（双向/因果、1D/2D/时间）、训练长度与目标长度、是否需要增量生成、继续训练预算、kernel 支持和 checkpoint 兼容共同决定。不存在只按“外推最好”选择的通用冠军。

## 场景建议

固定短长度、数据充足的编码器或视觉模型，可学习绝对位置简单且灵活；长度变化较温和、希望无参数时固定正弦是稳健基线。Decoder-only LLM 常采用 RoPE，因为相对 QK 几何、增量计算和高效 kernel 生态成熟；目标长度远大于预训练时需选经验证的缩放并继续训练。强调单调局部偏置、希望解析延伸且实现简单时可考虑 ALiBi。需要可解释距离桶或双向相对方向时，T5 风格 bias 很自然。

图像应保留二维坐标，视频还需时间轴；多模态要分开模态身份、内部坐标与跨模态全局关系。强行把所有 token 展平成一个绝对序号可能造成分辨率和模态长度变化时错位。

## 工程现实

已有 checkpoint 优先保持原机制，因为迁移会改变所有层。确认推理框架是否支持 rotary layout、动态 scaling、relative bias 与目标 attention kernel；理论方案若迫使退回慢 kernel，整体吞吐可能不可接受。位置方案不降低 attention 的二次复杂度，超长部署还需单独解决计算、显存和数据。

## 评估流程

对候选方案在同训练预算下比较：原长度困惑度、长度曲线、局部顺序、远距证据、多语言/模态切片、峰值显存和 p95 延迟。检查左 padding、packing、滑窗和逐步生成一致性。结果应形成质量—长度—成本 Pareto，而非只报最大可接受 token 数。

面试回答可先问五个问题：什么坐标结构、训练多长、要外推多远、是否沿用 checkpoint、kernel 支持什么；再给出带条件的选择。最成熟的结论通常是“保持协议、用数据验证”，而不是追逐名词更新。
