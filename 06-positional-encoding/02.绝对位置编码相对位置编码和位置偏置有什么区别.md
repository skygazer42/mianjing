# 02. 绝对位置编码、相对位置编码和位置偏置有什么区别？

## 三类机制

绝对位置编码给位置 \(i\) 一个表示 \(p_i\)，通常与 token embedding 相加：\(h_i=x_i+p_i\)。正弦编码和可学习位置表属于此类。模型先知道“我在第 17 位”，再由 Q/K 投影间接学习位置关系。

相对位置表示直接把 \(i-j\) 注入 token 对之间的交互。例如 Shaw 方法可在 key/value 路径加入距离向量，attention score 包含 \(q_i^\top a_{i-j}\)。RoPE虽通过绝对角度旋转 Q/K 实现，但旋转后的点积只显式依赖相对差，因此常归入相对位置机制。

位置偏置只对 attention logit 加标量 \(b(i,j)\)：

\[
s_{ij}=\frac{q_i^\top k_j}{\sqrt{d_k}}+b(i,j).
\]

T5 的 bucketed relative bias 和 ALiBi 是代表。它不直接改变 value 内容，参数与计算通常更轻。

## 能力与成本

绝对位置实现简单，但可学习表有最大索引，超长时没有训练行；固定正弦可计算任意位置，却不保证网络在超长分布上会使用。相对方法更直接表达距离平移不变性，常有更好的长度泛化，但可能需要构造 \(L\times L\) 距离索引或专用 kernel。Bucket 能把远距离压缩成少数类别，省参数却损失精确距离。

位置偏置只改变“看谁”的先验，value 本身不携带位置；有些任务需要丰富位置内容时，纯标量偏置可能容量不足。RoPE 的 Q/K 旋转几乎不增加注意力矩阵存储，但长长度频率分布需要特别处理。

## 选择和误区

“绝对”和“相对”不是严格互斥：模型可同时使用可学习绝对向量与相对偏置；RoPE 的实现输入是绝对 position id，但点积呈相对性质。判断一种方案不能只看公式能否生成超长位置，还要看训练长度、mask、数值精度和任务评估。

面试时可沿“注入位置：输入表示、QK/V 交互、logit 标量”三层比较，再讲参数、外推与 kernel 兼容性。这样能避免把所有非正弦方法都模糊地称为相对编码。
