# 23. 左 padding 和右 padding 为什么容易造成位置错位？

## 问题本质

Padding 改变张量索引，但通常不应改变有效 token 在语义序列中的位置。右 padding 时有效 token 从数组 0 开始，默认 arange 恰好正确；左 padding 时有效 token 被推到后面，若仍用统一 \([0,\ldots,L-1]\)，同一句因 batch 最大长度不同会得到不同 position_ids。

例如长度 3 的句子在宽度 5 左填充后为 \([P,P,a,b,c]\)。默认索引让 a,b,c 使用 2,3,4；按有效序列重新编号应是 0,1,2。可用

\[
p_i=\max(\operatorname{cumsum}(mask)_i-1,0)
\]

生成，PAD 填 0 并由 mask 屏蔽。是否需要重编号取决于 checkpoint 训练约定，但生成模型做批量左 padding 时通常必须显式处理。

## 为何输出会变

可学习绝对表直接换了三行；正弦/RoPE 换了角度。RoPE 的 QK 点积对共同平移具有相对性质，似乎整体加 2 应不变，但 causal 边界、未旋转通道、数值实现、其他位置机制及缓存 offset 仍可能让结果不同；更重要的是 PAD key 必须彻底屏蔽。不能用相对性质为错误 position_ids 辩护。

## 生成与训练

Decoder 批量生成常选左 padding，让每条请求的最后有效 token 位于同一列，便于取 logits；训练常选右 padding。切换 padding_side 时应做 full-vs-incremental 和 single-vs-batch 回归。EOS 被复用为 PAD 时，attention mask 必须按实际填充位置构造，不能简单用 token_id != eos，否则真实 EOS 会被屏蔽。

## 排障

打印 token、mask、position 三元组；同一句放在不同 batch 宽度比较最后有效位置 logits；检查全 PAD 样本、BOS 和截断。许多“批量生成质量下降”其实是 position/mask 错位，而非模型并行数值误差。

面试回答应说明左 padding 改数组索引、用 mask cumsum 恢复有效位置，并强调 attention mask、position_ids 和最后有效 token 索引是三个独立但同步的问题。
