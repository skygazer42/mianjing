# 05. 位置向量与 token embedding 为什么通常相加而不是拼接？

## 主要原因

相加保持表示宽度 \(d_{\text{model}}\) 不变：

\[
h_i=x_i+p_i.
\]

后续 Q/K/V 和前馈层无需扩宽，参数量、残差形状和 kernel 都保持简单。拼接若得到 \([x_i;p_i]\in\mathbb{R}^{d_x+d_p}\)，要么让整个主干变宽、显著增加参数和 FLOPs，要么立即通过投影压回 \(d_{\text{model}}\)。后者本质是学习 \(W_xx_i+W_pp_i\)，与“分别投影后相加”接近。

## 相加为何不会简单覆盖语义

高维向量可以在不同子空间/方向同时承载内容和位置，线性投影会学习如何组合。模型并不要求能从 \(x+p\) 无损还原两个原向量，只需保留对任务有用的信息。残差、归一化和多层非线性还会继续重组信号。关键是两者尺度匹配；若固定位置向量远大于 token embedding，内容确实会受压制，因此经典架构可能对 embedding 做 \(\sqrt d\) 缩放。

## 拼接何时有价值

若位置特征维度很小、语义明确且希望模型显式区分通道，例如坐标、时间间隔、多模态框位置，拼接后用专门投影可能更灵活。代价是参数和接口复杂。相对位置 bias、RoPE 等方案甚至不在输入层融合，而是在 attention logit 或 Q/K 上注入，绕开“加还是拼”的选择。

## 工程误区

相加要求位置与 token 表最后一维相同，并正确广播为 \([B,L,d]\)。Padding 位置即使 token 行为零，加上位置后仍非零，所以必须依靠 attention/label mask，而不能认为零 PAD embedding 足够。若模型 checkpoint 原本采用相加，改拼接会改变所有后续权重形状，无法直接兼容。

面试回答应从维度与成本解释“通常相加”，说明相加是可学习的信号叠加而非语义覆盖，再指出拼接与投影、相对偏置、RoPE 都是合理变体，最终由架构和任务验证决定。
