# 28. 如何排查 position_ids 的 off-by-one、越界和复用错误？

## 先打印协议

对最小样例同时打印 token 字符串、token id、attention mask、position id、segment id 和 label。明确 BOS 是否占 0、左/右 padding、有效长度、截断起点及新增 token 的下一位置。多数位置 bug 不是公式错误，而是数据管线和模型对这些约定理解不同。

## 三类故障

**Off-by-one** 常来自服务和 tokenizer 都添加 BOS，或生成时把前缀长度减/加错。症状是 full forward 与逐步 decode logits 从首个生成位置开始不一致。

**越界** 对可学习位置表会直接 index error；对 RoPE 动态生成未必报错，却可能超过配置缓存长度或未应用预期 scaling。检查最大有效 position，而不是张量长度；全 PAD 行的 cumsum-1 还可能产生 -1。

**复用错误** 出现在批重排、请求复用、packed samples 或滑窗：token 状态移动了，position offset 没同步；不同 rope scale 的请求误用同一 cos/sin cache；窗口重置后又与全局表示混合。

## 单元与差分测试

1. 同一句单独、右填充、左填充在有效位置的 logits 按约定一致。
2. 一次性整段前向与逐 token 前向对应 logits 接近。
3. Packed 独立样本与分别前向一致，证明 block mask 与 position reset 正确。
4. 在最大长度前后各跑一个样例，检查 scale 切换连续性。
5. RoPE 验证 position 0 旋转不变、旋转保持范数。

## 可观测性

线上记录而非全文打印：模型/位置配置版本、请求有效长度、min/max position、padding_side、window offset 和是否触发缩放。出现质量问题时可复现同一位置序列。对编译模型，还要检查 position shape 是否被错误静态化。

面试回答应给出“可视化三元组 + full/incremental 差分 + 边界测试”的排障流程，而非只说检查数组下标。越界报错反而容易，静默错位才是生产中最危险的问题。
