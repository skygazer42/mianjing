# 19. 双向编码器与因果解码器的位置机制需求有何不同？

## 可见性不同

双向编码器中位置 \(i\) 通常可看左右两侧，位置关系需要区分“前方/后方”和距离；相对 bias 往往为正负方向设置不同 bucket。因果解码器只能看 \(j\le i\)，未来位置已由 mask 屏蔽，主要表示“向过去多远”。因此同一种 T5 bucket 或 ALiBi 构造在双向与因果模式下符号和类别数可能不同。

## 任务与汇聚

编码器常用于分类、匹配或 token 标注，CLS/全局 pooling 的绝对位置和 padding 一致性很重要；输入整段一次处理，通常不涉及逐 token 增量位置。解码器生成时每步追加 token，position_ids 必须与已有前缀长度连续，训练与增量推理的 QK 旋转/偏置需完全一致。

Causal mask 本身已经提供方向结构：第 \(i\) 位能看到 \(i+1\) 个前缀位置，不同位置可见集合不同。因此因果模型即使没有显式位置向量也不完全置换等变；但它仍难精确表达相对距离，位置机制依然重要。双向全 attention 若无位置则真正把序列当集合。

## 方案适配

可学习绝对、正弦、RoPE 都可用于两类模型，但训练习惯不同。RoPE 在 decoder-only LLM 常见，双向模型也能使用，只是正负相对方向都实际出现。ALiBi 的线性距离惩罚在因果模式自然；双向版本要明确定义 \(|i-j|\) 还是有符号距离，否则可能丢方向。

Encoder-decoder 还包含 cross-attention：query 位置来自目标序列，key/value 位置来自源序列，二者坐标系不必直接相减。通常分别在各自 self-attention 编码位置，再由内容做 cross-attention；若加入跨模态/跨序列相对位置，需要专门定义。

## 面试回答

应从 mask 可见性、距离符号、增量生成与 cross-attention 坐标系比较，而不是说“编码器用绝对、解码器用相对”。工程测试需分别验证双向反转、因果未来泄漏和逐步生成与整段前向 logits 一致。
