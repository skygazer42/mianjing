# 24. 长上下文继续训练时如何配置位置缩放和数据长度？

## 先定义目标

明确原训练上限 \(L_0\)、目标长度 \(L_1\)、采用的 RoPE/位置方案、显存预算和真正需要的依赖跨度。仅把 max_position_embeddings 改大不会赋予能力；需要让位置映射、训练数据、attention kernel 和评估长度共同覆盖目标。

## 配置与初始化

RoPE 模型可选线性插值、频率选择缩放或其他与 checkpoint 兼容的方案，并明确 original_max_position、factor、base theta 与 attention factor。可学习绝对表需扩行，可用插值初始化但新增位置仍要训练。不要同时在数据管线缩 position_ids、模型内部又启用 rope_scaling。

## 数据课程

长样本应包含真实长程依赖，而非把互不相关短文重复拼接。可从短到长做课程训练，逐步增加 4k、8k、16k 等比例以控制不稳定和成本；目标阶段仍混入短样本，保持局部能力。按 token budget 采样时注意少量超长样本会占据大部分计算，需报告“样本比例”和“token 比例”两套分布。

Packing 必须处理 block mask、position reset 与 label 边界。文档截取策略要让证据和目标跨越多种距离，避免答案总在开头或结尾形成位置捷径。

## 优化与验证

序列加长会降低可用 batch size，可能改变有效 batch token 数、梯度噪声和学习率适配；可用 gradient accumulation、activation checkpointing 与高效 attention，但要核对数值等价。监控 loss 随长度、位置分桶梯度、QK logit 和短上下文回归。

评估不仅是能跑到 \(L_1\)，还要看短程困惑度、长文检索、目标深度/距离、干扰项数量和端到端吞吐。扩长若只在合成 needle 通过而自然长文退化，仍不能发布。

面试回答可按“位置配置—长依赖数据—优化预算—分段评估”四步展开，并强调所有组件使用同一位置协议。
