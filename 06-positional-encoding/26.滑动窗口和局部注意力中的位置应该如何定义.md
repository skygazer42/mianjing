# 26. 滑动窗口和局部注意力中的位置应该如何定义？

## 两套坐标

滑动窗口里应区分全局位置和窗口内数组位置。全局位置表示 token 在原始文档/生成序列中的真实索引，窗口位置只是当前张量的 0…W-1。若每次滑窗都把 position_ids 重置，窗口内相对距离仍正确，但同一 token 在不同重叠窗口会有不同绝对表示；若使用全局递增位置，则跨窗口一致，却可能越过预训练长度。

## 与位置机制的关系

RoPE 的 QK score主要依赖相对差；窗口内 Q、K 都用同一全局 offset 时，共同平移理论上不改变相对 score，因此保留全局 position 通常自然。可学习绝对位置表受上限限制，可能不得不重置或使用层次位置。ALiBi 只需窗口内距离，局部 mask 已限制最远可见范围。

局部 attention 的 mask 常规定每个 query 只看最近 W 个 key。位置编码不会替代这个稀疏 mask；反过来，mask 只限制可见性，也不会告诉模型 token 距离。若叠加全局 token、跨块记忆或 dilation，需要为这些连接定义真实/压缩距离，不能把所有远端记忆都假装相邻。

## 具体例子

文档窗口 [1000,1511] 在张量内是 [0,511]。使用全局 RoPE 时 position_ids 为 1000…1511；下一重叠窗口 [1256,1767] 中同一 token 1300 仍用 1300。使用窗口重置则它分别是 300 与 44，合并两个窗口的向量时会产生位置不一致。若最终只在各窗口内独立分类，重置可能无害；若要跨窗融合，需显式处理。

## 工程与评估

记录 window_start，并由它生成 position，避免数据切片后丢失 offset。边界测试要覆盖首窗、重叠区、最后不足 W 的窗和超过原上限的位置；检查 local mask 是否 off-by-one（窗口宽 W 是含当前 token 还是 W 个历史 token）。

面试回答应先区分全局/局部坐标，再按是否跨窗复用表示选择；同时说明位置机制和局部稀疏计算解决的是不同问题。
