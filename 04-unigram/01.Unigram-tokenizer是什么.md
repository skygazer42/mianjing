# 01. Unigram tokenizer 是什么？

## 结论

Unigram tokenizer 是一种概率化子词模型：为词表中每个 token 学习独立概率，一段文本可以有多种合法切分，编码时通常用 Viterbi 选择 token 概率乘积最大的路径。训练往往从较大的候选词表开始，通过 EM 估计概率并逐轮删除贡献较小的 token，直到目标大小。

## 核心原理

设切分 \(z=(t_1,\ldots,t_k)\)，Unigram 假设给定切分时

\[
P(z)=\prod_{i=1}^{k}p(t_i),\qquad
\operatorname{cost}(z)=-\sum_i\log p(t_i).
\]

所有能覆盖原字符串的 token 构成有向无环 lattice。确定性编码找最小代价路径；训练时还需考虑一句话的多条路径，对隐变量切分求和，再估计每个 token 的期望计数。

## 具体例子

“unigram” 可有 [uni, gram]、[un, i, gram]、[u, n, i, gram] 等路径。若 \(p(uni)p(gram)\) 最大，Viterbi 输出第一条；这不是选择最长 token，也不是按 merge rank 合并。只要基础字符或 byte fallback 能覆盖输入，低频词仍能由小单元组成。

## 工程取舍与误区

概率独立是假设，不代表自然语言 token 真正互相独立；上下文语义由后续模型学习。Unigram 训练比 BPE 更复杂，需要候选初始化、前向后向、数值稳定和剪枝；优势是能表达分词不确定性，并自然支持 n-best 与采样。SentencePiece 是实现框架，可训练 Unigram 或 BPE，不能把两者当同义词。

## 面试回答要点

- 定义必须包含“token 概率、多路径、Viterbi、从大到小剪枝”。
- 与 BPE 的关键方向相反：不是从基础符号不断加 merge。
- 开放词表仍取决于 required chars/byte fallback。
- 概率切分可用于训练时 subword regularization。

## 延伸追问与复习

面试官常继续问：token 概率是否参与下游 Transformer 的预测？答案是否定的，Viterbi 只用它决定输入 ID 序列，模型随后使用自己的参数。还可比较一个最长 token 存在却未被选择的反例，说明 Unigram 优化的是全路径概率而非 token 数最少。工程验证应同时检查最佳路径分数、decode、未知字符和多路径采样分布；只观察切分“像不像词根”并不能判断模型质量。最终还要在固定词表与模型参数预算下，通过独立语料长度和小模型 loss 选择配置。
