# 13. Unigram 与 WordPiece 的概率和贪心差异是什么？

## 结论

Unigram 为最终词表项保留概率，用 Viterbi 比较完整切分路径；经典 WordPiece 推理不使用 token 概率，只从左到右选择当前位置最长的合法词表项。Unigram 还能对所有路径求和和采样，WordPiece 标准编码则是单一路径确定性规则。

## 推理对比

对字符串 x，Unigram 最小化 \(-\sum\log p(t)\)。WordPiece MaxMatch 每步最大化当前 token 长度，并用 ## 区分续接状态。最长前缀可能迫使后缀碎裂，Unigram 会权衡全局；WordPiece 某位置没有字符候选时经典行为为整词 [UNK]，Unigram 若 required chars 完整则仍有路径。

## 具体例子

abc 的 WordPiece vocab 含 ab、a、##bc、##c，会选择 [ab,##c]。Unigram 即使同时有 ab、a、bc、c，若 \(p(a)p(bc)>p(ab)p(c)\)，会选择 [a,bc]。WordPiece 的训练可能具有似然/关联评分思想，但推理时不带这些候选分数，这是容易混淆之处。

## 工程取舍与误区

Unigram 构 lattice 与 DP 的常数高于 Trie MaxMatch，不过片段通常较短。WordPiece 与 BERT checkpoint 高度绑定，不能为获得“全局最优”直接换成 Unigram；所谓最优也只是 tokenizer 自身概率，不保证下游语义最优。两者边界符号、normalization 与 special tokens 的差异可能大于算法差异。

## 面试回答要点

- 最终推理：概率全局路径对比无概率局部最长。
- WordPiece 训练有评分不代表推理使用 token 概率。
- 覆盖失败语义不同，但依赖具体基础 alphabet 配置。
- 迁移必须考虑模型 ID 兼容，而非只比较算法。

## 延伸追问与复习

可让候选人给出一个“最长首片段使后缀很差”的反例，并分别手算 WordPiece 与 Unigram 输出，这能验证是否真正理解局部与全局。性能上，WordPiece Trie 记录最远终止节点，Unigram Trie 枚举所有终止节点再交给 DP；前者边选择更少，后者保留概率选择空间。若 Unigram 只保留每个位置最长边再做 DP，就已经错误地退化了搜索空间。

比较未知输入时还要限定实现：经典 WordPiece 常整词 [UNK]，Unigram 若 required chars 完整则可字符退化；但配置 byte fallback 的现代变体会改变结论。算法名称不能替代具体覆盖设置。
