# 12. Unigram 与 BPE“从大到小”和“从小到大”有何本质差别？

## 结论

BPE 从基础 alphabet 出发，每轮增加一个可由历史 merge 构造的新 token；Unigram 先给出丰富候选，每轮删除对概率目标贡献较小的 token。方向差异带来不同推理表示：BPE 用有序 merge rank，Unigram 用最终 token 概率和全局路径搜索。

## 训练对比

BPE 评分通常是当前相邻 pair 频次，词表单调增长，早期选择会限制后续可达组合且不回溯。Unigram 候选一开始即可包含长子串，EM 让多条切分竞争概率，剪枝时评估删除后的替代 loss；一个长 token 即使不由某条 merge 历史逐步构造，也能直接成为 lattice 边。

## 具体例子

对 “tokenizer”，BPE 必须先学习 to、tok、token 等依赖规则才能出现 tokenizer；如果某个早期 pair 没被选，长 token 不可达。Unigram seed 中若已有 tokenizer，它从第一轮就与 [token, izer] 等路径竞争，最终根据概率与剪枝保留或删除。推理时后者可能选择多个短 token，即使最长项存在，因为全路径概率更高。

## 工程取舍与误区

BPE 训练简单、产物直观、编码常更快；Unigram 初始化和 EM 更重，却支持 n-best/采样。两者都可能以字符或 byte 兜底，也都受 normalization 和词表预算影响。不能把“删词”理解成仅按低频删除，也不能把 BPE vocab 当作无序最长匹配表。

## 面试回答要点

- 训练方向、评分目标、产物和推理算法四点同时回答。
- BPE 有 merge 可达性，Unigram 有候选 lattice。
- Unigram 的删除依据替代损失，非简单 bottom frequency。
- 最终好坏依赖语料和部署指标，不由方向先验决定。

## 延伸追问与复习

两者还可从“模型文件修改风险”比较：BPE 调整 merge 顺序会改变构造路径；Unigram 调整某个 piece score 即使 ID 不动，也可能改变多个字符串的 Viterbi 最优切分。因此两种产物都必须与 checkpoint 成对冻结。公平实验应统一 normalization、基础覆盖、词表大小和训练语料，再比较平均及 P99 token 长度、词表频次、编码吞吐与小模型 loss。只比较算法方向无法得出实际优劣。
