# 02. Unigram 为什么叫“一元语言模型”？

## 结论

“Unigram” 指切分路径的概率被建模为各 token 边缘概率的乘积，即当前 token 的分数不条件依赖前一个 token。它是一种用于分词的零上下文概率模型，不应与下游 Transformer 的完整语言建模能力混为一谈。

## 概率假设

对路径 \(z=(t_1,\ldots,t_k)\)，

\[
P(z)=\prod_i p(t_i).
\]

若是 bigram 分词模型，则会使用 \(p(t_i\mid t_{i-1})\)，状态和参数规模明显增大。Unigram 的独立假设让一条 token 边只需固定权重 \(-\log p(t)\)，Viterbi 和前向后向都可在字符串位置组成的 DAG 上高效运行。

## 具体例子

对 “therapist”，候选路径 [the, rap, ist] 与 [therapist] 的比较只看各自 token 概率乘积，不使用 “the 后面更常跟什么”这类顺序条件。这个目标可能选择看起来不符合词素的路径，但只要统计上能解释语料即可。token IDs 进入 Transformer 后，self-attention 仍会学习强上下文关系。

## 工程取舍与误区

一元假设简化训练和推理，也让 token 概率可跨位置复用；代价是无法直接用邻接偏好消除某些分词歧义。增加 n-gram 状态会提高计算、内存和稀疏性，未必能转化为更好的下游模型。不要把 tokenizer 的 \(p(t)\) 当成生成模型输出概率，两者的词表用途相关但参数完全不同。

## 面试回答要点

- “一元”是切分概率分解假设，不是模型只能理解单个词。
- 路径代价是 token 固定负对数概率之和。
- 独立假设使 lattice DP 简单可扩展。
- 下游神经网络仍负责上下文建模。

## 延伸追问与复习

若把 tokenizer 改成 bigram piece 模型，DP 状态不仅包含字符串位置，还需包含前一个 token，边数与参数规模显著增加，训练期望计数也更复杂。这未必值得，因为下游网络本来就会学习上下文。面试回答可用“切分器只决定如何读字符串，语言模型决定在上下文中说什么”概括分工。评估时也不要用 Unigram 自身的 sentence likelihood 宣称语义更好；它只衡量候选 pieces 对表面字符串的统计解释，最终价值仍看序列效率、覆盖和端到端任务。
