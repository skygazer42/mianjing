# 04. Viterbi 如何求 Unigram 最优切分？

## 结论

Viterbi 在字符串位置 DAG 上做动态规划：令 \(dp[j]\) 为覆盖前 j 个单位的最小负对数代价，枚举所有以 j 结尾的 token 边 \(i\to j\)，取 \(dp[i]-\log p(t)\) 最小者并记录回指。到终点后沿 backpointer 逆序恢复 token。

## 公式与伪代码

\[
dp[0]=0,\qquad
dp[j]=\min_{(i,j,t)}\{dp[i]-\log p(t)\}.
\]

~~~text
dp[0] = 0, 其余为 +inf
for i from 0 to n-1:
    for token t matching text at i, end=j:
        cand = dp[i] - log p(t)
        if cand < dp[j]:
            dp[j] = cand
            back[j] = (i, t)
从 n 沿 back 回溯
~~~

## 具体例子

“ab” 有 a、b、ab，概率分别 0.2、0.3、0.05。[a,b] 概率为 0.06，大于 [ab] 的 0.05，因此即使 ab 更长，Viterbi 仍选择 [a,b]。在 log 域比较为 \(-\log0.2-\log0.3 < -\log0.05\)，避免直接连乘下溢。

## 工程取舍与误区

复杂度取决于 lattice 边数 \(E\)，DP 是 \(O(E)\)，用 Trie 构边约与输入长度和可匹配前缀相关。并列总代价要定义稳定 tie-break，如更少 token、固定 token ID 顺序，否则跨平台结果可能变化。Viterbi 只找最大概率单路径，不等于训练时对所有路径求和；也不等于最长匹配。

## 面试回答要点

- 状态是字符位置，转移是一条 token 边。
- 用负 log 把概率乘积变成代价求和。
- backpointer 恢复路径，时间与 lattice 边数线性相关。
- 与 forward algorithm、MaxMatch 的目标要区分。

## 延伸追问与复习

复杂度分析应写成 \(O(E)\) 而不是简单说 \(O(n)\)，因为每个位置可能有多条候选边。实现可用 Trie 从起点同时枚举候选，避免检查所有子串；使用 log probability 可防止连乘下溢。单测至少包含：最长 token 不是最优、多个等价路径的稳定 tie-break、未知字符导致终点不可达、空串以及 Unicode 多字节输入。还要把恢复后的 token 重新拼接，确认完整覆盖且没有重叠或遗漏。若换成 n-best，不能只保存一个 backpointer，而需为每个位置维护多个候选或使用 k-shortest path。

工程实现还要禁止零长度 token，否则 lattice 会出现自环，位置 DP 不再是 DAG。若 score 是负对数代价而非 log probability，转移时应直接相加，不能再次取负号；加载模型时必须查清字段语义。对于同分路径，应固定按 token 数、ID 或字典序裁决，并在各语言绑定中保持一致，避免相同模型跨平台产生不同 IDs。
