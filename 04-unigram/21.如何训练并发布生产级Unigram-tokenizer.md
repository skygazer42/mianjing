# 21. 如何训练并发布生产级 Unigram tokenizer？

## 结论

生产流程包括目标定义、语料治理、冻结 normalization、构建 seed vocab、EM 与迭代剪枝、多维离线评估、小模型联合实验以及制品化发布。必须把 piece scores、normalizer、特殊 token、byte fallback 和 decoder 与模型 checkpoint 成对版本化。

## 训练步骤

先按语言领域去重和采样，确定 character coverage、required chars、user-defined symbols 与是否 byte fallback。选择目标 vocab、最大 piece 长度和 seed size，生成大候选；在 lattice 上多轮 forward-backward 更新概率，按删除 loss 批量剪枝，接近目标后细化。固定随机种子与 tie-break，保存数据/配置指纹。

## 验证与发布

独立集报告 UNK/fallback、tokens per byte/character、P95/P99 长度、词表频率、round-trip、offset 和编码吞吐；对 n-best/采样测试概率和随机性。用固定总参数的小模型比较验证 loss 与关键下游任务。发布模型文件、转换后 tokenizer 配置、special IDs、hash 和 golden corpus，跨语言实现做精确 ID 对拍。

## 工程取舍与误区

只保存 .vocab 文本不够，其中 score 展示精度也可能不足以重建原模型；应保留二进制/完整 JSON。tokenizer 训练集不必机械等于 LLM 语料，平衡采样能更好分配词表。上线后改变 score 即使词表和 ID 不变，也可能改变 Viterbi 路径，因此属于破坏性版本更新。

## 面试回答要点

- 数据、候选、EM、剪枝、评测、制品六阶段完整回答。
- 覆盖底座和 special IDs 在训练前确定。
- tokenizer score/normalizer 与 vocab 一样是模型 ABI。
- 发布以 golden IDs、hash 和模型配对校验收尾。

## 延伸追问与复习

上线前还应做故障演练：加载错 tokenizer 时服务能否因 hash 或 vocab size 不匹配立即失败；转换后的移动端实现是否对 byte fallback、dummy prefix 和 user-defined symbols 一致；随机训练能否从 checkpoint 恢复相同样本切分。灰度比较新旧版本时，先在影子流量统计 token 成本和尾部覆盖，再用各自适配的模型做质量 A/B，不能让同一个 checkpoint 直接交换 tokenizer 得出结论。

训练数据与产物还应有可追溯版本，包含抽样权重、去重规则、许可证和敏感信息审计。这样发现某个不当 piece 时，才能定位来源并决定是重训还是屏蔽，而不是只修改线上文件造成模型错位。
