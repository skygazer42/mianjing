# 30. 什么场景适合 Unigram，以及关键参数怎么调？

## 结论

Unigram 适合希望概率化全局切分、n-best 或 subword regularization，以及需要 SentencePiece 原句训练生态的场景。若更看重简单 merge 制品和极成熟 LLM byte-BPE 工具链，可选 BPE；若必须兼容 BERT checkpoint，则保留 WordPiece。关键参数应围绕覆盖、候选规模、目标词表和采样强度调优。

## 参数地图

character_coverage/required_chars 决定基础覆盖；byte_fallback 决定开放输入兜底；seed_size、max_piece_length、min_frequency 控制初始 lattice 规模；vocab_size 决定序列与 embedding 权衡；shrinking factor/剪枝比例控制训练速度和稳定；EM 轮数与收敛阈值控制概率估计；alpha、nbest_size 只影响采样增强。

## 场景选择

低资源机器翻译或形态丰富语言可从采样多切分获益；多语言原句训练可利用 ▁ 边界与统一管线。开放聊天生成若启用 byte fallback 和保真 normalizer，也可使用 Unigram。极低延迟场景需测 lattice DP 与具体实现，不能凭算法名称断言比 Trie MaxMatch 慢到不可用。

## 调参与误区

先锁定 normalization 和语料采样，再做 vocab/coverage 候选；否则超参曲线没有可比性。用独立集绘制 token 长度、UNK/fallback、held-out loss、分语言 P99 和吞吐，再以固定总参数的小模型验证。不要把 SentencePiece 默认值当跨语言最优，也不要只优化 Unigram 自身似然。

## 面试回答要点

- 选择优势是全局概率路径与天然采样。
- 覆盖、seed、vocab、剪枝、sampling 五组参数各司其职。
- 兼容旧 checkpoint 的约束优先于算法偏好。
- 最终决策由端到端质量、成本、可逆性和工程生态共同给出。

## 延伸追问与复习

调参顺序应避免相互污染：先冻结数据与 normalization，确定 required/byte 覆盖，再扫描 seed 与最大长度保证候选召回，随后选择目标 vocab 和剪枝稳定性，最后才调训练采样 alpha。每一步保存独立集的长度、likelihood、路径熵、吞吐和分语言尾部。若已有 checkpoint，兼容性直接否决大多数 tokenizer 替换；若从零训练，才可把 BPE、WordPiece 和 Unigram 放在相同预算下公平比较。
