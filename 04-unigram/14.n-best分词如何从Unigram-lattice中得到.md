# 14. N-best 分词如何从 Unigram lattice 中得到？

## 结论

N-best 要在同一个 lattice 中返回代价最小的前 N 条完整路径，而不是反复删除上次结果。可使用 k-shortest paths、每个位置保留 top-N 部分路径，或 A*/后向启发式枚举；路径分数仍是 token 负 log 概率之和。

## 算法思路

简单 DP 为每个位置维护按代价排序的最多 N 个状态，每条入边与前驱的 N 个状态组合，再截取 top-N。更节省内存的实现先算最佳后向代价，随后用优先队列按“当前代价+可采纳启发式”枚举完整路径。必须对完全相同的 token 序列去重，并定义并列分数顺序。

## 具体例子

“abc” 的候选路径有 [abc]、[a,bc]、[ab,c]、[a,b,c]。Viterbi 只返回第一名；N=3 时返回前三条及各自分数或归一化概率。用户可以观察边界不确定性，或在下游训练中从这些候选按分布选择，而不总锁定单一切分。

## 工程取舍与误区

路径总数可能指数级，N 很大时内存和时间迅速增长；应设置上限和概率阈值。返回路径的原始乘积并不一定在截断集合内归一化，API 要说明 score 语义。N-best 与 sampling 不同：前者确定列出高分路径，后者按某个温度化分布随机抽样。不要通过对 token 逐个做局部 top-N 代替全路径搜索。

## 面试回答要点

- lattice 上的 k-shortest paths 是标准抽象。
- 每条路径仍按全局总代价排序。
- N-best、Viterbi 和随机采样三者目的不同。
- 控制 N、去重和分数语义是工程接口重点。

## 延伸追问与复习

N-best 的接口最好同时返回 token IDs、未归一化 log score 和相对概率，并明确概率是对全部路径还是仅 top-N 重新归一。若用于数据增强，简单在 top-N 中均匀抽样会高估低概率路径；更合理的是按温度化分数采样。测试可用短字符串穷举所有路径，排序后与算法结果精确对拍，并覆盖同分路径、重复 token 表面和 N 大于总路径数。长输入还需设置 N 与内存上限，防止用户请求指数级枚举。
