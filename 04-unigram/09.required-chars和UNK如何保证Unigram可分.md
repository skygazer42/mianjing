# 09. Required chars 和 UNK 如何保证 Unigram 可分？

## 结论

Required chars 是剪枝时强制保留的基础字符集合，用来确保规范化文本至少能按字符形成一条路径；UNK 则为仍未覆盖的输入提供失败兜底。若加入 byte fallback，任意 UTF-8 输入可由 bytes 表示，能进一步减少信息丢失，但会改变词表和长度成本。

## 覆盖机制

从训练语料按 character_coverage 选择基础字符：高频字符直接进入 required 集，低频尾部可能由 UNK 表示。覆盖率设为 1.0 适合字符集可控场景，极大 Unicode 空间则可能使词表膨胀。剪枝阶段 required pieces 不参与删除，即使其估计概率很低；否则一条包含该字符的句子会失去完整 lattice 路径。

## 具体例子

日文常用字符集大，通常需要高 character coverage；若只覆盖 99%，罕见人名汉字可能成为 UNK。byte fallback 可把该汉字的 UTF-8 字节输出为多个保留 byte token，保留信息但增加序列。注意 byte fallback 是 SentencePiece 等实现的可选能力，不是概率模型数学定义的一部分。

## 工程取舍与误区

UNK 率低可能掩盖关键实体信息丢失，应按脚本和业务字段分析。required 集过大挤占多字符 piece 的目标词表预算，过小则未知率高。Normalization 先折叠字符可提高覆盖，却可能不可逆。训练与推理 Unicode 版本不一致也会引入新 code point，必须用真实线上尾部样本评估。

## 面试回答要点

- required chars 保证训练/目标字符可走字符路径。
- UNK 是信息丢失兜底，byte fallback 是可逆性更强的扩展。
- character coverage 在词表容量与未知字符间权衡。
- required token 不能在概率剪枝中被删除。

## 延伸追问与复习

覆盖测试应遍历目标样本的规范化 code point，逐个确认至少有字符 piece、byte fallback 或明确 UNK 路径，并按语言输出缺失榜单。若 byte fallback 开启，还需确认所有 256 个 byte token 都保留且 decoder 能在多 token 拼接后严格恢复 UTF-8。character coverage 是训练数据分位数，不代表未来线上绝不会出现新字符；因此开放系统即使选很高覆盖率，也应设置可观测的兜底与 token 膨胀告警。
