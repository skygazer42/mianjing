# 22. 如何实现一个最小可用 Unigram Viterbi 分词器？

## 结论

最小实现需要 token→log probability、覆盖全部输入的基础 pieces、从每个位置查候选的逻辑，以及 dp/backpointer。先写枚举子串的参考版确保正确，再换 Trie；输入无法到达终点时返回明确 UNK/fallback，而不是静默丢字符。

## 参考算法

令 dp[0]=0，其余为无穷。对每个可达起点 i，枚举词表中与 text[i:j] 相等的 token，候选代价为 dp[i]-logp[token]；若更小则更新 dp[j] 与 back[j]=(i,token)。结束时从 n 回溯，若 dp[n] 仍无穷说明基础覆盖配置错误。并列时可按更少 pieces、较小 token ID 等固定规则选择。

## 测试设计

手工词表 {a,b,ab} 可验证“更长不一定更优”；加入多个等价路径验证 tie-break；加入 Unicode、空格元符号、空串和未知字符。将 Viterbi 分数与穷举所有短字符串路径的最小值对比，做 property-based test。再验证 IDs 和 decode，而不只看 piece 表面值。

## 工程取舍与误区

概率应在 log 域，不要直接连乘。若 score 文件已经存的是 logp，就不能再次取 log；具体格式需确认。Python substring 枚举适合教学，大词表应用 Trie 限制最大长度。normalization、special token 与 offsets 应保持模块分层，避免 DP 正确却完整 tokenizer 不兼容。

## 面试回答要点

- 状态、转移、代价、回指四要素齐全。
- 基础覆盖保证终点可达。
- log 域与确定 tie-break 保证稳定。
- 先穷举对拍参考版，再做 Trie 和批量优化。

## 延伸追问与复习

最小实现可增加一个 brute_force 函数，对长度很短的文本枚举所有完整 token 组合并计算总代价，用它验证 DP 的最优值和回溯路径。之后再测试概率缩放、同分 tie-break 与不可达状态。生产优化时 Trie 只负责列出所有匹配终止节点，不能像 WordPiece 那样只保留最长节点；否则会丢掉概率更高的短路径。所有 token 必须消费正长度输入，避免空 token 形成图中的自环。

模型加载还需验证每个概率有限、ID 唯一且基础覆盖成立；输入为空时应返回空普通 token，再由外层决定是否添加 BOS/EOS。
