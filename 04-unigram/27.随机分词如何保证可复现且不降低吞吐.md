# 27. 随机分词如何保证可复现且不降低吞吐？

## 结论

为每个样本从稳定的全局种子、epoch 和样本 ID 派生独立随机流，避免依赖 worker 调度顺序；推理关闭采样。性能上应直接在 lattice 做后向采样、缓存可复用结构并控制 nbest/最大 piece 长度，而不是枚举所有路径。

## 随机性设计

可构造 seed=hash(run_seed, epoch, sample_id)，这样 worker 数或 batch 顺序变化仍得到同一切分；同一样本跨 epoch 因 epoch 不同获得增强多样性。分布式数据重采样时 sample_id 必须稳定。记录 alpha、nbest_size、tokenizer hash 和 RNG 算法，才能复现实验。

## 高效采样

先用温度化 log scores 做 forward 或 backward DP，随后从当前位置按“边概率×剩余路径质量”逐步抽样；复杂度与 lattice 边数相关，无需生成指数多路径。对重复文本可缓存候选 lattice，但不能缓存最终随机路径；缓存键含 normalized text 和 tokenizer 版本。

## 工程取舍与误区

所有 worker 使用同一 seed 会产生相同随机序列，降低多样性；完全依赖进程 RNG 又使恢复 checkpoint 后不可复现。alpha 过小和 nbest 无限会增加碎片与计算。动态 token 长度会影响 batch packing，应按采样后 token 数组 batch。线上打开采样会破坏响应一致与 KV/prompt cache 命中。

## 面试回答要点

- 随机种子应按样本派生，而非按执行顺序消费。
- lattice 后向采样避免枚举全部路径。
- 缓存结构不缓存结果，推理默认 Viterbi。
- 复现元数据和实际 token 预算都要纳入训练系统。

## 延伸追问与复习

断点恢复时不仅保存模型与优化器，还应保存 epoch/样本游标和种子派生版本；否则相同 sample_id 可能在恢复后使用不同随机路径。若数据增强希望每个 epoch 变化，种子必须包含 epoch，若希望重跑完全一致则 run_seed 固定。性能分析应把 normalization、lattice 构建、DP 和 RNG 分开计时，并检查不同 worker 数不会改变样本的切分分布或导致所有 worker 使用同一随机序列。
