# 08. Unigram 如何评估删除一个 token 的损失？

## 结论

剪枝不能只删除当前概率最低的 token，因为低概率项可能是某些字符串的唯一覆盖或能显著改善似然。训练器会估计移除候选后，受影响语料改用替代切分所增加的负对数似然，优先删除损失小且非必需的 token，再重新运行 EM。

## 核心思路

对候选 t，找到使用它的路径或出现位置；临时禁止 t 后，用其组成字符或其他候选计算替代路径成本。删除代价可近似为受影响位置的最优/期望 loss 增量。required chars、special tokens、byte fallback 等不可删除。每轮通常批量剪去一定比例，而非一次只删一个，以控制训练轮数。

## 具体例子

token “xyz” 概率很低，但若 x、y、z 都存在，删除后只把 [xyz] 改成 [x,y,z]，语料 loss 增加很小，适合剪掉。罕见字符 “𠀀” 的概率也低，却若是唯一覆盖项，删除会让相关句子无任何路径，必须保留。另一个中频词根可能让成千上万词获得更低成本，删除损失远高于其单独频次所示。

## 工程取舍与误区

精确为每个候选重跑全语料代价过高，实际会用局部或批量近似，因此 pruning 策略是实现差异来源。批量比例过大会让多个互为替代的 token 同时删除，质量骤降；每轮剪少则训练慢。剪枝后概率要重估，不能沿用旧分布。仅按频率 bottom-k 删除不是 Unigram 的完整思想。

## 面试回答要点

- 核心是“删除后的替代切分损失”，不只是 token 自身概率。
- required 基础项永不删除。
- 批量近似换效率，但需在每轮后重新 EM。
- 剪枝比例、候选替代关系与覆盖是常见追问。

## 延伸追问与复习

可进一步构造两个互为替代的长 token：单独删除任意一个损失很小，但若批量同时删掉，语料只能退化成许多字符，真实损失很大。这说明批量剪枝的独立近似会产生交互误差，剪枝比例越大风险越高。工程上每轮后应重建 lattice、重跑 EM 并检查覆盖，接近目标大小时降低删除比例。删除清单还可保留 estimated loss，便于分析最终词表为什么放弃某个肉眼高频候选。
