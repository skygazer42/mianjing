# 16. Unigram tokenizer 和神经语言模型有什么区别？

## 结论

Unigram tokenizer 的概率只用于比较字符串的切分方式，参数通常是每个 token 一个标量；神经语言模型估计上下文条件概率 \(P(t_i\mid t_{<i})\)，参数包含 embedding 与多层网络，用于预测和生成。二者共享 token 词表，却优化不同数据、目标和能力。

## 模型对比

tokenizer 路径模型为 \(P(z)=\prod p(t)\)，不读左右语境，Viterbi 对固定字符串找低成本覆盖。自回归模型则分解

\[
P(t_1,\ldots,t_n)=\prod_i P_\theta(t_i\mid t_{<i}),
\]

同一 token 在不同上下文概率不同。Unigram score 在 tokenizer 训练结束后冻结，编码所有请求；神经模型 logits 每一步随 hidden state 改变。

## 具体例子

“bank” 是否指河岸不影响 Unigram 将它切成 [bank] 还是 [ba,nk]，只看表面字符串和 piece 概率。Transformer 会根据 “river bank” 或 “central bank” 学到不同上下文表示。tokenizer 即使把整个 bank 设为高概率 token，也没有学到这两种语义。

## 工程取舍与误区

不要用 tokenizer piece score 作为模型置信度，也不能把 Unigram 的 perplexity 与 LLM perplexity直接比较，归一化单位和目标不同。tokenizer 选择会改变神经模型序列和 softmax 空间，因此间接影响训练，但不替代语义建模。改 tokenizer 概率还可能改变编码，即使 ID 不变，也会使旧模型输入分布漂移。

## 面试回答要点

- tokenizer 是无上下文切分模型，神经 LM 是上下文预测模型。
- 前者每 token 标量，后者大量条件参数。
- 词表是接口耦合点，目标函数和“概率”语义不同。
- tokenizer 分数不能当生成概率或语义置信度。

## 延伸追问与复习

两者仍有紧密接口：tokenizer 决定 vocab size、ID 和序列长度，神经模型的输入 embedding 与输出 logits 都据此定形。改变 Unigram score 会在相同字符串上改变 ID 序列，从而让旧模型面对训练时未见的组合；因此 score 也是兼容制品。面试若问“能否联合训练 tokenizer 与模型”，可以说研究上可以设计可微或交替优化，但标准 Unigram 通常先独立训练并冻结，工程上更稳定。
