# 24. Unigram 解码可逆性和 offset 有哪些陷阱？

## 结论

Unigram pieces 拼接通常能还原模型实际看到的规范化字符串，但端到端能否恢复原文取决于 normalization、空格元符号、UNK/byte fallback 和特殊 token 策略。offset 必须从规范化过程携带 alignment，不能按 piece 表面长度倒推。

## 解码链路

ID 查 piece，按顺序拼接；SentencePiece 风格将 ▁ 还原为空格，并处理 dummy prefix；byte pieces 先组回 bytes 再 UTF-8 decode；控制符按策略保留或跳过。若训练前 lowercase、NFKC 或折叠连续空格，原始差异已经丢失，decoder 只能得到规范化形式。

## 具体例子

原文 “ Café  ” 可能规范化成 “▁Café” 或 “▁cafe”，输出 pieces 带 ▁。去重音/小写后无法恢复 C、é 和双空格。若罕见字符变成 UNK，多个原文映射同一符号；若 byte fallback 则可保留其 UTF-8 bytes。user_defined_symbol 内含 ▁ 时不能用全局字符串替换粗暴解码。

## 工程取舍与误区

offset 单位需明确 UTF-8 byte、code point 或 UTF-16 unit。一个 normalization 输出字符可能对应多个原字符，或反之，简单 start/end 只能给包围区间。fast tokenizer 转换可能与原生 SentencePiece 在 dummy prefix、byte fallback offsets 上有差异，需 golden tests。decode 相同也不代表 ID 相同。

## 面试回答要点

- 分清 piece 可拼接与完整管线可逆。
- 信息损失多来自 normalizer 和 UNK。
- ▁/byte fallback/special token 各有独立 decoder 语义。
- 对齐必须在前处理时传播，并明确索引单位。

## 延伸追问与复习

可逆性测试应分三档：IDs 解为模型内部 piece 字符串、还原规范化文本、还原原始文本。只有最后一档要求 normalizer 也可逆。offset 测试则用预组合/组合重音、emoji、CJK、连续空白和 byte fallback，明确每个 token 对应的原文区间。若一个规范化字符来自多个原字符，多个 token offset 可能重叠；消费方不能假设跨度严格首尾相接。特殊 token 的 (0,0) 或空跨度也应在接口文档固定。

流式解码 byte pieces 时还要缓存不完整的 UTF-8 尾序列，不能逐 token replacement decode；否则一个合法汉字跨多个 token 会显示成多个替换字符。展示层与内部增量状态应分离。
