# 多 Agent 如何共享状态而不互相污染？

## 结论先行

多 Agent 不应共享可随意改写的提示词文本，而应共享带 schema、所有者、版本、可见范围和生命周期的黑板/事件流。把事实、推测、计划、工具结果和审批票据分开存储；写入使用 append-only 事件或 compare-and-swap，读取使用快照版本。Agent 之间传递的是经过验证的 artifact ID 和结构化摘要，不是无限上下文。敏感字段按最小权限裁剪。

## 真实案例

旅行规划、预算审核和合规 Agent 共同处理一张出差申请。Notebook 通过 6 条黑板事件比较最后写入覆盖与带 owner/version 的 append-only 黑板。

## 工程取舍与常见坑

共享状态越多，协调成本和隐私面越大；分离太彻底又会重复查询。不要把模型推测写成权威事实，也不要让一个 Agent 覆盖另一个 Agent 的审批证据。生产需加租户隔离、审计、TTL 和 artifact hash。

## 延伸追问

“什么时候不该用多 Agent？”任务工具少、目标稳定、没有独立专长或评测证明收益时，单 Agent/Workflow 更简单可靠。
