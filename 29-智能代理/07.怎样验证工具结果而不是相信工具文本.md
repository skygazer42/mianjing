# 怎样验证工具结果而不是相信工具文本？

## 结论先行

工具返回“成功”不是事实；Agent 必须依据权威状态、版本、请求关联 ID 和后置条件验证结果。对写操作至少验证：响应 schema、状态码、资源版本变化、目标字段是否匹配、事件是否落账；对读操作验证数据新鲜度与权限范围。失败时区分未知结果、确定失败与可安全重试，不能因为模型看见一句成功文本就宣称完成。

## 真实案例

订单取消 API 可能超时，但后端已经取消；也可能返回旧缓存“已取消”。Notebook 使用 6 条取消事件比较相信文本 baseline 与“请求 ID + 权威订单状态 + 版本号”验证，演示超时后的安全回读。

## 工程取舍与常见坑

把工具响应当最终答案会发生幻觉式完成；只重试会重复扣费。后置验证需要可查询的权威状态和关联 ID，最终一致系统还要轮询窗口、状态机和人工升级路径。

## 延伸追问

“如果读不到权威状态？”把结果标记为 pending/unknown，而非 success；保留任务和幂等键，等待异步回调或人工处理。
