# 熔断与降级怎样保护 Agent 系统？

## 结论先行

熔断器把下游连续失败转换为本地、快速、可观测的拒绝：closed 正常放行，超过窗口阈值进入 open，冷却后以少量 half-open 探测恢复。降级不是伪造成功，而是按业务选择缓存只读结果、排队、草稿、人工升级或明确失败。熔断指标要按工具、租户、地域和错误类型分桶，避免一个客户的错误封住所有客户。

## 真实案例

物流查询服务连续 5xx 时，客服 Agent 若持续调用会耗尽线程并拖慢退款。Notebook 以 6 个请求的响应流比较直接调用 baseline 与手写 closed/open/half-open 状态机，展示缓存降级和探测恢复。

## 工程取舍与常见坑

把所有失败计入同一计数会让 4xx 误触发熔断；open 状态若没有冷却探测会永久不可用。缓存降级必须标注时间与范围，写操作通常只能排队或要求用户稍后重试。

## 延伸追问

“熔断和重试先后怎样放？”先检查熔断，再在 closed/half-open 中执行有限重试；每次失败都应反馈给熔断器，避免重试绕过保护。
