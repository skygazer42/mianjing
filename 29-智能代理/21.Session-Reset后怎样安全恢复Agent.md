# Session Reset 后怎样安全恢复 Agent？

## 结论先行

Session reset 不是把旧对话全文再塞回 prompt。恢复时从持久化 checkpoint 读取任务 ID、已验证 artifact、权威状态版本、未完成节点、预算和权限票据；重新建立最小 context，再对可能有副作用的节点做权威回读。绝不能把模型曾说“已完成”当 checkpoint，也不能以重放文本替代幂等键。重启后的 Agent 应能解释哪些事实已验证、哪些未知、下一步是否安全执行。

## 真实案例

采购助手在审批后进程重启。Notebook 以 6 条 checkpoint 事件比较“恢复整个聊天记录”和“恢复结构化状态+回读采购单”的差异，特别展示写操作结果未知时的 pending。

## 工程取舍与常见坑

保存过多原始上下文会泄露数据并消耗 token；保存过少又丢失因果证据。checkpoint 要版本化、加 ACL 与 TTL，artifact 用 ID/hash 引用。session reset 与 event replay 不同：前者重新建立运行上下文并验证可继续性，后者用于复现历史。

## 延伸追问

“重启时工具调用正超时怎么办？”保持 unknown，使用同一幂等键读权威状态；未经确认不得重发写操作。
