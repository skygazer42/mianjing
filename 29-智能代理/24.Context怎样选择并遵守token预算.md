# Context 怎样选择并遵守 token 预算？

## 结论先行

context 选择是带预算的证据排序，不是简单 truncate 或总结。先保留不可变的系统策略、当前目标、权限和关键 artifact；再按与当前子任务的相关性、时效、权威性、风险和 token 成本选择证据。每个片段记录来源、更新时间和 token 估算；超过预算时宁可舍弃低价值记忆，也不能裁掉安全策略或把过期摘要当事实。

## 真实案例

客服 Agent 需要在 80 token 预算内处理退款，候选包括订单状态、政策、历史聊天、旧摘要、工具 schema 和无关商品文案。Notebook 比较按时间截断与价值/成本选择，输出每个片段的分数和保留结果。

## 工程取舍与常见坑

相关性模型可能偏爱相似措辞却忽略权威状态；只按 recency 会丢掉稳定规则。必须给不可省略项保留配额，缓存摘要也应带时间与来源。这里的选择器不同于普通 compaction：它为一个具体动作选择可验证证据并显式受预算约束。

## 延伸追问

“token 估算不准怎么办？”使用真实 tokenizer 预估并保留安全余量；超限时先移除低优先级片段，绝不在运行时静默丢策略。
