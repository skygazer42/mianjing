# 为什么 Agent 必须权威状态回读？

## 结论先行

Agent 的内部记忆、工具文本和缓存都可能过时或错误；在提交高风险动作、宣称完成、重试超时请求、计划依赖外部事实时，必须从拥有该事实的权威系统回读。回读需要资源 ID、版本/更新时间、读权限和一致性语义；读到旧版本时要标记 stale，而不是无条件覆盖工作记忆。权威回读是事实层，模型摘要属于推理层，二者不可混写。

## 真实案例

支付助手先读订单余额、生成退款计划，随后支付系统发生人工退款。Notebook 用 6 个读写事件比较使用旧记忆提交与提交前回读版本的做法。

## 工程取舍与常见坑

每步都强读会增加延迟和成本，完全不读会制造陈旧写。按风险、TTL、资源易变性和副作用分层；对写操作通常需要 read-after-write 验证。缓存必须保存来源与时间。

## 延伸追问

“回读到的也是最终一致旧值怎么办？”使用版本、读一致性级别、轮询窗口和 pending 状态；不要用模型补全缺失事实。
