# 长程 Agent Harness 怎样隔离与恢复？

## 结论先行

长程 Harness 负责把 Agent loop 放进可恢复、可隔离的执行环境：每个任务有 fixture、工作目录/资源命名空间、时间预算、外部依赖替身、checkpoint 与清理策略。测试一次长程任务不是让它跑更久，而是验证 session reset、artifact handoff、超时、晚到结果、状态恢复和清理后不会污染下一任务。Harness 只提供控制面，不替代权限、沙箱和工具服务的业务校验。

## 真实案例

代码修复 Agent 在两个租户 fixture 中创建草稿、超时并恢复。Notebook 用 6 个任务事件比较共用全局状态和隔离 fixture，显示任务 A 的临时文件不会进入任务 B。

## 工程取舍与常见坑

共享 fixture 快但会制造串扰；完全真实外部服务成本高且不稳定。应使用可复放 fake、资源配额、确定性时钟、超时取消与 artifact 清理；生产执行仍需容器/microVM 和网络策略。

## 延伸追问

“如何测晚到结果？”让工具结果带 task ID、attempt 和 checkpoint version；恢复后不接受旧 attempt 写入。
