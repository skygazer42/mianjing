# Agent 间怎样用 Artifact Handoff 交接？

## 结论先行

交接的单位应是可验证 artifact，不是一段自由文本总结。artifact 至少包含类型、schema 版本、内容 hash、创建者、来源工具、权限范围、有效期、权威状态版本和验收状态；接收者先校验 hash、schema、ACL 和输入版本，再决定能否消费。交接把长上下文压缩为稳定引用，也把责任边界从“谁说过”变成“谁产出了可核验对象”。

## 真实案例

研究 Agent 将供应商报价表交给采购 Agent。Notebook 用 6 个 artifact 事件比较只传摘要的 baseline 与 hash、版本、租户校验的 handoff，展示报价被篡改和过期后拒绝。

## 工程取舍与常见坑

hash 证明字节未变，不证明内容正确；仍需来源与验收状态。不要在 artifact 中塞隐私原文，改用最小字段和权限代理。交接不是共享全局可写内存，接收者只能消费已发布版本。

## 延伸追问

“schema 升级怎么办？”同时支持兼容读取或显式转换，转换后生成新 hash，不能悄悄按旧字段解释新对象。
