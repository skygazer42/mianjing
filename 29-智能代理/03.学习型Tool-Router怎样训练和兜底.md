# 学习型 Tool Router 怎样训练和兜底？

## 结论先行

Router 的任务是把请求路由到工具簇、具体工具或 no-tool，并在低置信度时回退到检索、追问或人工队列。训练标签应来自成功完成的、版本化的调用轨迹，而非只复制模型历史选择；评估除了 top-k 召回，还必须有参数可填率、执行成功率、错误副作用和成本。上线采用 allowlist、置信度阈值、影子流量和可回滚模型版本。Router 永远没有权限绕过 schema 与授权门禁。

## 真实案例

售后助手需要在物流查询、退款查询、地址变更、无工具回答之间选择。Notebook 用 6 条带真实字段的脱敏工单，手写词项权重路由器，比较“第一个匹配工具”的 baseline 与带 no-tool、置信度和兜底的 Router。

## 工程取舍与常见坑

类别不平衡会让 no-tool 看似准确却漏掉关键写操作；工具版本变化会让旧标签失效。不能把工具名当标签泄漏给文本特征，也不能只报 offline accuracy。应按租户、权限、工具版本分桶回放。

## 延伸追问

“何时训练 Router，何时只做检索？”工具少且稳定时规则更透明；目录大、描述相似且轨迹足够时才训练。无论哪种都需约束候选集合。
