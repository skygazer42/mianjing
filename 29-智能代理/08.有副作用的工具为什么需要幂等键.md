# 有副作用的工具为什么需要幂等键？

## 结论先行

网络超时不等于请求未生效；对扣款、下单、退款、发邮件等有副作用动作，客户端必须携带稳定幂等键，服务端把键、请求摘要和最终结果持久化。相同键与相同摘要返回同一结果；相同键不同摘要必须拒绝；键有明确作用域和过期策略。幂等保证的是重复交付不重复副作用，不保证两个不同键的业务冲突。

## 真实案例

退款 Agent 在第一次调用超时时再次提交同一退款。Notebook 以 6 个退款事件模拟请求账本，比较不带幂等键的 baseline 和键+摘要的去重，展示“键复用但金额变更”必须拒绝。

## 工程取舍与常见坑

仅在 Agent 内存去重，进程重启就失效；只存 key 不存请求摘要会把不同订单错误合并。服务端 ledger 要原子写入，保留足够 TTL，并将用户、租户、动作类型纳入作用域。

## 延伸追问

“幂等键能解决库存超卖吗？”不能。它解决同一逻辑请求重复投递；库存并发仍需要锁、条件更新或业务 Saga。
