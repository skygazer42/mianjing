# Trace 怎样做分层 Grading？

## 结论先行

一个总分掩盖了 Agent 如何失败。分层 grader 至少独立检查：输入/权限、计划结构、工具参数、工具结果验证、最终回答和副作用；每层用可重放 fixture 与权威状态给出 pass/fail/unknown 和证据。总分只用于概览，发布门禁应对安全层设置硬失败。trace grading 不等于记录 trace：前者把事件与因果期望进行判定，并可定位失败层。

## 真实案例

退款 Agent 的 6 条 trace 分别出现无授权调用、计划缺依赖、金额参数错、未回读、回答虚假成功和完整成功。Notebook 进行分层判定并输出层级分数矩阵。

## 工程取舍与常见坑

LLM-as-judge 可辅助解释，但安全和最终状态必须有确定性 grader。只看最终文字会漏掉非法工具调用；只看工具调用又无法判定是否真正解决用户目标。grader 自身要版本化、固定 fixture、统计一致性。

## 延伸追问

“各层权重如何设？”安全/权限为硬门槛，其他层按任务风险加权；不要用高质量文案抵消未授权副作用。
