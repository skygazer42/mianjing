# 为什么参数校验必须在模型之后？

## 结论先行

模型输出只是未可信输入；参数校验必须在模型之后、工具之前、服务端执行。校验分语法、类型、范围、跨字段、权限、权威状态和副作用前置条件六层。错误必须结构化返回给 Agent，允许它在有限次数内修正；绝不能把解析失败自动转换成默认写操作。写操作以服务端实际校验结果为准，客户端或 prompt 中的检查都不能代替。

## 真实案例

地址变更请求包含订单归属、国家、邮编、是否已出库等字段。Notebook 用 6 条事件比较“补默认值直接提交”的 baseline 与手写逐层 validator，包含跨字段冲突和已出库拒绝。

## 工程取舍与常见坑

只做 JSON 解析会漏掉业务约束；把校验错误写成一句自然语言会让模型难以修复。返回机器可读 error code、field、expected、actual 和可否重试，并限制修复轮数防止循环。

## 延伸追问

“校验应该在 Gateway 还是工具服务？”两层都要：Gateway 做通用风险与租户门禁，工具服务做不可绕过的领域权威检查。
