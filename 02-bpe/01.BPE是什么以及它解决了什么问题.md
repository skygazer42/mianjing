# 01. BPE 是什么，以及它解决了什么问题？

## 结论

BPE（Byte Pair Encoding）在 NLP 中是一类**贪心子词词表学习算法**：从字符或字节等很小的基本符号出发，反复把语料中最常见的相邻符号对合并为新符号。它把“按词切分容易遇到未登录词”和“按字符切分导致序列过长”折中成可控词表下的子词切分。

## 核心原理

设训练语料当前由符号序列组成。每一轮统计相邻对 \((a,b)\) 的加权频次，选择频次最高的一对并创建 \(ab\)，随后在整个语料中执行不重叠替换。高频单词、词根、后缀或代码片段会逐渐合成较长 token；低频词仍可退化成更细的符号组合。训练最终产出基础词表、按先后排序的 merge 规则以及 token 到 ID 的映射。

## 具体例子

语料中 “low” 出现 5 次、“lower” 出现 2 次。字符初始化后，\((l,o)\) 和 \((o,w)\) 都出现 7 次。若先合并 \(l+o\rightarrow lo\)，再合并 \(lo+w\rightarrow low\)，那么 “low” 可能只占一个 token，“lower” 则可表示成 “low + er”。这不是语言学切词，而是语料统计驱动的压缩式建模。

## 工程取舍与误区

BPE 只保证每轮局部最优，不保证得到全局最优词表；“最高频”也不等于“语义最完整”。词表过小会把文本切得太碎、增加注意力和 KV cache 成本；词表过大会放大 embedding 与输出层，并产生训练不足的稀有 token。字符级 BPE 仍可能遇到训练字符集之外的 OOV，byte-level BPE 才能用 256 个字节覆盖任意 UTF-8 输入。

## 面试回答要点

- 定义中要同时说清“从小到大”“相邻对”“按频次贪心合并”。
- 价值是平衡词表大小、序列长度与开放词表能力，而不只是压缩。
- 区分 tokenizer 训练与文本编码：编码时只应用已学 merge，不能重新统计输入。
- 可追问：BPE 与 WordPiece 的训练评分、与 Unigram 的删词方向有什么不同？

## 延伸追问

如果面试官要求设计实验，应固定模型参数预算，对多个词表大小分别统计各语言的 tokens/byte、P99 序列长度和实际训练吞吐，再训练小模型比较验证 loss。这样才能判断 merge 带来的压缩是否真正转化为模型收益，而不是只让少量高频样本看起来更短。
