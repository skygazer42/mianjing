# 08. BPE 如何用固定 merge rank 编码新文本？

## 结论

编码新文本不是再训练一次 BPE，而是先复现训练时的规范化、预分词和基础符号化，然后只应用已保存的 merge 规则。当前可合并 pair 中 rank 越小者优先，直到不存在合法规则，最后把符号映射为固定 token ID。

## 编码步骤

以规则 rank 0: l+o→lo，rank 1: lo+w→low，rank 2: e+r→er 为例。输入 lower 先变成 l o w e r；应用 rank 0 得 lo w e r，应用 rank 1 得 low e r，应用 rank 2 得 low er。若还有 low+er 的更晚规则则继续，否则输出两个 token。伪代码核心是：

~~~text
symbols = initial_symbols(piece)
while symbols 中存在已学习的相邻 pair:
    p = rank 最小的可用 pair
    symbols = 从左到右合并 p 的不重叠位置
return vocab_id(symbols)
~~~

## 为什么不能重算频次

单个请求里的最高频 pair 与训练语料的全局规律无关。若根据请求重新选择，同一词在不同句子甚至不同 batch 中会产生不同 ID 序列，缓存、模型训练和线上服务全部失去一致性。merge rank 表示构造依赖：较晚规则的左右 token 往往只有在较早规则执行后才出现。

## 工程实现与误区

朴素实现每次重新扫描所有 pair，最坏可接近 \(O(L^2)\)。常用优化是为相邻 pair 建最小堆，以 rank 为键；合并后仅更新左右邻居，并用版本号丢弃堆中失效条目。对大量重复词，可缓存“预分词片段→token IDs”，但缓存键必须包含规范化结果和 tokenizer 版本。盲目做 vocab 最长前缀匹配并非严格 BPE，在存在不可达 token 或不同 merge 依赖时结果可能不同。

## 面试回答要点

- 先讲完整前处理，再讲 rank 驱动合并，最后映射 ID。
- 训练看频次，推理看固定 rank。
- 说明堆、链表与片段缓存如何降低编码成本。
- 回归测试要比较 tokens、IDs、offsets 和 decode，而非只比 token 数。

## 延伸追问

还可以追问缓存是否会改变语义：缓存只能复用完整预分词片段的确定编码，不能在任意字符前缀处缓存后直接拼接，因为跨前缀边界可能存在合法 merge。缓存键还要绑定 tokenizer 文件哈希；否则模型升级后旧 ID 序列会被错误复用。
