# 05. BPE 词表、merge 规则和 merge rank 分别是什么？

## 结论

词表定义“哪些 token 可以映射为 ID”，merge 规则定义“哪两个已有符号能合成哪个新符号”，merge rank 则是这些规则的训练先后优先级。三者相关但不可互换：只有词表而没有有序 merge，通常无法严格复现 BPE 编码结果。

## 核心原理

假设依次学到 \(l+o\to lo\)、\(lo+w\to low\)。这两条规则的 rank 分别为 0 和 1，后一个 token 依赖前一个先存在。编码新词时，从基础字符或字节开始，在当前所有相邻对中选择 rank 最小的可用规则，合并其不重叠出现位置，直到没有规则可用。vocab 则给 l、o、lo、low 等表面符号分配稳定整数 ID，供 embedding 和输出层使用。

## 具体例子

对 “lower”，当前可能同时出现某条较晚学到的 \(w+e\) 和较早学到的 \(l+o\)。编码器先应用较小 rank，而不是按当前输入中的频次或盲目选择最长子串。最终所有生成 token 必须在 vocab 中有 ID。解码通常不需要 merge rank，只需按 ID 取出其字节串或带边界标记的字符串后拼接。

## 工程取舍与常见误区

有些序列化格式把新 token 的表面值隐含在左右 token 拼接中，有些明确保存 pair 到新 ID；实现必须遵循格式约定。若对 merge 文件重新排序，即使词表和 ID 完全不变，编码也可能变化。若只在 vocab 末尾加入一个字符串，却没把它注册为 added token 或建立可达 merge，它可能永远不会由 BPE 产生。特殊 token 通常在 BPE 普通流程外优先匹配。

## 面试回答要点

- vocab 负责 ID 空间，merge table 负责构造路径，rank 负责冲突时的顺序。
- 训练阶段依据 pair 频次选规则；推理阶段依据固定 rank 用规则。
- 模型参数与 token ID 绑定，因此上线后不能随意重排 vocab。
- 可追问：为什么最长匹配和按 merge rank 合并不总是等价？

## 延伸追问

一个很有区分度的追问是：若两个实现 decode 相同但 token IDs 不同，是否兼容？答案是否定的，因为模型读取的是 ID 对应的 embedding。排查时应打印每一轮可用 pair 与最小 rank，找出第一条分叉规则，而不是只比较最终字符串。
