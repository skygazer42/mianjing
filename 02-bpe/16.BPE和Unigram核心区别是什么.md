# 16. BPE 和 Unigram 的核心区别是什么？

## 结论

BPE 从小词表出发不断添加最高频 pair 的拼接结果；Unigram 通常从较大的候选词表出发，为 token 建概率模型，再迭代估计概率并删除损失影响较小的候选。BPE 编码由 merge rank 确定，Unigram 用动态规划在切分 lattice 上求最大概率路径，还能自然采样多条切分。

## 目标与方向

BPE 每轮优化局部频次，词表单调增长。Unigram 假设一条切分 \(z=(t_1,\ldots,t_k)\) 的概率近似为 \(\prod_i p(t_i)\)，训练考虑句子的多种可能切分，通过 EM 类过程更新 \(p(t)\)，再评估删除 token 对语料负对数似然的影响。它是概率模型，不依赖一串构造 merge。

## 具体例子

字符串 “unigram” 在 BPE 中只能使用按历史规则可构造出的组合；即使 vocab 表面上含有某字符串，缺失依赖 merge 时也未必被选。Unigram 会建立所有能覆盖当前位置的候选边，比较 “uni+gram”“un+i+gram”等完整路径的概率，Viterbi 选总 \(-\log p(t)\) 最小者。训练时还可以按路径分布采样，形成 subword regularization。

## 工程取舍与误区

BPE 训练与推理通常更简单、更快、产物易调试；Unigram 训练涉及候选生成、前向后向和剪枝，成本更高，但能表达分词不确定性。两者都受 normalization、预分词和基础字符覆盖影响。SentencePiece 是工具包而非算法同义词，它可训练 Unigram 也可训练 BPE。不能断言某算法对所有语言必然更好，应按 token 长度、鲁棒性与下游指标比较。

## 面试回答要点

- 记忆为：BPE“小到大加 merge”，Unigram“大到小删候选”。
- 推理：rank 合并对比 lattice + Viterbi。
- Unigram 天然支持 n-best 与随机切分，BPE 需 dropout 等扩展。
- 最终词表大小相同并不意味着序列或模型效果相同。

## 延伸追问

面试官还可能问“Unigram 是否一定比 BPE 全局最优”。应答：Viterbi 只在给定词表和概率下求最优路径，候选生成、EM 与剪枝仍可能落入局部方案；BPE 虽更贪心，却可能在某些语料和预算上更适合。算法搜索更复杂不等于下游质量必然更高。
