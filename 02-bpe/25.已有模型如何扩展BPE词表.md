# 25. 已有模型如何扩展 BPE 词表？

## 结论

可以追加 token，但这不是只改 tokenizer 文件：要保持旧 ID 完全不变，把新 ID 追加到末尾，扩展输入 embedding 和输出头，合理初始化新行，再用足够数据继续训练。若改变旧 merge 顺序或旧文本编码，兼容风险远大于单纯 added tokens。

## 两种策略

最保守方式是 added token：在普通 BPE 前优先匹配完整领域字符串，不修改已有 merges。另一方式是追加新的 merge 规则，使领域词可由旧基础符号构成；必须确保旧规则 rank 与旧 ID 不变，并测试旧语料是否仍得到相同编码。模型侧将矩阵从 \(V\times d\) 扩到 \((V+K)\times d\)，若输入输出权重共享需保持 tying。

## 初始化与训练

新 token embedding 可用其旧分词子 token 向量的均值或加权组合初始化，输出 bias 也需处理；随机初始化则需要更多适配数据。继续预训练时混入通用语料，避免只学新行却导致灾难性遗忘。还要检查量化权重、张量并行切分、LoRA 适配器和保存格式是否支持 resize。

## 工程取舍与误区

新增 token 能缩短领域术语，却不一定提升效果：旧模型已学会组合原子 token，新行反而缺少训练。过多 added tokens 会绕过普通边界，产生字符串包含关系和安全问题。绝不能重用或移动旧 special token ID。若目标只是让模型理解新概念，微调通常比改 tokenizer 风险低；只有 token 膨胀显著且有继续预训练预算时才更值得扩词表。

## 面试回答要点

- tokenizer 与 embedding/output head 必须同步扩展。
- 旧 ID 稳定和旧输入回归是兼容底线。
- 初始化只是起点，新 token 必须通过训练获得语义。
- 先量化长度收益和适配成本，再决定 added token、追加 merge 或重训。

## 延伸追问

扩展后需要特别检查输出层：生成模型若输入输出权重共享，只 resize 一处可能由框架自动处理，也可能打破 tying；MLM decoder 还可能有独立 bias。保存再加载、量化和张量并行切分都要测试新 shape，避免训练时可用而部署时索引越界。
