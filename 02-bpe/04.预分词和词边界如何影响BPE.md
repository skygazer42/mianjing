# 04. 预分词和词边界如何影响 BPE？

## 结论

预分词器先决定 BPE 可以在哪些范围内合并，因此它实际上定义了算法的搜索空间。是否允许跨空格、换行、标点或数字边界合并，会直接改变词表、同一字符串的 token 数、解码可逆性以及模型对格式的敏感程度。

## 核心原理

经典子词 BPE 常先按空白得到词频表，并在每个词末加入词尾标记；merge 只发生在一个词内部。GPT 风格 byte-level BPE 通常用正则把文本分成片段，再对每个片段的字节表示独立应用 merge。SentencePiece 风格则可以把空格编码成可见元符号，使空格成为句子片段的一部分。无论采用哪种方式，训练和推理必须使用完全相同的边界规则。

## 具体例子

若预分词把 “ hello” 保留为带前导空格的片段，词表可能同时出现 “hello” 与 “Ġhello” 一类不同 token；句首和句中同一单词因此编码不同。若数字整体参与 BPE，训练集中高频年份可能成为 token，但长随机数字会出现大量组合；若先把数字限制成固定长度片段，可以控制词表浪费和推理长度。代码中换行与缩进也不能随意折叠，因为它们承载语法信息。

## 工程取舍与误区

更强的预分词约束可减少无意义的跨边界 token，却也可能错过 URL、邮箱、中文或代码中的有效长模式。正则的 Unicode 语义、大小写选项和 regex 引擎版本都可能导致线上线下不一致。常见误区是只复制 vocab 和 merges 就认为 tokenizer 可复现；缺少 normalization、pre-tokenizer 与 byte 映射配置时，ID 序列仍可能完全不同。

## 面试回答要点

- 预分词不是性能优化细节，而是 BPE 模型定义的一部分。
- 它控制 merge 是否能跨边界，并影响空格和格式的表示。
- 给出 “hello” 在句首/句中或代码缩进的例子最容易说明问题。
- 调试编码差异时应先比规范化和预分词片段，再比 merge 规则。
