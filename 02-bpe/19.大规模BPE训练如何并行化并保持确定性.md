# 19. 大规模 BPE 训练如何并行化并保持确定性？

## 结论

BPE 的 pair 计数可以按语料分片并行归约，但每轮“选择哪个 pair 并更新符号序列”存在全局依赖，不能让 worker 独立学习 merge 后再简单拼接。可靠方案是并行统计、中央确定性选举、广播单条或经证明兼容的一批 merge，再由各分片局部更新。

## 典型流程

首先统一 normalization、预分词和片段频次聚合。每个 worker 对自己的片段统计 pair→加权计数，使用整数做全局 reduce；协调者按 \((-count, tie\_key)\) 排序选出唯一 winner，分配新 token ID 和 rank；worker 应用该 merge，仅更新局部受影响计数，进入下一轮。checkpoint 需保存 merge 列表、基础词表、当前片段状态或可重放输入以及 trainer 配置。

## 确定性难点

若使用浮点语料权重，树形归约次序会造成末位误差并翻转并列；哈希表无序迭代也会导致不同 pair 被选。应尽量把采样权重转换为稳定整数或固定精度，明确 pair 的二级排序键，并由单一协调者分配 ID。worker 数量变化时仍应得到同一结果，才能称训练可复现。

## 工程取舍与误区

每轮一次全局同步会产生 \(M\) 次通信，合并数数万时延迟很高。可压缩词频表、在节点内聚合、批量传输增量；某些近似算法一次选择多个互不冲突 pair，但它已经改变标准逐轮 BPE，必须通过质量和兼容测试。不能只把原始语料文件并行读完就宣称训练分布式，真正瓶颈可能是全局决策与状态更新。

## 面试回答要点

- 可并行的是计数和局部替换，串行语义是全局 merge 次序。
- 确定性依赖整数计数、稳定 tie-break、统一 ID 分配。
- checkpoint 除模型产物，还需保存训练状态与数据指纹。
- 近似批量 merge 换吞吐，但不保证与标准算法相同。
