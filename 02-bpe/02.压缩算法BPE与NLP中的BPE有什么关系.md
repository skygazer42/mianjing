# 02. 压缩算法 BPE 与 NLP 中的 BPE 有什么关系？

## 结论

两者共享“反复替换最高频相邻符号对”的思想，但目标和产物不同。原始 BPE 是字节序列压缩方法，追求用新符号缩短数据；NLP BPE 借用这套贪心过程学习子词词表，追求让语言模型在固定词表预算下得到较短且可泛化的 token 序列。

## 核心原理

经典压缩 BPE 在一段数据中找到最高频 byte pair，以未使用字节或码表项替代它，并保存替换字典。解压时逆序展开字典。NLP 版本通常在大规模词频表或预分词片段上训练，把每次合并记录成有顺序的 merge table。编码新文本时从基础符号开始，按 merge rank 组合；解码则把 token 对应的字符或字节串拼接回来。

## 关键差别

压缩系统必须把码表开销计入压缩率，而且可针对每个文件单独学习；tokenizer 一旦与模型共同训练，词表 ID 与 embedding 行绑定，所有样本和线上请求必须共享同一份模型文件。NLP BPE 的停止条件往往是目标词表大小或 merge 次数，而非继续合并是否还能减少文件总字节数。预分词、Unicode 规范化、空格表示和特殊 token 也属于 NLP 管线，而不是原始算法的必备组成。

## 例子与误区

若 “ing” 在语料中很高频，NLP BPE 可能学出它，即使保存 merge 表后并没有获得最佳物理压缩率，因为该 token 能在许多词形间共享表示。反过来，一个只在单个文件中反复出现的随机 ID 很适合压缩，却未必值得占用通用模型的永久词表。常见误区是看到 “Byte” 就认为 NLP BPE 必须以字节初始化；早期子词 BPE 常以字符初始化，byte-level 只是现代常见变体。

## 面试回答要点

- 相同点：最高频相邻对、逐轮创建新符号、可逆展开。
- 不同点：优化目标、训练范围、停止条件和产物生命周期。
- NLP 中真正部署的是基础词表、merge 次序、规范化与预分词配置的组合。
