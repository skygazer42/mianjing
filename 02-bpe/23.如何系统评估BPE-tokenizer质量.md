# 23. 如何系统评估 BPE tokenizer 质量？

## 结论

不存在一个指标能定义好 tokenizer。应在固定词表和模型预算下，从覆盖与可逆性、序列效率、分组公平、边界稳定、运行性能以及下游模型效果六个维度评估，并与字符数、UTF-8 字节数及旧 tokenizer 建立可复现基线。

## 核心指标

覆盖类包括 UNK 率、byte fallback 率、decode round-trip 与 offset 正确率。效率类可报告 tokens/character、tokens/byte、每词子词数 fertility、平均及 P50/P95/P99 序列长度。词表健康度包括 token 频次分布、从未或极少出现的词表项、实际覆盖质量。性能类包括单线程与批量编码 tokens/s、内存、冷启动和超长片段时延。

## 评测设计

测试集必须与 tokenizer 训练语料隔离，并按语言、领域、文本类型、长度和噪声分桶。加入 URL、JSON、代码、数字、emoji、组合字符、拼写错误和恶意长字符串。比较时固定同一批原文，既给宏平均避免大语言主导，也给按线上流量加权结果。最终用相同模型规模或相同总参数预算训练小型代理模型，比较验证 loss 与下游任务。

## 工程取舍与误区

token 数少不一定好：超长、低频 token 很难学到可靠 embedding；漂亮的形态边界也不保证语言模型 loss 更低。训练集上的压缩率会乐观，应重点看未见领域。API 成本要按真实 prompt 模板与输出分布模拟。若词表扩大，比较模型时应扣除增加的 embedding 参数，否则不是公平消融。

## 面试回答要点

- 先声明多目标，不要只答 UNK 或平均长度。
- 必须分语言/领域报告长尾分位数。
- tokenizer 离线指标最终要由受控下游实验验证。
- 质量回归与性能回归都应进入 CI。

## 延伸追问

还应做词表频次审计：统计多少 token 在训练后几乎从未出现、多少容量被模板、随机标识符或单一语言占用。对于同样的平均长度，一个频次更平滑的词表通常更容易把 embedding 训练充分，但这仍只是诊断信号，不能替代固定预算的语言模型实验。
