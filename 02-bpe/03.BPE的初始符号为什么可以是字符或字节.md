# 03. BPE 的初始符号为什么可以是字符或字节？

## 结论

BPE 本身只要求输入是离散符号序列，并不规定最小符号一定是什么。以 Unicode 字符初始化更直观、初始序列通常更短；以原始字节初始化只需 256 个基础符号，就能完整覆盖任意 UTF-8 文本，避免未知字符，但非 ASCII 文本在合并充分前会更长。

## 核心原理

字符级方案先把规范化后的字符串分成 Unicode code point，再在字符之间学习 merge。如果某字符从未进入基础词表，推理时只能报错、使用未知符号或依赖额外 byte fallback。字节级方案先执行 UTF-8 编码，任意输入都会变成 \(0\ldots255\) 的序列，所以表示能力是完备的。BPE 后续可以把构成常见汉字、emoji 或单词的连续字节重新合并成大 token。

## 具体例子

“你”的 Unicode 字符数是 1，但 UTF-8 是三个字节 E4 BD A0。字符级 BPE 初始就是一个符号；byte-level BPE 初始是三个符号，若训练语料中“你”足够常见，可能先合并 E4+BD，再与 A0 合并，最终仍成为一个 token。罕见 emoji 由四个字节组成，即使没有对应 merge，也能无损编码和解码。

## 工程取舍与常见误区

字符级并非天然支持“所有 Unicode”：完整 Unicode 空间巨大，训练集往往只收录其中一部分，而且组合字符、变体选择符会让“肉眼一个字符”对应多个 code point。字节级也不代表直接把不可打印字节写进 JSON；很多实现使用可打印 Unicode 映射保存 256 个字节，解码前再映射回来。还要避免把 byte-level BPE 与纯 byte-level 语言模型混为一谈，前者仍会学习多字节 merge。

## 面试回答要点

- 初始字母表决定覆盖能力和初始序列长度。
- 字节方案的关键性质是 UTF-8 可逆与 256 个值完备覆盖。
- 最终 token 粒度由语料和 merge 决定，而不是永远停留在字符或字节。
- 场景选择要同时看多语言长尾、token 成本、可逆性和实现复杂度。
