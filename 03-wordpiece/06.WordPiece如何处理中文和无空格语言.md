# 06. WordPiece 如何处理中文和无空格语言？

## 结论

经典多语言 BERT 的 BasicTokenizer 会识别 CJK 统一表意文字并在其两侧加入分隔，使常见汉字通常作为独立预分词片段，再由 WordPiece 查词表；它并不先执行语言学中文分词。其他无空格语言是否这样处理取决于脚本规则和训练器，不能把 CJK 策略泛化到所有语言。

## 核心原理

英文天然空格给出候选词边界，而中文句子没有。将每个 CJK code point 分隔可确保 MaxMatch 有稳定输入并减少整句 [UNK] 风险，但也阻止 WordPiece 跨汉字边界形成多字词 token。部分现代实现会采用不同预分词策略或直接在连续文本上训练子词，以获得常见词组合；这已不是原版 BERT BasicTokenizer 的完全相同行为。

## 具体例子

“自然语言处理”在经典规则下先成为 “自 然 语 言 处 理”，如果单字均在 vocab，通常输出六个 token，而不会因 vocab 中偶然存在“自然语言”就自动跨 basic-token 边界匹配。日文还包含平假名、片假名与汉字，韩文有音节块；只按 CJK 汉字分隔会产生不同粒度，需要用实际 tokenizer 验证。

## 工程取舍与误区

逐字切分覆盖稳、实现简单，但中文序列较长，词语级统计共享不足。允许跨字子词能压缩高频词，却更依赖语料、边界和词表容量。评估应分脚本报告 tokens/character、[UNK]、命名实体和混合中英文效果。Unicode CJK 扩展区若规则或词表覆盖不足，罕见字仍可能 [UNK]。

## 面试回答要点

- 经典 BERT 是 CJK 字符分隔，不等于中文分词器。
- WordPiece 不跨 BasicTokenizer 已建立的片段边界。
- 中文、日文、韩文与其他无空格脚本应分别评估。
- 若为新模型设计 tokenizer，可改变策略，但不能直接配旧 BERT checkpoint。

## 延伸追问

评估中文时不要用英文“每词子词数”直接套用，可报告每汉字 token 数、外部分词后的辅助 fertility、实体 [UNK] 和 512 上限的截断率。若尝试允许跨汉字候选，应把 BasicTokenizer 与词表共同重训，并用同参数模型验证收益，不能只向旧 vocab 添加多字词期待经典管线自动命中。
