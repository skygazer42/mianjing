# 03. WordPiece 的基础词表如何保证覆盖？

## 结论

要避免 [UNK]，词表必须为规范化与预分词后可能出现的每个基本字符提供合法的词首和词内表示，或配置明确的 byte/character fallback。经典 WordPiece 并不天然拥有全 Unicode 覆盖；基础 alphabet、字符频率阈值与最大字符集配置决定真实覆盖范围。

## 核心原理

训练通常先收集字符 alphabet，再生成多字符候选。对英文，可能需要 a 与 ##a 两种边界状态；实际 trainer 可用统一内部表示构造它们。高层子词只是缩短序列，最细字符路径才是兜底。如果当前位置连一个字符候选都不在 vocab，longest-match-first 无法推进，经典 BERT 实现便返回 [UNK]。

## 具体例子

训练语料只包含 ASCII，而线上出现 “café”。若 lower/strip accents 将 é 归一为 e，仍可覆盖；若保留重音且词表无 é/##é，整个词可能变 [UNK]。中文扩展区罕见字、emoji 和组合字符同理。加入全量 Unicode 字符会显著扩大词表，且仍有新版本字符，因此现代系统有时增加 byte fallback，但那是扩展设计，不是原版 WordPiece 的固有性质。

## 工程取舍与误区

alphabet 过大挤占多字符子词容量，过小则提高 [UNK] 与信息丢失。应按语言和脚本统计字符覆盖、词级 [UNK] 率以及造成 [UNK] 的 code point，而不只看总体样本数。Normalization 可以提升覆盖，却可能丢大小写、重音和兼容字符语义。不要认为“subword 就不会 OOV”，只有底层符号全集能表示输入时这一说法才成立。

## 面试回答要点

- 覆盖保证来自基础 alphabet，不来自最长匹配。
- WordPiece 的 [UNK] 常是某一步没有单字符兜底导致。
- 字符表、规范化和 fallback 共同决定覆盖与可逆性。
- 生产评测要按语言和 Unicode 类别定位未知字符。

## 延伸追问

覆盖验收可从线上样本收集所有规范化后 code point，检查其在词首和续接状态是否至少有一条路径，并为缺失项输出频次与业务字段。若使用 byte fallback，还应验证解码能逐字节还原，且模型确实训练过这些 byte IDs；“词表里有兜底项”不等于对应 embedding 已学充分。
