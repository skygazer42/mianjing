# 17. WordPiece 与 BPE 在训练和推理上如何系统比较？

## 结论

系统比较应分四层：训练评分、模型产物、推理搜索和未知输入。BPE 典型地按最高频相邻 pair 增长词表，并保存有序 merges；WordPiece 更强调似然改善或归一化候选评分，典型推理只靠最终 vocab 做 longest-match-first。两者都需要相同的前处理管线才能公平比较。

## 对比框架

BPE 训练时的历史决定 merge rank，推理从基础符号向上组合；WordPiece MaxMatch 从当前位置向最长词表项搜索，通常不重放合并历史。BPE 若以 bytes 为底座可覆盖任意输入；经典 WordPiece 基础字符缺失会让整个词 [UNK]。BPE token 常用前导空格或词尾约定，WordPiece 常用 ## 标记续接。

## 具体例子

最终 vocab 即使同时含 a、b、ab、abc，BPE 是否能生成 abc 取决于存在且可按 rank 到达的 a+b、ab+c 等规则；WordPiece 只要 abc 是合法词首项，就可直接最长匹配。反之，WordPiece 某个后续字符无 ## 形式会失败，而 byte BPE 可以退回原始 bytes。

## 工程取舍与误区

不能用两个现成模型的 token 数直接归因于算法，因为语料、词表大小、normalization、pre-tokenizer 完全不同。公平实验应同语料、同词表预算训练，按语言比较长度和下游 loss。BPE 与 WordPiece 都有多种实现变体，算法标签不是完整配置。更换旧模型 tokenizer 会破坏 ID/embedding 兼容。

## 面试回答要点

- BPE：频次 merge + ordered ranks；WordPiece：候选收益 + MaxMatch。
- 比较 [UNK] 时必须说明基础 alphabet 与 byte fallback。
- 最终表现依赖数据和前处理，不可宣称一方普遍更优。
- 给出同 vocab 但可达性不同的例子最能展示推理区别。

## 延伸追问

还可设计一个 conformance 实验：对相同预分词词，分别记录 BPE 每轮 rank 合并轨迹和 WordPiece 每步最长候选。即使最终 token 数相同，构造机制也可能不同。比较性能时应把 regex、normalization 和实现语言成本剥离，否则“算法更快”的结论可能只是一个用了 Rust、另一个用了 Python。
