# 14. 为什么一个字符缺失可能让整个词变成 [UNK]？

## 结论

经典 WordPiece 的契约是：一个预分词词必须被若干词表项完整覆盖；从任一位置找不到候选时，该词的切分失败并整体输出 [UNK]。这样实现简单且保持一个词的原子失败语义，但会把已经匹配的前缀信息也丢掉。

## 核心原理

MaxMatch 从 start=0 前进，每一步至少需要一个合法字符级项。假设词首 “play” 已命中，但剩余罕见字符 “🙂” 没有 ##🙂，算法不能跳过或凭空生成 ID。若输出 [play, [UNK]]，这将是另一种 fallback 规范；经典 BERT slow tokenizer 通常设置 is_bad=True 后返回 [UNK]，因此实现兼容时不能自行改变。

## 具体例子

词表覆盖 “microservice”，输入 “microserviceβ”。即使前 12 个字符可由多个子词表示，只要 β 在续接位置无候选，整个 basic token 可能变为一个 [UNK]。若 BasicTokenizer 先把 β 独立分开，则前半部分可保留，说明 [UNK] 粒度同时受预分词边界影响。

## 工程取舍与误区

整体 [UNK] 会产生信息碰撞：不同罕见用户名可能都成为相同 ID，影响检索、NER 和安全审计。改进方法包括扩大 alphabet、byte fallback、把未知字符预先独立切出，或改用 byte-level tokenizer；但任何改变都与旧模型预训练分布不一致。监控应记录导致未知的 code point 与所属 basic token，而不只统计 [UNK] token 占比。

## 面试回答要点

- 失败条件是当前位置没有任何合法候选。
- 经典行为通常是整个 basic token [UNK]，不是只替换一个字符。
- pre-tokenizer 决定失败影响范围。
- 解决覆盖问题时要考虑与 checkpoint 的兼容性。

## 延伸追问

面试官可能继续问“为什么不保留已匹配前缀再放一个 [UNK]”。答案是这属于另一种明确可设计的 fallback，但会改变经典 BERT 训练时看到的序列与 unknown 粒度；旧 checkpoint 未必适应。实际排障应打印第一个失败 start 和最短字符候选，从而区分字符缺失与 max length 触发。
