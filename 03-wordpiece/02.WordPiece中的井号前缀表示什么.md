# 02. WordPiece 中的 ## 前缀表示什么？

## 结论

## 是词表中的**词内续接标记**：没有前缀的 token 只能匹配一个预分词词的开头，带 ## 的 token 只能匹配该词的后续位置。它编码边界状态，帮助同一字符序列在词首和词中拥有不同词表项；它通常不是原始文本里的两个井号。

## 核心原理

对一个词做 MaxMatch 时，位置 start=0 的候选直接取子串，例如 play；start>0 的候选先拼接 ##，例如 ##ing，再查 vocab。解码器显示文本时通常去掉 ## 并与前一个片段连接。边界状态让 “un” 与 “##un” 可以拥有不同 ID 和统计，因为词首前缀与词内片段的语境分布不同。

## 具体例子

词表为 {play, ##ing, ing}。单独的 “ing” 可编码为 [ing]，而 “playing” 编为 [play, ##ing]。若只有 ing 而没有 ##ing，算法不能在 playing 的后半段直接复用 ing；反之只有 ##ing 时，它不能作为独立词的首片段。这与 SentencePiece 的 ▁ 或 GPT 风格前导空格符号用途相近，都把边界信息带入 token，但位置与实现约定不同。

## 工程取舍与误区

直接用字符串 replace("##","") 解码不可靠：原文可能真的包含 ##，特殊 token 和标点又有独立拼接规则，应使用配置化 decoder。词表文件中的 ## 是模型语义的一部分，改成别的前缀会使查词失败。中文经 CJK 字符分隔后很多单字处于“词首”位置，续接标记的表现与英文不同。offset 不能把两个井号算进原文跨度。

## 面试回答要点

- ## 表示 continuation，不表示 Markdown、注释或未知字符。
- 词首 token 与词内 token 是不同词表项，可有不同 ID。
- 举 ing 独立出现与 playing 中出现的对比。
- 与 ▁/前导空格比较时要说清：共同点是编码边界，具体方向不同。

## 延伸追问

可以进一步解释 vocab 中同时存在 “run” 与 “##run” 并不冗余：前者的统计来自词首，后者来自复合词内部，模型会学习不同 embedding。实现测试应分别编码独立词、带前缀词和原文真的含井号的代码片段，确认 continuation marker 只在模型层生效而不污染 offset。
