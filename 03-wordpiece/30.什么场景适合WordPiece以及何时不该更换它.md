# 30. 什么场景适合 WordPiece，以及何时不该更换它？

## 结论

需要复用 BERT、mBERT 或既有 WordPiece checkpoint、追求成熟 encoder 工具链和快速确定性 MaxMatch 时，WordPiece 是合理选择。开放多语言生成、任意 Unicode 无损输入或需要随机分词正则化时，应评估 byte-level BPE 或 Unigram。对已训练模型，通常不应仅为减少 token 数而更换 tokenizer。

## 决策维度

首先看兼容：token ID 与 embedding 已绑定时，更换等价于改变模型输入语言。其次看覆盖：[UNK] 是否在目标域可接受，是否需要 byte fallback。再次看任务：分类可容忍规范化与有限未知，精确生成和代码更重视可逆。最后看资源：WordPiece Trie 推理快、制品简单，但词表扩大仍增加 embedding/softmax。

## 具体场景

在医院内部用 BioBERT 做分类，继续使用原 WordPiece 并做领域微调通常风险最低；即使医学术语较碎，模型已在该切分上预训练。若从零构建面向全球用户的聊天生成模型，罕见脚本和 emoji 整体 [UNK] 不可接受，byte 底座更稳妥。低资源机器翻译若希望采样多切分，Unigram 可作为候选。

## 工程取舍与误区

“新算法更新”不是迁移理由。若确实重训 tokenizer，需要重新或继续预训练模型、重做输入输出矩阵和全套评测。若只是新增少数领域概念，知识微调可能比改词表更有效。选择实验要统一语料、词表和总参数预算，报告分组 fertility、UNK、吞吐、截断和下游结果。

## 面试回答要点

- 兼容旧 checkpoint 是第一约束。
- WordPiece 优势是成熟、确定、快速；短板是经典字符覆盖和整体 UNK。
- 新模型按任务与输入开放性比较算法，旧模型不要轻易换。
- 决策需要端到端证据，而不是算法流行度。

## 延伸追问

迁移评估可以先做影子编码，统计新旧 token 数和 ID 序列变化，但质量 A/B 必须使用分别适配的模型 checkpoint，不能让旧 BERT 直接读取新 IDs。若项目生命周期短、已有生态稳定，迁移成本往往高于少量长度收益；只有覆盖、成本或任务质量形成明确瓶颈时才值得重训。
