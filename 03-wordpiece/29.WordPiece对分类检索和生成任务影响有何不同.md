# 29. WordPiece 对分类、检索和生成任务影响有何不同？

## 结论

分类关注信息是否保留与序列是否被截断；检索还关心查询和文档实体切分的一致性及向量效率；生成则要求可逆文本、开放字符覆盖和流畅的逐 token 解码。经典 WordPiece 很适合 BERT encoder 生态，但 [UNK] 与非严格可逆使它未必是开放域生成的首选。

## 分类场景

多个子词可由 self-attention 聚合，适度碎片化通常可接受；但长文因 fertility 高而更早截断，或关键实体整体 [UNK]，会直接损失分类信号。tokenizer 指标应与准确率、截断率共同观察。cased/uncased 选择还依赖标签是否需要大小写信息。

## 检索与生成

双塔检索要求 query 与 document 使用同一 tokenizer 版本，领域词被一致拆分有利于表示共享；大量 [UNK] 会让不同实体碰撞。生成模型每步在词表 softmax 上预测，## decoder 要正确拼接且 normalization 丢失的大小写/重音无法恢复。用户可能生成任意 emoji 或代码，字符级 WordPiece 覆盖不足会成为明显问题。

## 工程取舍与误区

不能因为 BERT 分类表现好就推断该 WordPiece 适合 decoder-only LLM。任务模型已预训练时兼容性优先，通常不应换 tokenizer；从零训练时应按输出空间选择 byte fallback、可逆 normalization 和词表。评估需要任务真实样本、长尾实体、成本和下游质量，而非孤立看几条切分。

## 面试回答要点

- 分类看信息与截断，检索看实体一致与碰撞，生成看覆盖与可逆。
- 同一个 tokenizer 缺点在任务间权重不同。
- 旧模型首先遵守 checkpoint 兼容，新模型才自由选算法。
- 最终用端到端指标验证，不凭 tokenizer 美观度判断。

## 延伸追问

对于检索，可以构造只在最后一个字符不同的长尾实体，观察它们是否都变成同一 [UNK] 并造成向量碰撞；对于生成，测试大小写、重音、emoji 和代码空白能否 round trip。分类则重点比较截断前后关键证据是否保留。三套测试能把同一 tokenizer 风险映射到不同业务后果。
