# 13. 从语料训练 WordPiece 词表通常有哪些步骤？

## 结论

典型流程包括冻结规范化与预分词、构建带词首状态的基础 alphabet、统计词频和候选、按似然改善或近似评分迭代扩展词表、达到预算后导出 vocab，并用最长匹配回放语料评估。特殊 token 与 ID 排序必须在训练前后有明确契约。

## 训练步骤

先清洗、去重并按语言领域采样语料，使用目标 BasicTokenizer 得到词频表。初始化时确保常见字符在词首与续接位置可表示，并加入 [PAD]/[UNK]/[CLS]/[SEP]/[MASK]。随后从当前分解生成相邻候选，计算评分，选择 winner 创建新子词，再更新受到影响的词分解与统计，直到 vocab size 或最低收益阈值满足。

## 具体例子

playing:10、player:5 初始可分成 p ##l ##a ##y ##i ##n ##g 等。训练可能先得到 play，再得到 ##ing 和 ##er。最终推理不需要保存 BPE 式有序 merges，只需最终 vocab 与 continuation_prefix 即可做 MaxMatch；但训练产物还应保存 normalizer、pre-tokenizer 和 special token 配置。

## 工程取舍与误区

候选数可能随语料爆炸，需要 min frequency、最大子词长度、字符覆盖和分桶统计。不同 tie-break 会改变 ID 和最终词表，应稳定排序并记录 trainer 版本。直接在全量句子上反复切分成本很高，常先聚合重复词频。仅导出 vocab.txt 会遗漏 lowercase、Chinese chars、never_split 等关键行为。

## 面试回答要点

- 数据管线和基础覆盖先于候选学习。
- 训练需迭代评分、加 token、更新当前分解。
- 推理主要依赖最终词表做 MaxMatch，不等同于重放训练过程。
- 训练后必须按独立语料和模型任务验证。

## 延伸追问

生产训练还要保存语料指纹、BasicTokenizer 配置、trainer 版本、随机种子和并列排序。可在小词频表上逐轮打印 winner 与当前分解，验证词频权重没有被误当成词型数。导出后用全新进程加载 vocab，确认特殊 ID、最长匹配、decode 与 offsets 均能复现，避免训练器内存状态掩盖缺失配置。
