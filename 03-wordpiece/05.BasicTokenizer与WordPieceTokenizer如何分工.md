# 05. BasicTokenizer 与 WordPieceTokenizer 如何分工？

## 结论

在经典 BERT 管线中，BasicTokenizer 负责清理与规范化文本、按空白和标点切分、可选 lowercase/去重音，并对 CJK 字符加边界；WordPieceTokenizer 只对这些“词”执行词表最长匹配。二者配置共同定义最终 ID，不能只复制 WordPiece vocab 就期望行为一致。

## 核心流程

原文先处理无效控制字符和空白，再根据 do_lower_case、strip_accents 等选项规范化。标点通常独立切出；中文字符周围插入空格式边界，使每个汉字成为独立片段。得到片段列表后，WordPiece 逐个应用 MaxMatch；最后 post-processor 为任务添加 [CLS]、[SEP]，padding/truncation 则在更外层。

## 具体例子

输入 “Hello,世界!”。BasicTokenizer 可能产生 [hello, ',', '世', '界', '!']；WordPiece 再把 hello 切成 [he, ##llo]，标点和汉字若在 vocab 中直接映射。若关闭 lowercase，Hello 可能走不同 token 甚至 [UNK]。如果换一个标点规则把 “Hello,” 保持整体，最长匹配的搜索空间随之改变。

## 工程取舍与误区

“BERT tokenizer”不是一个单算法名称，而是 normalizer、basic pre-tokenizer、WordPiece model、special post-processing 的组合。快速 Rust tokenizer 与旧 Python tokenizer 可能在控制符、Chinese chars、never_split 和 offset 上有边界差异，需要 golden tests。某些现代 WordPiece 管线并不完全复刻原始 BasicTokenizer，面试回答应注明“经典 BERT 实现”。

## 面试回答要点

- BasicTokenizer 决定片段和规范化，WordPiece 负责片段内部子词。
- [CLS]/[SEP] 不是 WordPiece 匹配出来的。
- 前处理变化会比词表小差异更大地改变 IDs。
- 调试时打印 basic tokens，再打印 wordpieces，能快速找第一处分叉。

## 延伸追问

可以用 “Résumé，北京!” 做分层演示：先观察 lowercase/去重音，再看标点和 CJK 边界，最后看每个 basic token 的 ## 切分。若某端结果不同，先比较 Unicode code point 和 basic tokens；只有它们一致才进入 MaxMatch 调试。训练服务和移动端还需固定 max chars、never_split 与特殊 token 阶段，否则同一 vocab 仍不兼容。

从测试设计看，每一层应有独立输入输出契约：normalizer 断言规范化串，BasicTokenizer 断言片段与跨度，WordPiece 断言 pieces，post-processor 断言最终 IDs 和 mask。分层单测比只检查最终句子更容易定位回归，也能证明代码没有意外跨层改变语义。
