# 15. MaxMatch 的复杂度与 Trie 优化是什么？

## 结论

朴素 MaxMatch 在每个起点从词尾逐字符缩短并构造 substring，长度为 \(n\) 的词最坏会做 \(O(n^2)\) 级字符检查或分配。将词表组织成 Trie 可从当前位置沿字符向前走并记录最后一个终止节点；进一步的 failure-link/LinMaxMatch 方案能避免反复回退，使处理更接近线性。

## 朴素与 Trie

朴素算法对 start=0 试 n、n-1…长度，命中后再对下一个 start 重复。Trie 从根开始消费字符，路径不存在时返回最近的合法终止点；词首 Trie 与续接 Trie 可分开，或在节点状态中区分 ##。最大子词长度 \(K\) 有界时，复杂度可粗略控制在 \(O(nK)\)，内存则取决于节点表示。

## 具体例子

输入由一万个 a 后接 b 组成，词表只有短 a 片段且无 b。朴素 substring 试探会创建大量临时字符串，成为 CPU 和 GC 热点。Trie 每个位置只沿有限深度前进，并在最终失败时按契约返回 [UNK]。对批量短英文词，LRU 缓存热门词的结果往往比复杂算法带来更大实际收益。

## 工程取舍与误区

标准哈希表的 \(O(1)\) 查找不意味着整体 \(O(n)\)，substring 构造和尝试次数仍存在。压缩 Trie、双数组 Trie 能降低内存，但实现复杂；Unicode 按 code point、UTF-8 byte 或 UTF-16 unit 构树必须与规范一致。性能测试应含超长无边界输入，并设置 max_input_chars_per_word 提前拒绝，防止分词 DoS。

## 面试回答要点

- 朴素瓶颈来自重复前缀尝试和 substring 分配。
- Trie 共享前缀，记录最远终止节点实现最长匹配。
- LinMaxMatch/failure links进一步避免回退。
- 缓存、长度上限和 Unicode 索引同样重要。

## 延伸追问

实现 Trie 时不能一遇到终止节点就立刻输出，而要继续走并记录“最后一个终止节点”，直到路径失败才回到最远合法点，否则会变成最短匹配。对词首与续接可以维护两个根，也可以把状态编码在边上。性能基准应同时报告冷缓存、热缓存和恶意超长词的 P99。
