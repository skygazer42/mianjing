# 08. WordPiece 词表大小如何影响序列和模型参数？

## 结论

更大 WordPiece 词表通常让高频词由更少子词表示，缩短序列；同时增加 embedding 和输出层参数，并产生更多低频、训练不足的 token。最优词表取决于模型隐藏维度、语料规模、语言数量和下游长度分布，不是固定的 30k。

## 成本关系

词表大小为 \(V\)、隐藏维度为 \(d\) 时，输入 embedding 有 \(Vd\) 参数。BERT 类 masked LM 还要对词表输出 logits，即使与输入 embedding 共享权重，也有大词表 softmax 成本。序列从 \(L\) 降低则可减少各层计算；标准 self-attention 的相关项约随 \(L^2\) 增长，FFN 项约随 \(L\) 增长。

## 具体例子

从 30k 增到 60k，在 \(d=768\) 时输入矩阵增加约 2304 万参数。若医学文本的平均 fertility 从每词 2.2 降到 1.4，可能显著节省长度；若通用集只从 1.18 降到 1.15，新增参数和稀有 token 未必值得。多语言词表还会出现高资源语言占据额外容量的现象。

## 工程取舍与误区

比较词表时要固定总参数或至少报告 embedding 差异，不能让大词表模型天然拥有更多参数再归因于 tokenizer。平均长度会掩盖低资源语言和长实体的 P99。过细切分并非总坏，它提高形态共享；过粗整词也并非总好，低频 embedding 难学。还需评估 [UNK]、实际 token 频次、编码吞吐与下游 loss。

## 面试回答要点

- 词表大：序列短，但矩阵、softmax和稀有项成本高。
- 词表小：共享强，但序列和注意力成本上升。
- 通过多候选曲线和受控小模型实验找拐点。
- 多语言/领域应分组评估，不照搬 BERT 的历史大小。

## 延伸追问

固定总参数比较时，词表从 30k 增到 60k 增加的 embedding 参数应从主干宽度或层数预算中扣除；固定算力时还要计入 MLM softmax。一个可靠决策会同时画 vocab size 对 P95 长度、稀有 token 占比、吞吐和验证 loss 的曲线，在边际收益开始变小时选取拐点。
