# 22. 生产级 WordPiece 如何用 Trie 和缓存提速？

## 结论

生产优化的核心是减少重复前缀扫描和字符串分配：用 Trie 共享 vocab 前缀，用最近终止节点实现最长匹配，用双数组或压缩节点降低内存，并缓存高频 basic token 的结果。批量并行适合词之间，不应破坏单词内部的确定顺序。

## Trie 搜索

可为词首项和 ## 续接项建立两个 Trie，或在同一 Trie 根下编码边界状态。从 start 沿字符前进，记录最后一个 is_terminal 节点及其 end；路径断开时回到最后终止点输出 token，没有终止点则整词失败。failure-link 的线性 MaxMatch 变体可进一步复用失败后的状态，避免重复从根开始。

## 缓存与批处理

自然语言中功能词和常见词高度重复，LRU 缓存 normalized basic token→piece IDs 可显著提速。键必须包含 tokenizer 版本与影响结果的模式，例如 lowercase 已在上游完成后才可安全复用。多线程可分发 basic tokens，再按原顺序拼回 offsets；相同词可先聚合去重后批量查询。

## 工程取舍与误区

Trie 节点若使用大哈希映射可能比 vocab 本身更占内存，双数组 Trie 更紧凑但构建复杂。缓存对随机 ID、URL 等高基数输入可能失效并造成抖动，要限制条目数、键长度和 admission。性能基准要包括 ASCII、CJK、长未知词、热缓存与冷缓存，并确认快速实现的 Unicode 索引、max length 和 [UNK] 语义未变化。

## 面试回答要点

- Trie 把重复 substring 查找变成共享前缀遍历。
- 记录最远终止节点才能保持 longest-match-first。
- LRU 利用词级重复，键要绑定规范化结果和版本。
- 优化指标包括吞吐、P99、内存和精确兼容性。

## 延伸追问

若缓存 tokens 而 offsets 依赖词在原文中的绝对位置，应只缓存相对片段跨度，命中后再平移，不能复用绝对 offset。并发缓存还要防止大键和重复构建造成锁竞争。启动时可预热最常见词，但必须把 tokenizer hash 放入命名空间，模型切换后整体失效。
