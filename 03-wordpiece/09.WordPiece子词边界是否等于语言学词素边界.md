# 09. WordPiece 子词边界是否等于语言学词素边界？

## 结论

不等于。WordPiece 边界由训练语料、候选评分、词表预算和预分词规则共同决定，可能碰巧对应词根或后缀，但没有显式形态学约束。它的目标是统计建模与覆盖折中，不是输出语言学正确的 morpheme 分析。

## 核心原理

高频组合更可能成为词表项，跨多个词共享的片段也可能获得较好评分，因此英文中常看到 play + ##ing 之类可解释结果。但品牌名、拼写片段、标点组合或偶然高频字符串也会成为 token；一个真实词素如果频次低或字符组合竞争失败，仍会被拆开。MaxMatch 又只依据最终词表长度，不评价语义合理性。

## 具体例子

“unhappiness” 理想形态分析可能是 un + happy + ness，实际词表可能给出 [un, ##ha, ##pp, ##iness]，也可能把 happiness 整体保留。两种切分都能供模型学习，Transformer 会在上下文中组合表示。中文单字切分更不能等同于词语分析；代码标识符中的 ## 片段也未必遵循 camelCase。

## 工程取舍与误区

把 token 可视化后凭“看起来像词根”评价 tokenizer 很主观。形态边界对某些低资源和标注任务可能有益，但语言模型最终质量还与长度、频次、模型容量相关。若任务需要真正形态分析，应使用专门工具或监督目标，而不是依赖 tokenizer。不能把 token 当作人类可解释语义原子，也不能用单个 token embedding 直接代表完整概念。

## 面试回答要点

- WordPiece 是统计子词，不是语言学切词。
- 可解释边界是高频规律的副产品，不是保证。
- 模型能组合多个子词，切分丑不必然导致任务差。
- 评价要用覆盖、效率和下游指标，而非只看少数例子。

## 延伸追问

若任务确实希望形态边界，可把人工 morpheme boundary F1 作为辅助指标，或在 tokenizer 训练中加入约束，但应同时检查序列长度和模型 loss。对比时还要控制语料规模：低频词看似“乱切”可能只是没有统计证据，而不是算法不知道某条语言学规则。
