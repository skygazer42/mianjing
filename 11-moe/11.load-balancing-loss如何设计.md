# 11. load balancing loss 如何设计？

## 目标与经典形式

负载均衡希望每个 expert 获得相近 assignment 和 router 概率，避免少数 expert 过载、其余欠训练。一类常见辅助损失同时使用离散选择比例 \(f_e\) 与平均路由概率 \(P_e\)：

\[
f_e=\frac{1}{Tk}\sum_t\mathbf1[e\in TopK(t)],\qquad
P_e=\frac1T\sum_t p_{t,e},
\]

\[
L_{bal}=\lambda E\sum_{e=1}^{E} f_eP_e.
\]

均匀时 \(f_e,P_e\approx1/E\)。离散 \(f_e\) 通常不反传，梯度经可微的 \(P_e\) 推动 router 降低热门专家概率。

## 为什么不能只看 token 数

只惩罚离散 count 缺少常规梯度；只让平均概率均匀，top-k 排名仍可能集中。二者乘积把实际选择和概率联系起来。也有基于熵、方差、最大负载、Sinkhorn/OT 的设计，口径不同。Top-k、shared experts、sequence group 与 expert group 内归一化都要在公式中明确。

## 取舍

\(\lambda\) 太小会 collapse、overflow 和长尾等待；太大会迫使 router 为“均匀”牺牲语义最优，让不合适专家处理 token，并把辅助目标梯度污染主干表示。均衡只应达到系统可承受程度，不是所有 batch 每个 expert 完全相等。小 batch 的 count 方差天然大，适合跨更大 token group 统计，但全局 all-reduce 又增加通信。

PAD、被 drop 的 assignment和 top-2 第二路径是否计入必须一致。若只在每卡本地算均衡，可能每卡都偏向不同本地 expert但全局仍失衡；若跨 expert-parallel group 统计，梯度与通信要正确。

## 诊断与面试要点

同时记录 \(f_e,P_e\)、最大/平均、熵、辅助损失占主损失比例、drop 和任务质量。负载均匀不表示专家有用，也可能是 router 接近随机。

面试回答应写出 \(f_eP_e\) 类公式、解释离散/可微两部分，再说明系数过大与统计范围的代价。
