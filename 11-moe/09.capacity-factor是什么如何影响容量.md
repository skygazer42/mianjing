# 09. capacity factor 是什么，如何影响专家容量？

## 定义

固定容量 MoE 会为每个 expert 预留最多 \(C\) 个 token assignment。若本批有效 token 数为 \(T\)、专家数 \(E\)、每 token 选 \(k\) 个专家，均匀期望负载为 \(Tk/E\)，常设

\[
C=\left\lceil \alpha\frac{Tk}{E}\right\rceil,
\]

其中 \(\alpha\) 是 capacity factor。它不是“专家参数容量”，而是一次路由中每个专家可接收的 token 槽位倍率。

上式采用“全部 top-k assignment 共用一个容量池”的口径。部分 top-2 路由器会给第一、第二选择分别分配 \(C=\lceil\alpha T/E\rceil\) 的容量，或把 \(k\) 隐含进 \(\alpha\)；这些公式数值不能直接混用，判断 overflow 前必须先看实现如何计数。

## 数字例子

\(T=4096,E=32,k=2,\alpha=1.25\) 时，平均 assignment 为 256，容量 \(C=320\)。若 expert 7 收到 350 个 assignment，超出的 30 个必须 drop、改投备选、走 shared/residual，或让实现动态扩容。静态张量通常按 \([E,C,d]\) 分配，没填满的槽位是 padding。

## 质量、内存与吞吐取舍

\(\alpha\) 太小会产生溢出：被丢 token 的专家输出缺失，训练信号和生成质量受损，热门语言/任务还可能被系统性丢弃。太大能容忍路由倾斜，却增加 dispatch buffer、专家激活和 padding GEMM，降低利用率。Top-2、全局 batch、expert parallel group 大小、排除 PAD 与否都会改变 \(T\) 和真实均值，公式口径必须一致。

训练初期 router 更乱，可能需要较大 factor；稳定后可降低，推理时又因 batch/并发不同重新选择。不能直接照搬训练 \(\alpha\)。若 capacity 按本地 rank 计算但负载均衡统计是全局，分布式切分可能让局部溢出远高于预期。

## 监控与误区

至少记录每层最大/平均负载、容量利用率、overflow/drop/reroute 比例及按数据切片的溢出。平均利用率高不代表安全，P99 热点决定容量。Dropless MoE 不设这种硬丢弃槽位，但仍受最大 expert batch、工作区和尾延迟约束。

面试回答应写出 \(C=\lceil\alpha Tk/E\rceil\)，再解释小 factor 损质量、大 factor 浪费 padding/显存，以及 top-k 和分布式统计口径。
