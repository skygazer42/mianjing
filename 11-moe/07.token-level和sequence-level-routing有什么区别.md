# 07. token-level 和 sequence-level routing 有什么区别？

## 核心区别

Token-level routing 为序列中每个 token 独立选专家，粒度细、条件容量强，但同一序列可能被拆到多台设备，dispatch 不规则且 all-to-all 频繁。Sequence-level routing 为整个序列、样本或任务选择同一组专家，路由稳定、缓存和批处理更规则，却无法让一句话里的代码片段、自然语言和不同推理阶段分别使用不同专家。

## 公式与数据流

Token 级对隐藏状态 \(x_t\) 计算 \(p_t=\operatorname{softmax}(W_rx_t)\)，得到 \(S_t=TopK(p_t)\)。序列级先聚合

\[
\bar x=Pool(x_1,\ldots,x_L),
\quad S=TopK(\operatorname{softmax}(W_r\bar x)),
\]

再让所有 \(t\) 使用同一 \(S\)。Pool 可用首 token、mean 或外部任务 id；因果生成若用全序列 mean 会看到未来，必须只用前缀可用信息或在请求开始固定路由。

## 具体例子

一条“请解释下面 Python 报错”的请求同时包含中文指令、代码和堆栈。Token routing 可将不同片段交给不同专家；sequence routing 只能选择一组折中专家。但服务端按请求固定专家后，权重放置、batch grouping 和尾延迟更可预测，还可能提前预取专家权重。

## 训练和系统取舍

Token 级负载统计的样本数是 token assignments，通常更平滑；序列级若长短差异大，按“序列数均衡”不等于按“token/FLOPs 均衡”，一个长请求会压垮专家。Sequence routing 还可能形成任务/租户捷径，跨域泛化较差。Token routing 则容易相邻 token 频繁切专家，通信局部性差。

可采用层次路由：先按序列选候选 expert group，再在组内按 token top-k，兼顾局部性和精细分工，但路由与容错更复杂。

## 常见误区与面试要点

Sequence-level 不等同于 batch-level；批内每条序列仍可选不同专家。Token-level 也不要求每层选择相同 expert。面试应从粒度、表达能力、因果可用信息、通信规则性和负载口径比较。
