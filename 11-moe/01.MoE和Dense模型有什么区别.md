# 01. MoE 和 Dense 模型有什么区别？

## 结论先行

Dense 模型对每个 token 都执行同一组 FFN 参数；稀疏 MoE 把一组 FFN 换成多个 expert，并由 router 为每个 token 只选择 top-k 个 expert。于是 MoE 可以拥有很大的**总参数量**，同时把单 token 的**激活参数量和 FLOPs**控制在较低水平，但要额外承担路由、负载均衡、专家参数存储和跨设备 all-to-all 通信。

## 从一个 Transformer block 看区别

Dense FFN 可简化为：

$$
y = W_2\,\sigma(W_1x)
$$

所有 token 都经过同一个 $W_1,W_2$。如果把这一层改成 $E$ 个专家，router 先计算：

$$
p(x)=\operatorname{softmax}(W_rx)
$$

再选择分数最高的 $k$ 个专家集合 $S(x)$，输出近似为：

$$
y=\sum_{i\in S(x)}\tilde p_i(x)\,\operatorname{Expert}_i(x)
$$

其中 $k\ll E$，$\tilde p_i$ 是 top-k 之后重新归一化或按实现处理的路由权重。典型 expert 本身仍是 SwiGLU/MLP 一类前馈网络，attention 往往保持 dense；所以 MoE 通常指**稀疏 FFN**，不要与稀疏 attention 混为一谈。

## 参数量与计算量怎么区分

假设每个 expert 有 $P_e$ 个参数，共有 $E$ 个 routed experts，每个 token 激活 $k$ 个：

```text
专家总参数量       ≈ E × P_e
单 token 专家激活量 ≈ k × P_e
```

再加上 attention、embedding、norm、router 和可能的 shared experts，才是完整模型。比如有 64 个等宽专家、每个 token 选 2 个，专家部分的总参数是单专家的 64 倍，但单 token 只执行约 2 个专家，而不是 64 个。这就是“参数容量扩大，计算不同比例扩大”的来源。

不过 $kP_e$ 相同不代表真实延迟相同。Dense FFN 是规则的大矩阵乘，容易让 GPU 吃满；MoE 需要把 token 按专家分桶、跨卡发送、执行大小不均的矩阵乘，再把结果送回原顺序。小 batch、路由倾斜或互联带宽不足时，理论 FLOPs 较低也可能更慢。

## MoE 得到了什么

1. **更大的参数容量**：模型可以存储更多模式，而不让每个 token 经过全部参数。
2. **条件计算**：不同 token 可使用不同参数子集，理论上允许一定程度的功能分工。
3. **更好的训练计算扩展**：在合适数据、集群与实现下，相近训练 FLOPs 可获得比同等激活规模 dense 模型更强的容量。

这里的“专家”只是参数分支，不保证自动对应“数学专家”“中文专家”等人类可解释领域。路由常会受词形、位置、频率和数据分布共同影响，专业化需要用实验证据验证。

## MoE 付出了什么

- **参数与显存**：推理某个模型实例原则上仍需放置或分片所有专家，除非做卸载、复制或按需加载；总参数不会因为稀疏激活消失。
- **负载均衡**：router 可能把太多 token 发到少数专家，产生 expert collapse、丢 token 或尾延迟。
- **通信**：expert parallel 通常需要 dispatch 和 combine 两次 all-to-all，容易受拓扑与带宽限制。
- **训练稳定性**：离散 top-k、router logits、容量约束和辅助损失引入额外超参数。
- **服务复杂度**：并发请求的路由分布动态变化，专家放置、batching、量化和故障定位都比 dense 更难。

## Dense 与 MoE 如何公平比较

至少区分三种口径：

1. **总参数相同**：MoE 只激活一部分，通常单 token 计算更少，但所有权重仍要存储。
2. **激活参数/FLOPs 相同**：MoE 总参数更多，可比较条件容量带来的质量收益。
3. **端到端延迟或成本相同**：必须计入通信、batch、内存带宽和集群利用率，最接近生产决策。

只说“某 MoE 有几千亿参数，所以一定比几十亿 dense 更贵”忽略了稀疏激活；只说“每次只用几十亿参数，所以显存只需几十亿参数”同样错误。

## 什么时候 Dense 反而更合适

小模型、端侧部署、低 batch 实时服务、互联较弱或运维团队规模有限时，dense 的规则计算、稳定延迟和简单并行通常更有价值。MoE 更适合数据与算力规模足够大、模型质量受参数容量限制，并且集群能高效承担专家并行通信的场景。

## 面试回答要点

先说“dense 全激活，MoE 由 router 稀疏激活 top-k experts”，再分别比较总参数、激活参数与真实延迟。最后主动指出 MoE 的三项主要代价：所有专家仍需存储、路由需要负载均衡、跨卡 dispatch/combine 产生 all-to-all 通信。
