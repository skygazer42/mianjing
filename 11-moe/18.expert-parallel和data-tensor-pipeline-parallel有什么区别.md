# 18. expert parallel 与 data、tensor、pipeline parallel 有什么区别？

## 四种切分轴

Data parallel（DP）复制完整模型、切分样本，并同步梯度；tensor parallel（TP）切分单个矩阵/attention heads，中间需要 all-reduce/all-gather；pipeline parallel（PP）按层分 stage，以 microbatch流水；expert parallel（EP）把不同 experts放到不同 ranks，token按路由跨rank all-to-all到目标expert。

## EP 数据流

每个rank先持有一部分输入token和router结果，按目标EP rank分桶；第一次 all-to-all发送隐藏状态与元数据，目标rank在本地expert做grouped GEMM；第二次 all-to-all把输出发回源rank，再按原序列combine。EP切的是“参数分支”，不是固定token或矩阵维。

## 如何组合

大模型常形成多维网格。DP组间复制一套专家集合并同步对应expert梯度；EP组内每rank持不同expert；每个expert自身太大时再用TP切分；层太多用PP。总world size不是四者简单随便相乘，rank映射、组大小与专家数需可整除或定义复制。

例如 64 GPU 可设 DP=2、PP=4、EP=8（此例不再叠TP），每个DP副本有4个pipeline stage，每stage的MoE层在8个EP ranks间分expert。若某层只有4个KV heads或expert数不整除8，需复制/特殊映射。

## 通信差异与取舍

DP主要在反向做参数梯度归约，TP每层有规则collective，PP在相邻stage传激活，EP流量由数据依赖的路由决定、负载不规则。EP最好放在高带宽域内，跨慢网络all-to-all代价大。多种collective重叠不当还会竞争同一链路。

## 常见误区与面试要点

EP不是“每卡一个完整模型只跑某专家”，dense attention等参数仍需按其他并行方式放置。面试应先说清每种切分对象，再描述EP两次all-to-all与组合网格。
