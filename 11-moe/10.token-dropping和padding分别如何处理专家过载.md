# 10. token dropping 和 padding 分别如何处理专家过载？

## 两种机制

固定容量把每个 expert 表示成最多 \(C\) 个槽位。Padding 是对负载不足的 expert 补空槽，使所有专家形成规则 \([E,C,d]\) 张量和等形 GEMM；token dropping 是对负载超过 \(C\) 的 assignment 截断。前者处理“不足”，后者处理“超额”，常在同一容量受限实现中同时存在。

## 数据流

Router 得到 expert id 与 gate。系统按 expert 分桶并为每个 assignment 计算槽位序号。若 slot \(<C\)，写入 dispatch buffer；否则标为 overflow。Expert 对满尺寸 buffer 计算，空槽由 mask 清零；combine 只取真实槽位，并把 dropped 路径按策略处理。

Top-1 token 若被 drop，有的实现让 MoE 分支输出零、仅保留 residual/shared expert；top-2 可保留未溢出的另一条路径或尝试 reroute。不能说“drop 就丢掉整个 token”，通常 token 仍沿 Transformer 残差前进，只是缺一条专家变换。

## 取舍与偏差

规则 padding 便于静态 shape、批量 GEMM 和编译，但 \(\alpha\) 越大、路由越不均，空算越多。Dropping 控制最坏计算和通信，却会使高频路由群体得到较少专家处理，产生有偏训练；按 gate 分数保留高分 assignment 比按输入顺序截断合理，但可能让低置信长尾更常被丢。

替代方案包括提高容量、第二选择、随机/优先级 reroute、dropless variable-size expert batch。Dropless 保质量但慢 expert 决定 step 时间，且需要不规则 grouped GEMM。

## 监控和面试要点

记录 padding ratio、各 expert 实际/容量、drop token 与 drop assignment 两种比例、哪些语言/任务被丢，以及 residual 后的影响。常见误区是把 padding token 与 tokenizer 的 PAD 混淆：这里是专家 buffer 的空槽。

面试回答应明确“padding 对齐负载不足、dropping 截断负载过多”，再讲规则计算、质量偏差和 dropless 备选。
