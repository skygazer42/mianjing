# 04. top-1 和 top-2 routing 有什么区别？

## 结论先行

Top-1 为每个 token 只执行分数最高的一个 routed expert，计算、dispatch 流量和专家状态读取最少；top-2 同时执行两个专家并按 gate 权重合并，增加计算与通信，但通常提供更高容量、路由容错和更平滑的学习信号。它们的优劣不能只看 \(k\)：还受 expert 宽度、shared expert、容量、重归一化方式和硬件实现影响。

## 公式与数据流

Router 得到概率 \(p=\operatorname{softmax}(W_rx)\)。Top-1 输出近似为

\[
y=E_{i^*}(x),\qquad i^*=\arg\max_i p_i,
\]

也有实现保留 \(p_{i^*}\) 作为缩放。Top-2 选择 \(i_1,i_2\)，常写成

\[
y=\tilde p_{i_1}E_{i_1}(x)+\tilde p_{i_2}E_{i_2}(x),\quad
\tilde p_i=\frac{p_i}{p_{i_1}+p_{i_2}}.
\]

Top-2 会把 token dispatch 两份；返回后按原 token 索引 scatter-add。若容量按 assignment 数计算，平均负载从 \(T/E\) 变为 \(2T/E\)，通信字节和专家 FLOPs也近似翻倍。

## 具体例子与取舍

若 64 个专家、每个 token 的前两名概率为 0.52 和 0.46，top-1 的决策对小 logit 扰动很敏感；top-2 可同时利用二者，输出更连续。若第一专家已过载，部分系统还可尝试第二选择，降低 drop。但若两个专家高度相似，第二路径只是重复计算；低 batch 时每个 expert 的微批更碎，实际延迟可能高于理论两倍。

Top-1 常适合极致推理吞吐或已有 shared expert 提供公共能力的架构；top-2 更适合愿意用额外激活计算换质量和鲁棒性的训练。公平比较应固定总激活 FLOPs：top-2 可把每个 expert 做窄，而不是拿相同 expert 宽度直接对比。

## 常见误区与面试要点

Top-1 不等于 router 没梯度：选中 gate（若参与输出）、负载损失和 z-loss 仍可训练 router。Top-2 也不保证负载均匀，热门 token 的前两名可能仍集中在少数专家。面试回答应依次比较激活专家数、combine、容量/通信、质量容错和真实延迟。
