# 08. shared expert 和 routed expert 分别做什么？

## 结论先行

Shared expert 对所有 token 始终执行，承担通用知识和稳定的基础变换；routed experts 只对 router 选中的 token 执行，负责条件容量和差异化模式。二者输出通常相加或按门控组合。Shared 分支能减轻 routed expert 重复学习公共能力、降低 top-1 路由失误的伤害，但会增加每 token 固定 FLOPs，且不自动解决 routed experts 的负载不均。

## 计算形式

一种简化写法是

\[
y=E_{shared}(x)+
\sum_{e\in TopK(x)}g_e(x)E_e(x).
\]

也可有多个 shared experts、对 shared 分支再设 gate，或把一部分 FFN 中间维固定共享。必须查看具体架构：所谓 shared 并不一定与单个 routed expert 等宽。

若 64 个 routed experts 中 top-1，再加一个等宽 shared expert，每 token 实际执行两个 FFN；总专家参数约 \(65P_e\)，激活专家参数约 \(2P_e\)，不能宣传成只激活 1 个专家而忽略 shared 成本。

## 为什么有效

标点、基本语法、常用转换等模式对所有 token 都有用。没有 shared 分支时，多位专家可能各自复制这些能力，浪费条件参数；router 早期错误还会让 token 进入不合适专家。共享路径提供稳定梯度和兜底，routed 路径可更专注长尾差异。反过来，shared 过宽会吞掉大部分任务，router/expert 只学很小残差，条件计算收益下降。

## 系统取舍

Shared expert 可像 dense FFN 一样本地复制或做 tensor parallel，无需 token dispatch；routed 分支才走 expert parallel all-to-all。因此 shared FLOPs规则、利用率高，却在所有 token 上支付。部署比较要同时看固定 shared GEMM 与稀疏 routed GEMM，不能只算后者。

## 面试要点与误区

Shared expert 不是“热门专家”，它不经过竞争容量；routed expert 被所有 token 高频选择仍会过载。回答应覆盖公共/专门能力分工、输出合并、固定计算代价和训练兜底。

## 延伸追问

1. Shared expert 太强为什么可能导致 routed experts 欠训练？
2. Shared 与 routed 输出是否需要相同 gate/归一化尺度？
3. 如何通过消融判断 shared 分支学到的是公共能力而非冗余参数？
