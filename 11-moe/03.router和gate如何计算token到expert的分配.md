# 03. router / gate 如何计算 token 到 expert 的分配？

## 结论先行

router 通常用一个很小的线性层把 token 隐状态映射成 $E$ 个专家 logits，再经过 softmax 或其他打分，选 top-k 专家；dispatch 根据选择结果把 token 发到对应 expert，combine 再用路由权重合并输出。难点不在一行 `topk`，而在容量限制、负载均衡、数值精度和跨卡重排。

## 基本公式

对某层输入 token 表示 $x\in\mathbb R^d$，router 参数 $W_r\in\mathbb R^{E\times d}$：

$$
z=W_rx+b,\qquad p=\operatorname{softmax}(z)
$$

取分数最高的 $k$ 个专家：

$$
S(x)=\operatorname{TopK}(p,k)
$$

若对选中权重重新归一化：

$$
\tilde p_i=\frac{p_i}{\sum_{j\in S(x)}p_j},\quad i\in S(x)
$$

MoE 输出为：

$$
y=\sum_{i\in S(x)}\tilde p_iE_i(x)
$$

不同实现可能直接使用未归一化 top-k 权重、加入缩放因子、sigmoid gate 或 shared experts，不能只凭“top-2”推断完整公式。

## dispatch—expert—combine 流程

假设一个 batch 有 4 个 token、3 个专家、top-1 选择结果为：

```text
t0 -> e2
t1 -> e0
t2 -> e2
t3 -> e1
```

执行时通常先按 expert 排序：

```text
e0: [t1]
e1: [t3]
e2: [t0, t2]
```

对每个 expert 的 token 子批执行 FFN，然后按原 token 索引 scatter 回去。top-2 时每个 token 会复制到两个 expert，返回后按 gate 权重相加。跨设备 expert parallel 还要在排序后做 all-to-all，把 token 发到持有目标 expert 的 GPU。

router 参数量只有约 $Ed$，相对 expert FFN 很小；但它的一个决策会控制大规模计算与通信，因此数值和分布异常会被放大。

## 训练时如何处理 top-k 的离散性

`TopK` 对“哪些未选专家”不可微，但对已选路径中的 gate 权重和 expert 计算仍可反向传播。标准做法是让任务损失通过选中的 $\tilde p_i$ 更新 router，并增加负载均衡、router z-loss 等辅助项。未选专家对该 token 通常没有任务梯度，这也是路由早期偏置可能自我强化的原因。

一些实现加入 router jitter/noise，鼓励探索并打破专家平局；另一些采用 straight-through、soft routing 或不同的专家选择规则。关键是分清训练近似与推理时真正执行的稀疏路径。

## 容量约束

令本次路由 token 数为 $T$，专家数 $E$，top-k 为 $k$，期望均匀负载约为 $Tk/E$。固定容量常写成：

$$
C=\left\lceil \text{capacity\_factor}\times\frac{Tk}{E}\right\rceil
$$

这里把全部 top-k assignment 放进同一个容量池，所以均值是 $Tk/E$。另一些 top-2 实现会为第一、第二路由分别按 $T/E$ 设置容量，或把 $k$ 吸收到 capacity factor 的定义中；跨论文比较必须先统一计数口径。某 expert 接收超过 $C$ 时，系统需要丢弃/绕过溢出 token、路由到备选 expert，或动态扩展容量。容量太小损害质量，太大则 padding 和显存浪费；dropless 实现不设固定丢弃，但要承受不规则负载和尾延迟。

## router 精度与数值稳定

router softmax 对小的 logit 差异敏感，低精度舍入可能改变 top-k 排名。因此不少系统即使主体使用 BF16/FP8，也会让 router logits 或 softmax 保持更高精度。logits 过大还会使 softmax 饱和、梯度变差；router z-loss 会约束 `logsumexp` 的尺度。

还要正确处理：

- padding token 是否参与路由统计；
- 序列并行后负载统计是在本地还是全局；
- 相同分数的确定性 tie-breaking；
- top-k 权重是否重归一化；
- token 在 dispatch/combine 后顺序、梯度和 mask 是否对齐。

## 如何监控路由质量

至少记录每层、每 expert 的 token 数、gate 概率和选择频率，并观察：

- 最大负载 / 平均负载；
- expert 使用熵与从未被选中的 expert 数；
- 溢出、drop、reroute 和 padding 比例；
- router logits 范数、z-loss 和梯度；
- all-to-all 时间、最慢 expert 时间和 P99 延迟；
- 按语言、任务或 token 类型分桶后的路由分布。

负载均匀不等于语义路由正确，专业化也不等于系统高效；需要将路由指标与 loss、下游质量和硬件指标一起看。

## 面试回答要点

写出 `linear -> softmax -> top-k -> dispatch -> expert -> weighted combine`，说明 top-k 的离散性、容量和辅助负载损失。最后补充跨卡场景会产生 all-to-all，以及 router 常需要较高数值精度，这样才是完整的工程答案。
