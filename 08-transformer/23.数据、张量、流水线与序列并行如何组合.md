# 23. 数据、张量、流水线与序列并行如何组合？

## 结论

大模型并行不是四选一，而是把不同维度组成多维 mesh。数据并行复制模型、切 batch；张量并行切单层大矩阵；流水线并行切连续层；序列并行切 token/sequence 维上的激活与部分算子。组合目标是在显存可容纳的前提下，让计算占比高、通信可重叠、流水线气泡可接受。

## 各自通信

数据并行每个 rank 处理不同 micro-batch，反向后对梯度做 all-reduce；ZeRO/FSDP 进一步分片参数、梯度和优化器状态，以 all-gather/reduce-scatter 换显存。张量并行常把 attention/FFN 的列投影与行投影配对，层内需要 all-reduce 或 reduce-scatter，通信频繁，通常放在高速互联节点内。

流水线并行把层分到 stage，传递激活和梯度。micro-batch 数少时，部分 stage 等待形成 bubble；1F1B 等调度可降低峰值激活与气泡。序列并行常与张量并行配套，把 residual/norm/dropout 等原本复制的 `[B,S,d]` 激活沿序列切开，但 attention 的全局依赖可能需要 all-gather 或专门 context parallel 通信。

## 组合例子

64 张 GPU 可设 `DP=8, TP=4, PP=2`，三者乘积为 64。每个 DP 副本含 8 卡模型并行组；全局 batch 是各 DP rank 本地 micro-batch、梯度累积和 DP 数的乘积。若长上下文使单卡激活超限，可再在既有维度上引入 sequence/context parallel，但必须重新检查通信组映射。

## 工程取舍与误区

TP 太大时矩阵变小且每层 collective 占比上升；PP 太大气泡和跨节点激活通信增加；DP 太小会降低可用 batch 并让优化器分片空间不足。网络拓扑决定映射：高频 TP 通信优先 NVLink/NVSwitch，跨节点更适合 DP。Checkpoint 还需记录分片布局并支持世界大小转换。

## 面试回答要点

逐一回答“切什么、复制什么、何时通信”，再给乘积关系和拓扑映射。不要把 sequence parallel 与把不同样本分给不同卡混淆，后者仍是数据并行。
