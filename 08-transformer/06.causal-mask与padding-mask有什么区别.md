# 06. causal mask 与 padding mask 有什么区别？

## 结论

causal mask 约束信息方向，防止位置 (i) 看到未来位置 (j>i)；padding mask 屏蔽为了组成 batch 而补出的无效 token。两者解决不同问题，实际注意力中通常需要合并并正确广播。前者通常是下三角结构，后者由每条样本的真实长度决定。

## 公式与实现

在 softmax 前对 logits 加 additive mask：

\[
P_{ij}=\operatorname{softmax}_j\left(\frac{q_i k_j^\top}{\sqrt{d_h}}+M^{\text{causal}}_{ij}+M^{\text{pad}}_{j}\right).
\]

允许的位置 mask 为 0，禁止位置为 (-\infty) 或该 dtype 可安全表示的极小值。以长度 4 为例，causal 可见性依次是 `1000,1100,1110,1111`。padding mask 若样本真实长度为 2，则 key 位置 3、4 对所有 query 都不可见。训练 loss 还应另外忽略 padding 标签；只屏蔽 attention 并不会自动阻止 pad 位置参与损失。

## 常见陷阱

第一，布尔 mask 的语义在不同框架中可能相反：有的 `True` 表示保留，有的表示屏蔽。第二，只屏蔽 key 轴时，padding query 仍会产生输出，通常靠 loss mask 丢弃；若下游会读取这些输出，还需 query mask。第三，左 padding 会让 position id 与 cache offset 更复杂，不能简单用 batch 下标当位置。第四，半精度中直接填一个超出表示范围的常数可能产生 NaN。

## 工程取舍

现代 fused attention 常不显式构造 `[S,S]` 矩阵，而把 `is_causal` 和每条序列长度传给内核，以节省显存并跳过无效块。packed sequence 还要用 block-diagonal mask 防止不同样本相互注意。decode 单 token 时，因果关系常由“只传历史与当前 K/V”天然保证，但变长 batch 仍需要长度元数据。

## 面试回答要点

明确回答“一个防未来泄漏，一个防补齐污染”，说明在 logits、softmax 前合并，并补充 loss mask 与框架布尔语义，基本就覆盖了正确性重点。
