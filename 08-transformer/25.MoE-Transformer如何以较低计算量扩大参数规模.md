# 25. MoE Transformer 如何以较低计算量扩大参数规模？

## 结论

Mixture-of-Experts 通常把每层或部分层的密集 FFN 替换成多个专家 FFN，router 为每个 token 选择 top-k 专家。总参数随专家数 (E) 增长，但每 token 只激活 (k\ll E) 个专家，所以激活计算远低于把全部专家都跑一遍。它扩大的是条件容量，不代表训练和部署成本与小模型完全相同。

## 路由计算

router 产生 \(p=\operatorname{softmax}(W_rx)\)，选择 top-k 专家集合 \(\mathcal E(x)\)，输出可写为

\[
y=\sum_{e\in\mathcal E(x)}\tilde p_e\,\operatorname{FFN}_e(x).
\]

其中 \(\tilde p_e\) 是专家 \(e\) 被选中后的组合权重，通常由原 router 概率在 top-k 集合内重新归一化得到；有些实现保留原概率，必须以具体训练和推理约定为准。

token 先按专家分桶，通过 all-to-all 发送到拥有相应专家的设备，计算后再送回原位置。top-1 通信和计算较少，top-2 等可增加组合能力与鲁棒性。router 本身参数小，但其离散选择会造成负载不均。

## 负载均衡与容量

若大量 token 挤到少数专家，会出现设备尾部等待或超出 expert capacity。训练常加入 load-balancing auxiliary loss、router z-loss、噪声或容量约束。超容量 token 可能被丢弃、转到次选专家或使用 dropless 动态实现，各方案在质量、显存和通信上不同。辅助损失过强又会强迫均匀路由，损害专业化。

## 参数、显存与部署

虽然每 token FLOPs 近似只含 (k) 个专家，总专家权重仍要存储或分布到集群；推理小 batch 时请求触达的专家零散，权重读取与 all-to-all 可能使利用率很低。专家并行通常与 DP/TP/PP 组合，checkpoint、容错和量化也更复杂。报告 MoE 规模时应区分 total parameters 与 active parameters per token。

## 面试回答要点

用“router—top-k—dispatch/all-to-all—combine”说明完整路径，强调条件计算、负载均衡和通信瓶颈。常见误区是说 MoE 没增加显存，或把多个 attention head 称为专家；主流 MoE 专家通常是独立 FFN。
