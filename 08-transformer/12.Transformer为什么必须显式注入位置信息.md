# 12. Transformer 为什么必须显式注入位置信息？

## 结论

不带任何位置机制的自注意力对输入排列是等变的：若同时打乱 token 顺序，输出也只是以同样方式打乱，模型无法仅凭注意力区分“猫追狗”和“狗追猫”的次序。因而 Transformer 必须通过绝对位置向量、相对位置偏置、RoPE、ALiBi 等方式，把顺序或距离信息注入表示或注意力分数。

## 原理

设排列矩阵为 (P)，无位置输入的 QKV 都是逐位置共享线性投影，则

\[
Q(PX)=PQ(X),\quad K(PX)=PK(X),\quad V(PX)=PV(X).
\]

注意力满足

\[
\operatorname{Attn}(PX)=P\operatorname{Attn}(X),
\]

所以它知道 token 内容之间的匹配，却不知道哪个在前、相隔多远。因果 mask 本身会引入“只能看过去”的方向结构，但仅靠可见集合并不足以为每个距离提供细致且可泛化的表示，实际 decoder 仍使用位置机制。

## 常见路线

绝对位置 embedding 与 token embedding 相加，实现简单，但训练长度外的位置未学过；相对位置 bias 直接在注意力 logits 上加与距离有关的项；RoPE 旋转 Q/K，使点积依赖相对位移；ALiBi 加随距离变化的线性偏置。它们的参数量、长上下文外推和内核实现各有取舍，详细数学应在位置编码专题展开。

## 工程陷阱

padding、packed sequence、KV cache 和增量 decode 都要求 position id 与“真实序列位置”一致。左 padding 时不能把 padded tensor 的列号直接当位置；拼接多个文档时是否重置位置也必须与训练策略一致。位置错一位往往不会报 shape error，却会显著破坏生成质量。

## 面试回答要点

最有力的回答是给出“自注意力的排列等变性”，再比较位置注入的三个位置：输入表示、Q/K 变换、attention logits。不要把“并行计算”误说成丢失顺序的直接原因；真正原因是共享投影和无位置注意力的对称性。
