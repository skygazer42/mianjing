# 28. Attention 的二次复杂度有哪些常见优化路线？

## 结论

标准全局 attention 对长度 (S) 计算 (S\times S) 相关性，时间约 (O(S^2d))。优化路线可分为三类：不改变数学结果、只优化 IO 的精确内核；限制可见连接的稀疏/局部注意力；用核化、低秩或压缩记忆近似全局交互。选择时要区分训练/prefill 的二次计算与 decode 的历史读取成本。

## 三类方法

第一类以 FlashAttention 为代表，通过分块和在线 softmax避免物化完整分数矩阵，显存 IO 显著下降，但理论 FLOPs 仍是二次。

第二类让每个 token 只看窗口 (w)、块或少数全局 token，复杂度可到 (O(Swd))。滑窗适合局部相关任务，但远距离信息需要多层传播或全局锚点；block sparse 必须有硬件友好模式，否则理论稀疏不等于实际快。

第三类将 softmax attention 近似改写，如先聚合 \(\phi(K)^\top V\)，再计算 \(\phi(Q)(\phi(K)^\top V)\)，获得接近线性复杂度；也可对 K/V 下采样、聚类、低秩投影或使用外部/递归记忆。这些方法改变归一化或丢失细节，长程检索质量与数值稳定性需实测。

## 其他视角

跨设备 context parallel 并未减少全局 FLOPs，只是分摊序列和显存，并引入 K/V 环形通信。位置外推只扩大“允许输入的长度”，也不会自动降低 attention 计算。decode 有缓存时每步单 query 对历史 (S) 做 (O(Sd)) 读取，服务瓶颈常是 KV 带宽而非构造 (S^2) 矩阵。

## 评估与误区

应同时测精度/困惑度、needle retrieval、端到端延迟、峰值显存和目标硬件吞吐；很多算法的渐近复杂度更好，却因常数、kernel 缺失或通信而在常用长度更慢。不要把 FlashAttention、线性注意力和 KV cache 混称为同一种“降复杂度”。

## 面试回答要点

先指出二次项来源，再按“精确 IO、稀疏连接、近似重排”分类，最后区分 prefill 与 decode，能体现算法和系统两方面理解。
