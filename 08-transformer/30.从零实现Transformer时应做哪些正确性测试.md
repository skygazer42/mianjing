# 30. 从零实现 Transformer 时应做哪些正确性测试？

## 结论

正确性测试应从数学不变量、参考实现对齐、梯度、mask 和增量行为逐层建立，而不是只看训练 loss 最终会不会降。深度模型可能在有轻微 bug 时仍然学习，却损失性能或在特殊输入崩溃；小而确定的单元测试能在训练前发现这些问题。

## 最小测试矩阵

首先做形状测试：随机组合 `B,S,d,h`，确认拆头/合头互逆，输出 dtype/device/shape 正确，非连续输入也能处理。其次做 mask 测试：改变未来 token 后，较早位置输出必须完全不变；给 padding token 换任意内容，有效位置输出应不变；packed 样本之间不得互相影响。

数值测试使用极小 FP64/FP32 参考实现，对比 QKV、logits、概率、单头输出和完整 block；softmax 每行和应为 1，禁止位置概率为 0。对 LayerNorm/RMSNorm 检查目标均值/均方根和 epsilon；对 dropout 固定 RNG 测训练模式，并验证 eval 模式确定。

## 梯度与训练测试

对几维小张量使用有限差分或框架 `gradcheck` 检查 QKV、norm、激活的反向；确认 weight tying 时梯度确实共享。用两三条序列做单 batch 过拟合，loss 应显著下降。保存—加载 checkpoint 后，同输入 logits 必须一致；梯度累积 `k` 个 micro-batch 应与等效大 batch 在容差内一致。

## 推理一致性与边界

eval 模式下，整段 forward 各位置 logits 应与逐 token 增量执行的对应 logits 对齐；测试 `S=1`、全 padding（若接口允许，应明确定义）、最大长度、左/右 padding、不同 batch 长度。BF16/FP16 与 FP32 只要求合理误差，不应按 bitwise equality；分布式与融合内核也要对参考路径做容差测试。

## 面试回答要点

最好给出两个强不变量：“未来 token 改变不影响过去输出”和“full forward 等于逐步 forward”。再补 shape、参考数值、gradcheck、单 batch 过拟合和 checkpoint 往返，即构成可落地的测试体系。
