# 29. 如何定位 Transformer 实现中的 loss 不降与 NaN？

## 结论

定位应先证明数据与目标正确，再缩小到单 batch 过拟合、逐层数值和优化器更新，不能一上来盲调学习率。loss 不降常见于标签错位、mask 泄漏/全屏蔽、参数未进 optimizer、学习率调度错误；NaN 常由 softmax、norm、混合精度溢出或异常样本触发。

## 分层排查步骤

1. 固定随机种子，取 1—8 条样本打印 token、attention mask、position id、labels 与 ignore 区域。确认位置 (t) 的 logits 对应标签 (t+1)，EOS/padding 正确。
2. 用 FP32、无 dropout、单卡让一个 micro-batch 过拟合到极低 loss。做不到说明是模型/数据正确性，不是规模或泛化问题。
3. 与框架可信算子或极小 NumPy/PyTorch 参考实现对齐 attention，检查 QKV reshape、head transpose、缩放和 causal 方向。
4. 注册统计记录每层输入输出 RMS、最大值、非有限比例、梯度范数和参数更新范数，定位第一个异常层。
5. 检查 optimizer 参数组、`zero_grad/backward/step` 顺序、梯度累积除数、scheduler 单位与断点恢复状态。

## NaN 专项

用稳定 softmax、FP32 norm/归约，确认没有全 mask 行；FP16 先 unscale 再 clip 并在非有限时跳步。暂时关闭 fused kernel 可帮助获得更清晰栈，但最终还要对比融合/非融合输出误差。二分层数或 batch 数据能快速区分结构性与样本触发问题。

## 常见假象

loss 低得异常可能是未来 token 泄漏或训练/验证重复，并非成功；loss 轻微抖动不一定异常，应看 token 加权移动平均。梯度非零也不表示参数更新：权重可能被冻结、未注册成 Parameter、更新被 loss scale 跳过或学习率实际为零。

## 面试回答要点

回答成一条可执行证据链：数据对齐→单 batch 过拟合→参考实现→逐层统计→优化器。给出“第一个出现非有限值”的定位原则，比罗列几十个可能原因更有工程价值。
