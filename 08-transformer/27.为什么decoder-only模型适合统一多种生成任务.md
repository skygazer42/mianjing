# 27. 为什么 decoder-only 模型适合统一多种生成任务？

## 结论

decoder-only 把几乎所有任务都表述为“给定一个 token 前缀，预测后续 token”，同一架构、同一损失和同一推理接口即可覆盖续写、问答、翻译、代码与工具调用。统一表示降低了数据混合和规模化训练的工程复杂度，也使模型能通过提示和上下文示例在参数不更新时切换任务。

## 概率视角

将指令 (I)、输入 (X) 和输出 (Y) 序列化，模型学习

\[
p(I,X,Y)=\prod_t p(z_t\mid z_{<t}).
\]

在监督微调中常仅对 (Y) 区域计算 loss，本质上优化条件概率 (p(Y\mid I,X))，但 prompt 仍参与因果上下文。特殊 token、角色模板和明确分隔符把结构化协议编码为普通序列；工具调用也可生成满足 schema 的文本或 token。

## 为什么有 in-context 能力

自注意力能在前缀中读取任务描述、若干输入输出示例和当前问题，深层网络可从这些模式中推断当前应执行的映射。它不是在推理时真正做常规梯度更新，更准确地说是条件计算与模式匹配/隐式推断。能力需要足够规模、训练数据中的任务多样性和合适的上下文格式。

## 代价与边界

统一接口不等于每个任务最高效。检索 embedding 用 encoder 一次前向往往更便宜；源到目标任务用 encoder-decoder 可双向编码源且复用表示；长 prompt 会消耗上下文和 prefill 计算。decoder-only 还存在逐 token 生成延迟、错误累积和结构输出不合法问题，需要约束解码、验证器或专用头补充。

## 常见误区与回答要点

不能把成功全部归因于 causal mask，数据规模、目标一致性和模型容量同样关键；也不能说它“天然理解所有任务”。面试应从统一概率建模、统一数据接口、in-context 条件化讲优势，再主动给出表征任务和明确源目标任务的取舍。
