# 21. 滑动窗口、淘汰与 StreamingLLM 类策略有何区别？

## 结论

对标准全局 attention，任意删除旧 KV 会改变模型函数，因为未来 query 原本可能关注这些 token。安全淘汰需要模型本身使用有限滑动窗口，或接受有依据的近似策略。纯滑窗只保留最近 (W) 个 token；StreamingLLM 类方法还保留序列开头少量 attention sink token，再加最近窗口，以改善流式稳定性。

## 滑动窗口

若第 (t) 个 query 的 mask 定义只允许 (n\in[t-W+1,t])，那么更早 KV 永远不可见，可以物理回收，单请求 cache 上限变为约 (W)（加特殊全局 token）。这必须与模型训练/架构一致；给全局 attention checkpoint 强行设窗口会丢失远距离能力。

## attention sink 直觉

一些自回归模型把较多注意力分配给开头 token，即使其语义不重要，可把它视为 softmax “汇流”位置。简单滚动删除开头会使注意力分布剧烈漂移。StreamingLLM 保留最初若干 sink KV 与最近窗口，中间历史淘汰，在无需微调的设置中改善长时间流式生成稳定性；它仍是近似，并不能回忆被删掉的中间事实。

## 位置处理

淘汰物理块后，剩余 KV 的逻辑位置如何处理依位置编码方法。已旋转 K 若整体重编号，需重新旋转/做位置变换；只移动物理槽而保留逻辑 position 更简单，但超长 position 仍继续增长。具体 streaming 方法可能采用 cache position rolling，必须与官方实现一致。

## 其他淘汰策略

可按 attention score、token 重要性、层差异压缩/选择 KV，或把旧信息汇总成 memory token。这些都改变计算，需在困惑度、长程检索、事实一致性与真实对话上评估。LRU 适合跨请求 prefix cache，不适合在单个全局序列内直接判断语义可删性。

## 面试回答要点

明确“架构滑窗可精确回收，任意淘汰是近似，sink+recent 保稳定但不保被删记忆”。不要把 cache 淘汰宣称为无损内存优化。
