# 28. 如何完成一道 KV Cache 显存估算题？

## 题目与结论

假设 decoder 有 40 层，query heads 32，KV heads 8，head dimension 128，KV 用 BF16；同时服务 12 个请求，每个实际缓存 8192 token。忽略分页浪费时，KV Cache 约为 15 GiB。解题关键是使用 KV heads 而不是 query heads，并明确 GiB 与 GB。

## 逐步计算

单 token、单层的 K 与 V 元素数：

\[
2\times H_{kv}\times D_h=2\times8\times128=2048.
\]

BF16 每元素 2 bytes，所以单 token、单层为 4096 bytes；40 层为

\[
4096\times40=163840\text{ bytes}=160\text{ KiB/token}.
\]

总 token 数 `12*8192=98304`，因此

\[
163840\times98304=16106127360\text{ bytes}=15\text{ GiB}.
\]

若误用 32 个 query heads，会高估为 60 GiB，正好差 GQA sharing factor 4。

## 加入实际开销

若 block size 16，每请求恰好 8192 可整除，没有尾块浪费；若长度是 8193，则每请求需 513 blocks，最后块只用 1/16，需按分配 token `513*16` 计。量化 INT8 时主数据理想减半，但需加 scales、对齐和可能的高精度尾块。TP=4 若 KV heads均匀分片，每卡理想 3.75 GiB；若存在复制则按物理 heads修正。

## 预算不能到总显存

GPU 还放权重、临时 workspace、通信 buffer、CUDA graph池和 allocator余量。应先从可用显存扣除这些，再用每 token 160 KiB 除，得到可承载物理 token 容量，并留安全 watermark。

## 面试回答要点

现场按“每层每 token→全层→总 token→单位转换→碎片/并行修正”计算，边写单位。无需心算到最后一字节，但必须把因子 2、Hkv 和 dtype 算对。
