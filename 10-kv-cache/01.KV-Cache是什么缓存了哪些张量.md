# 01. KV Cache 是什么，缓存了哪些张量？

## 结论

KV Cache 是自回归推理时按请求保存的中间状态：对历史每个 token、每一层 attention，缓存线性投影后的 Key 和 Value。生成新 token 时只计算该 token 的 Q/K/V，把新 K/V 追加到缓存，再让新 Q 读取全部可见历史。它缓存的不是原始 token、attention 概率或整层隐藏状态。

## 数据流

第 (l) 层历史隐藏状态 (X_{1:t}^{(l)}) 经投影得到

\[
K_{1:t}^{(l)}=X_{1:t}^{(l)}W_K^{(l)},\qquad
V_{1:t}^{(l)}=X_{1:t}^{(l)}W_V^{(l)}.
\]

生成位置 (t+1) 时只计算 (q_{t+1},k_{t+1},v_{t+1})，并执行

\[
o_{t+1}=\operatorname{softmax}\left(q_{t+1}[K_{1:t};k_{t+1}]^T/\sqrt{d_h}\right)[V_{1:t};v_{t+1}].
\]

每层都有自己的 K/V，因为各层输入隐藏状态和投影权重不同，不能只缓存模型最后一层。

## 缓存内容细节

使用 RoPE 的模型通常在写入前把 K 按逻辑 position 旋转，V 不旋转；使用 MQA/GQA 时缓存的是较少的 KV heads，而非扩展到 query head 数后的副本。物理实现可连续存储，也可按固定 token block 分页，逻辑含义不变。

## 生命周期

prefill 一次产生 prompt 所有 token 的 K/V；decode 每接受一个 token 就追加一格。请求完成、取消或被淘汰后，其块应释放；公共 prefix 可通过引用计数跨请求共享。cache 与模型权重版本、adapter、位置配置和 token 序列绑定，不能只因文本看似相同就盲目复用。

## 面试回答要点

回答应包含“逐层、逐 token、投影后的 K/V、按请求持有、decode 追加”。常见误区是说缓存 attention matrix：每个新 query 的注意力权重不同，历史分数无法直接通用缓存。
