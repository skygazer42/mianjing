# 12. PagedAttention 解决了什么问题？

## 结论

PagedAttention 借鉴操作系统虚拟内存：把每条序列的逻辑 KV 空间切成固定大小的 token blocks，通过 block table 映射到不连续物理显存。attention kernel 按映射读取这些块，避免为最大长度连续预留与扩容搬迁，从而提高 KV 显存利用率，并为共享、copy-on-write 和细粒度调度奠定基础。

## 工作流程

假设 block size 为 16 token，请求逻辑位置 0—15 对应逻辑块 0，16—31 对应块 1。调度器从全局 free list 分配物理块，例如逻辑块 `[0,1,2]` 映射到物理 `[7,42,5]`。写 token (t) 时用 `logical_block=t//16` 查表，再用 `offset=t%16` 定位槽；读取历史 attention 时 kernel 按逻辑顺序遍历 block table。

## 它优化什么、不优化什么

它主要优化容量管理和内存碎片，不改变标准 attention 的数学结果，也不把单 query 扫描 (S) 个 KV 的复杂度降为常数。间接收益包括容纳更多并发、减少预留浪费、请求完成后快速回收，以及 prefix/beam 共享。地址间接访问会增加少量 table lookup，需专门 kernel 保持合并访存。

## 与 FlashAttention 区别

FlashAttention 关注训练/prefill 中 attention 中间矩阵的 HBM IO，通过分块在线 softmax算同一结果；PagedAttention 关注推理 KV 的存储与寻址。二者都使用“block”概念但解决不同层面，可以组合使用。

## 工程边界

block table、引用计数和 free list 必须与 GPU kernel 同步；取消请求、抢占和异常回滚若漏释放会逐渐耗尽池。block size 影响碎片与性能，物理块虽不连续，单块内部仍需符合 dtype、head 和向量化对齐。

## 面试回答要点

用一条逻辑到物理映射例子，明确它解决预分配/碎片而非降低 attention FLOPs，并与 FlashAttention 分开，答案就足够完整。
