# 08. MHA、MQA、GQA 对 KV Cache 有什么影响？

## 结论

三者主要区别在 KV head 数。MHA 每个 query head 都有独立 K/V head；MQA 让所有 query heads 共享一个 K/V head；GQA 把 query heads 分组，每组共享一个 K/V head。KV Cache 与 (H_{kv}) 成正比，所以 MQA/GQA 能显著降低容量和 decode 读取带宽。

## 形状与倍率

设 query heads (H_q=32)、head dimension (D_h=128)。MHA 的 `Hkv=32`；MQA 的 `Hkv=1`，cache 理论上是 MHA 的 1/32；若 GQA `Hkv=8`，则是 MHA 的 1/4。Q 投影与 Q heads 仍可保持 32 个，attention 时第 (j) 个 Q head读取对应共享 KV group。

显存公式为

\[
M=2L N_{tokens}H_{kv}D_hb,
\]

因此节省不仅让同卡容纳更多并发，也减少每生成 token 扫描历史 K/V 的字节，常直接改善带宽受限 decode。

## 质量与性能取舍

独立 KV heads 提供更多 key/value 表示子空间；完全共享的 MQA 可能带来质量损失。GQA 在共享倍率与质量之间折中，且可从 MHA checkpoint 通过合并/继续训练转换，但不是简单在推理时平均 K/V 权重就保证无损。内核若不原生支持 GQA而物理重复 K/V 到 (H_q)，会丢失缓存和带宽优势。

## 工程细节

张量并行时 `Hkv` 可能小于并行度，需要复制少量 KV heads 或采用不均匀分片；容量估算要按物理复制后的数量修正。RoPE 对每个实际 KV head 旋转一次，再逻辑共享。

## 面试回答要点

用具体 `32→8→1` 例子和公式回答，强调节省的是 KV heads 与读带宽，而 Q heads/模型 hidden size 不必同比减少。不要把 GQA 说成把连续 token 分组，它分的是 query heads。
