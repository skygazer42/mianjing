# 02. KV Cache 为什么能加速自回归解码？

## 结论

没有缓存时，为生成第 (t) 个 token，每一步都把长度 (t) 的完整前缀重新经过所有层，历史 token 的 K/V 投影和历史间 attention 被重复计算。使用 KV Cache 后，历史 K/V 只算一次，新一步只处理一个新 token，并用它的 Q 扫描历史缓存，显著减少重复 FLOPs。

## 复杂度直觉

若每次都 full forward，生成 (T) 个 token 的 attention 相关性开销近似

\[
\sum_{t=1}^{T}O(t^2d)=O(T^3d),
\]

且每层投影/FFN 对历史也反复执行。缓存后，第 (t) 步只有一个 query 对 (t) 个 keys，attention 约 (O(td))，总计

\[
\sum_{t=1}^{T}O(td)=O(T^2d),
\]

更重要的是历史 token 的 QKV/FFN 不再重算。单步仍随上下文长度线性读取 K/V，KV Cache 并没有把长上下文 decode 变成严格 (O(1))。

## 为什么实际可能带宽受限

decode 每步矩阵形状小，需要读取模型权重以及逐层历史 KV，算术强度低。缓存省掉计算，却增加显存占用和内存访问；在长上下文、高并发时，读取 KV 的带宽可成为瓶颈。MQA/GQA、KV 量化和连续批处理就是针对容量/带宽而非数学重复计算的进一步优化。

## 具体例子

prompt 1000 token 后生成第 1001 个位置：无缓存会再次计算前 1000 个 token 在每层的 K/V 与 FFN；有缓存只计算新 token 的投影，将一个新 K/V 追加，再用单个 Q 读取 1001 个 K/V。下一步只多一个缓存槽。

## 面试回答要点

需说出“历史投影/层计算只做一次”和“单步从重算前缀变成单 query 扫历史”，同时指出显存随长度增长、单步仍是 (O(t))。只说“空间换时间”太泛，最好给出总复杂度变化与带宽瓶颈。
