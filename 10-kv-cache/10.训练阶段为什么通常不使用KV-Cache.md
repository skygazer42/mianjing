# 10. 训练阶段为什么通常不使用 KV Cache？

## 结论

标准 teacher-forcing 训练已知完整序列，虽然使用 causal mask，各位置 Q/K/V 仍可一次并行计算；KV Cache 的逐步追加会把序列维串行化，降低 GPU 利用率。训练还需为反向传播保留计算图，缓存历史 K/V 不能像推理那样 `detach` 后长期复用，因此通常没有收益。

## 并行性解释

训练输入 `[B,S,d]`，一轮矩阵乘同时得到全部位置 Q/K/V，attention 一次计算下三角分数。若模仿推理从位置 1 循环到 S，每步只处理一个 token，会启动大量小 kernel，总 FLOPs 未必少，且每步依赖前一步层输出，失去序列并行优势。

## 梯度问题

推理 cache 中的 K/V可视为常量；训练时后续位置的 loss 会通过 attention 回传到历史 K/V、投影权重和历史隐藏状态。若将 cache detach，会截断跨位置梯度，目标函数改变；若保留完整 autograd graph，历史激活仍要保存，不能获得推理式显存节省，反而增加状态管理。

## 例外场景

超长序列的 truncated backprop、Transformer-XL 式 segment recurrence 可缓存前段 memory 并停止梯度，属于明确改变训练依赖的算法；在线/强化学习生成阶段会用 KV Cache 采样，再对收集到的序列另做并行训练；prefix tuning 或固定前缀也可能预计算不参与梯度的部分。它们不能证明常规 CLM 训练应开启 `use_cache=True`。

## 工程注意

许多框架在 gradient checkpointing 时自动禁用 `use_cache`，因为缓存输出与重算/反向语义冲突。误开可能导致显存异常、旧 cache 跨 batch 泄漏或梯度错误。

## 面试回答要点

回答要同时说“完整序列可并行”和“训练需要跨历史反向图”，再给 segment recurrence 作为例外。不要误说 causal 模型训练也必须逐 token，因此自然需要 cache。
