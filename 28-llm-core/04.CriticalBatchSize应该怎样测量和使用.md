# 04. Critical Batch Size 应该怎样测量和使用？

    ## 结论先行

    Critical Batch Size 是“继续增大 batch 后，单位样本带来的优化收益开始明显递减”的量级，不是显卡能塞下的最大 batch。正确做法是固定模型、数据配方和目标 loss，测量不同 batch 到达目标所需 token/样本与 wall-clock，然后找拐点。GNS 可作为先验，但最好直接做短跑测量。实验在投诉分流任务中手写逻辑回归训练，比较 batch 1、2、3、6 的最终 loss 与达到目标的样本数。小样本不提供可迁移的 CBS 数字，只演示测量方法和线性学习率失稳这一失败模式。

    ## 公式与具体例子

    若 batch 从 $B$ 增至 $kB$，但到达同一 loss 所需样本数不再近似不变，则已越过有效并行区。可同时报告 $E(B)$（样本效率）和 $T(B)$（时间效率），而不是只报 throughput。

    具体到“支付重复扣款、陌生转账、盗刷冻结、登录验证码、地址修改、发票更正”六条工单：先用同一特征矩阵建立最朴素基线，再记录本题机制所改变的更新、尺度、梯度或调度量。Notebook 会把输入、每一步中间量和同一指标下的对照直接打印出来；它是机制实验，不是线上 A/B 结论。

    ## 工程取舍

    生产测量需固定 token budget、通信拓扑、混合精度和 sequence packing；否则吞吐差异可能来自系统而非优化。

    ## 常见坑

    只看每秒样本数，不看同目标 loss 的 token 数，会把更快但更浪费数据的设置误判为更好。

    ## 延伸追问

    CBS 随训练阶段变化时，如何做 batch warmup？为什么按样本数和按 token 数可能得到不同拐点？
