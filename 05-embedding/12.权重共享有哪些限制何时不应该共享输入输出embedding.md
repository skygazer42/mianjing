# 12. 权重共享有哪些限制，何时不应该共享输入输出 embedding？

## 核心判断

权重共享是有用的归纳偏置，不是普适规则。只有输入与输出使用同一符号集合、维度兼容，而且“编码该符号”和“预测该符号”适合共用几何时，收益才最稳。否则强行共享会制造不合理约束或复杂通信。

## 不适合共享的典型情况

1. **词表不同。** 机器翻译 encoder 的源语言词表与 decoder 目标词表不同，行无法一一对应。联合多语词表可共享，但同形 token 未必同义，仍需验证。
2. **维度不同。** 因子化 embedding 可能用较小 \(d_e\)，而隐藏宽度为 \(d_h\)。可通过投影共享，但多出的投影改变了参数与计算折中。
3. **角色冲突。** 输入向量需稳健编码长尾、噪声和组合结构，输出分类器要形成清晰决策边界；某些任务中分离矩阵能提供更高容量。
4. **输出集合不是输入 token。** 分类标签、动作、代码簿或候选实体与输入词表不同，自然不应共享。
5. **并行与更新策略冲突。** 例如输入表冻结、输出层需要快速适配，或两处采用不同量化/分片方案，共享会使优化和部署受限。

## 如何做证据化选择

比较时不能只看验证损失，还要记录参数量、训练吞吐、长尾 token 准确率和校准。可设置三组：完全不共享、直接共享、共享主矩阵但保留独立低秩适配器/输出 bias。若共享略降效果但大幅省内存，部署目标可能仍偏向共享；若目标是小词表高精度分类，参数节省不重要，分开更合理。

一个容易忽略的细节是 tokenizer id 对齐。两个词表字符串看似相同但 id 排列不同，直接引用同一矩阵会让行语义错位。迁移 checkpoint 时应通过词面映射重排行，而不是按索引硬接。

## 面试回答要点

先说明共享的三个前提：同词表、同维度/可投影、角色相容；再举源目标词表不同和输入冻结/输出适配两个反例。最后强调共享是容量与正则化的取舍，应该通过任务指标和系统成本共同决策，而非把“参数更少”误当作必然更好。
