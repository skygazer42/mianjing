# 04. Embedding 参数如何训练，反向传播时哪些行会收到梯度？

## 前向与反向

输入 embedding 的前向是 \(h_t=E[x_t]\)。若位置 \(t\) 的上游梯度为 \(g_t=\partial\mathcal L/\partial h_t\)，则该位置只给被选中的行累积梯度：

\[
\frac{\partial\mathcal L}{\partial E_i}
=\sum_{t:x_t=i}g_t.
\]

因此单看输入查表，本批未出现的行梯度为零，同一 id 出现多次则求和。自动微分通常用 scatter-add 完成反向；设置 padding_idx 后，框架一般会屏蔽 PAD 行梯度并保持其为零，但仍应核对具体实现和权重衰减行为。

## 为什么有时梯度又是稠密的

若语言模型用输出投影 \(z=hW_{\text{out}}^\top\) 对整个词表做 softmax，交叉熵对所有 logit 都有梯度：

\[
\frac{\partial\mathcal L}{\partial z_j}=p_j-\mathbf 1[j=y].
\]

所以 \(W_{\text{out}}\) 的更新通常是稠密的。输入输出权重共享时，同一个 \(E\) 同时收到查表路径的稀疏梯度和输出路径的稠密梯度。不能笼统地说“embedding 只有访问行被更新”，必须说明是哪条计算路径、是否做 full softmax。

## 优化器与分布式细节

小型推荐或超大稀疏词表可能使用 sparse gradient 与稀疏优化器，只维护被访问行的状态；Adam 若按整表保存一阶、二阶矩，优化器状态常是参数的两倍，实际内存远高于 \(Vd\)。大模型中输出层稠密、权重共享和张量并行使纯稀疏优化收益有限。重复 token 多的 batch 还会在 GPU scatter 时产生原子加和竞争，但常由高效内核处理。

## 常见问题

新增 token 若训练数据几乎不出现，行向量不会得到足够更新；冻结主干只训练新增行时，要确认梯度掩码没有误伤。混合精度下应关注稀有行更新过小、loss scaling 和 master weight。若 PAD 行出现非零范数，检查 padding_idx、权重衰减以及加载 checkpoint 后是否再次覆盖。

面试回答应同时说清公式、重复 id 的梯度相加、输出 softmax 造成的稠密更新，以及 optimizer state 和共享权重对工程判断的影响。
