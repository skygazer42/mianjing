# 23. Embedding 量化会怎样影响存储、吞吐和召回率？

## 核心结论

量化用更少比特表示向量，降低库容量、内存带宽和网络传输，有时还能借助整数指令提高相似度吞吐；代价是坐标、范数和排序产生误差，尤其相似度非常接近的候选容易换序。收益不能只按“FP32 到 INT8 理论缩小四倍”估计，还要包含 scale、zero-point、索引图和元数据。

## 常见方案

标量量化为每个向量、每维或每组学习比例，把浮点映射到 INT8/INT4。对称量化实现简单，非对称量化可适应偏移分布但需 zero-point。二值 embedding 只保留符号，Hamming 计算极快，表达损失更大。Product Quantization 则将子空间映射到码本 id，压缩更激进，并用查表近似距离。

若向量已 L2 归一化，量化会使重建向量范数不再恰好为 1；可以按索引实现决定是否重归一化，但库侧与查询侧必须一致。per-vector scale 更好保留每条相对形状，却可能改变跨向量范数比较；对最大内积检索尤其要谨慎。

## 评估方法

建立 FP32 exact 基线，再逐层比较：同一 embedding 的量化重建误差、exact-on-quantized 的 top-k 重合率、ANN-on-quantized 的召回，以及最终业务指标。这样可区分量化误差与 ANN 搜索误差。按查询难度、语言、文本长度和低 margin 样本分桶，因为总体 Recall@10 可能掩盖关键长尾退化。

常见部署是量化索引用于候选生成，保留 FP16/FP32 原向量对 top-N 重排，在内存与精度间折中。也可进行 quantization-aware training，让模型适应离散化噪声；仅在小校准集做后训练量化时，应覆盖真实范数和语言分布。

## 面试要点

给出存储近似公式 \(Ndb/8\) 字节，并指出实际还有 scale/索引开销；说明低比特减少带宽但不保证内核更快；最后用“浮点 exact → 量化 exact → 量化 ANN → 业务指标”的评估链路回答召回损失如何定位。
