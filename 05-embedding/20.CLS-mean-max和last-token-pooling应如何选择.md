# 20. CLS、mean、max 和 last-token pooling 应如何选择？

## 结论

Pooling 把变长 token 隐藏状态 \(H\in\mathbb{R}^{L\times d}\) 变成固定维向量。没有一种方法天然最好，选择取决于模型预训练结构、padding 方向、专门的句向量训练和任务。最重要的是正确应用 attention mask，并让训练、建库、查询使用同一策略。

## 四种方法

**CLS pooling**取专用 CLS 位置。编码器若在预训练/微调时明确让 CLS 汇聚全句，它高效且语义集中；没有此训练时，CLS 只是一个位置，不保证包含最佳句义。

**Mean pooling**计算有效 token 平均：

\[
e=\frac{\sum_t m_t h_t}{\sum_t m_t}.
\]

它利用所有位置、通常是可靠基线，但长句中无关词会稀释关键信息。必须排除 PAD，是否排除 BOS/EOS 需与训练设置一致。

**Max pooling**逐维取最大值，突出显著局部特征，却对异常激活敏感，并丢失频率/整体信息；负值维度和 mask 应用也容易写错。

**Last-token pooling**常用于 decoder-only 模型，因为因果注意力下最后一个有效 token 能读取全部前文。右 padding 时不能直接取数组最后位置；应按 mask 找每个样本最后有效索引。左 padding、EOS 是否追加以及截断都会改变该位置。

## 具体取舍

短关键词匹配可能从 max 获益，通用句义常以 masked mean 为强基线，经过专门指令/对比训练的 decoder 可能要求 last token。还可做 attention pooling 或多层加权，但增加参数和过拟合风险。长度差异大时，应检查 embedding 范数、性能随长度变化以及 truncation 对结果的影响。

## 验证与误区

不要在相同模型上只比较相似度样例，应固定训练和索引流程，用任务集报告 Recall@K、STS 或分类指标，同时 profile 延迟。Mean 后通常再按模型约定 L2 normalize；“先逐 token 归一化再平均”和“先平均再归一化”不是同一运算。混合 padding batch 应做单样本与批量输出一致性测试，能快速发现 mask 错误。

面试中应说清每种 pooling 的信息路径和适用模型，并特别指出 masked mean 与 last valid token 的实现细节。
