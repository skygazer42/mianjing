# 14. 扩充或替换词表后怎样初始化并训练新增 embedding？

## 先区分扩充与替换

扩充词表是在保留旧 token-id 映射的基础上追加新行，旧 checkpoint 可直接复用；替换 tokenizer 往往改变切分和 id 排列，即使词面相同也不能按原索引加载，风险大得多。无论哪种情况，都要同步 resize 输入表、输出 lm head、配置中的 vocab_size、特殊 token id 和权重共享关系。

## 初始化方法

新增行可随机按原表初始化分布采样，但少量继续训练时收敛慢。更稳的方法是把新 token 用旧 tokenizer 拆成若干片段，以这些旧行的均值或加权均值初始化，再加很小噪声打破完全相同；对于输出权重共享模型，这同时给出合理初始 logit。特殊协议 token 没有可组合语义，可用相近边界 token 均值或原分布随机初始化，关键是随后提供足够监督。

若替换整个 tokenizer，应按字符串和规范化规则建立可验证映射：完全相同的旧 token 复制；可分解的新 token 聚合旧片段；其余随机初始化。仅按 id 拷贝会静默错位。还需判断 byte token、空格前缀和 Unicode normalizer 是否语义等价，不能只比较显示字符串。

## 训练策略

第一阶段可冻结主干，只训练新增行和输出相关参数，让新符号进入已有空间；随后以较小学习率解冻部分或全部网络，避免主干因少数随机行受到冲击。训练语料必须让新 token 以足够频率、足够上下文覆盖出现，并混入通用数据以减少遗忘。可给新增行使用更大学习率，但要配梯度裁剪和范数监控。

## 验证清单

检查旧文本编码结果是否保持、模型能否生成新增 token、共享参数是否仍是同一对象、checkpoint save/load 后行数是否一致。分别统计新增/旧 token 的困惑度、频率分桶准确率、embedding 范数和最近邻；新行范数异常大可能污染 softmax，新行几乎不变则通常是数据或梯度掩码问题。

面试中最重要的回答不是“调用 resize_token_embeddings”，而是解释 id 兼容、初始化、两阶段训练和端到端验证；如果 tokenizer 大改，通常应评估继续预训练成本，而不是把扩词当作无损操作。
