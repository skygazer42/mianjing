# 25. 怎样离线和在线评估一个 embedding 模型？

## 评估框架

Embedding 没有脱离场景的单一分数。应先定义用途与候选集合，再同时评估语义质量、几何稳定、系统性能和线上价值。只看 STS 相关系数或几个最近邻，无法证明它在真实检索、聚类或去重中有效。

## 离线指标

检索任务以每个 query 的相关文档集合为真值，可报告 Recall@K、MRR、nDCG@K、Precision@K；多相关答案时 nDCG 比单一 MRR 更完整。语义文本相似度可看 Spearman/Pearson，分类可在线性探针或 kNN 下评估，聚类可看带标签的 ARI/NMI 和人工一致性。还需按语言、领域、长度、头尾查询、否定/数字等切片，给 bootstrap 置信区间。

系统层应区分 encoder latency/QPS、向量大小、索引构建时间、ANN recall（相对精确近邻）和端到端业务召回。一个模型可能 exact 检索优秀，却因维度太大或量化敏感而线上退化。

## 数据与基线

测试集要按时间或实体去重，避免同文改写泄漏；候选池大小必须接近生产，百条候选上的高分不能代表千万库。与 BM25、旧模型、随机/热门基线比较，并固定 pooling、metric 和索引参数。对阈值任务应画 ROC/PR、按成本选择 operating point，而非只报准确率。

## 在线实验

灰度或 A/B 测试关注最终行为：有效点击、成功率、人工解决率、下游转化和延迟/成本，并设置安全护栏。点击率受位置、展示和探索策略影响，需控制曝光偏差；新模型改变候选分布时，还要监控无结果率、重复率和长尾覆盖。线上显著性与实际效应大小都要报告。

## 回归与可观测性

建立版本化 golden queries、固定向量 checksum、近邻快照和漂移监控；新模型上线通常需要整库重编码。监控输入分布、向量范数、平均余弦、top-k 分数 margin 与语言占比，以便区分数据漂移、编码故障和索引问题。

面试回答可用“任务质量—几何/ANN—系统—在线价值”四层结构，并强调防泄漏、切片评估和置信区间。
