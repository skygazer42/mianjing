# 10. Word2Vec、GloVe、FastText 与 LLM embedding 有什么区别？

## 核心对比

Word2Vec、GloVe 和 FastText 主要学习静态词向量：一个词通常对应一个固定向量。LLM 的输入 token embedding 也是静态参数行，但它只是上下文化网络的起点；现代所谓 embedding 模型通常指用 Transformer 编码整句/文档并经 pooling 得到的上下文相关向量。四者不能仅按“新旧”排序，应从训练信号、粒度和用途比较。

## 三种经典方法

- Word2Vec 的 CBOW 用上下文预测中心词，skip-gram 用中心词预测上下文，常配负采样；它利用局部窗口共现。
- GloVe 从全局词—词共现计数出发，使向量点积拟合共现概率比值的对数，兼顾全局统计。
- FastText 把词表示为字符 n-gram 向量之和，能共享词形信息，并为未见过但可拆分的词构造表示；代价是形近未必义近，且子词哈希可能冲突。

它们通常以“词”为单位，难以直接处理一词多义。“bank”在河岸和银行语境中仍是同一静态向量。

## LLM 与句向量模型

LLM tokenizer 往往采用子词/字节粒度，输入行经过 self-attention 后得到随上下文变化的隐藏状态。通用生成 LLM 的末层隐藏状态并不天然是优质句向量，因为语言建模目标关注下一个 token，而非让相似句在全局空间靠近。专用 embedding 模型常在预训练编码器之上用对比学习、难负样本和 pooling 训练，优化检索或语义匹配。

## 场景取舍

经典静态向量体积小、推理快，在词级特征、资源受限或可解释邻词分析中仍有价值；FastText 对拼写变体和低资源语言尤其实用。上下文化模型计算更贵，却能表达语序、否定、多义和句级意图。比较时应控制词表覆盖、维度、训练语料和目标，不能把输入 token 表与经过专门训练的句向量输出混为一谈。

面试中可用一句话概括：Word2Vec/GloVe/FastText 学“词类型”的静态统计表示，Transformer 学“当前上下文中的 token 状态”，句向量模型再把序列表示针对相似度目标对齐。
