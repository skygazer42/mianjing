# 21. 向量检索中如何选择相似度函数并保证训练与索引一致？

## 核心原则

相似度不是索引层随手替换的配置，而是 embedding 模型定义的一部分。训练使用归一化余弦，建库却用未归一化内积，或者离线用精确 cosine、线上用 L2 且预处理不同，都会造成排序漂移。应把编码器版本、pooling、截断、后处理、维度、dtype 和 metric 作为同一个不可分割的向量协议。

## 选择逻辑

若训练分数为 \(\hat q^\top\hat d/\tau\)，文档和查询都做 L2 归一化后，用 inner product 或 cosine 索引等价；\(\tau\) 影响训练 softmax，但查询排序中除以固定温度不改变名次。若训练目标是未归一化 maximum inner product，范数可能携带信号，应选内积索引。若损失直接约束欧氏间隔，则优先 L2，并验证是否需要归一化。

模型未明确说明时，可以在带正负标注的开发集比较三种度量，但必须分别重建索引或严格转换。不能只根据若干手工例子选择，因为高频、长度和语言分布会影响范数。

## 一致性测试

保存一组 golden 文本，离线与线上分别编码，逐元素或按容差比较；随机抽样查询，比较暴力精确 top-k 与索引 top-k，拆分“embedding 模型误差”和“ANN 近似误差”。对 cosine，断言向量范数接近 1；对内积，监控范数分布漂移。还要验证批量/单条、CPU/GPU、FP32/低精度结果和 tokenizer 截断完全一致。

## 工程边界

ANN 库中 metric 名称的约定可能不同：有的返回相似度越大越好，有的返回距离越小越好，cosine distance 可能定义为 \(1-\cos\)。阈值服务若把符号方向弄反，会比 top-k 更隐蔽。量化、PCA、whitening 等变换必须同时用于库侧和查询侧，并纳入版本哈希；旧索引不能与新模型混用。

面试回答可用“训练几何决定线上 metric”开头，再给出单位向量时 cosine/IP/L2 的等价关系，最后说明 golden vector 与 brute-force 对账。这里讨论的是向量层协议，不涉及上层 RAG 的切块或生成策略。
