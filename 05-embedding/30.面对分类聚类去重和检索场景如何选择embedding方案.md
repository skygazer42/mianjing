# 30. 面对分类、聚类、去重和检索场景，如何选择 embedding 方案？

## 先明确任务几何

分类要求不同标签可分，未必要求全局语义距离完美；聚类要求簇内紧凑、簇间分离且密度可处理；去重关注极高相似区域的精确阈值；检索关注每个 query 的候选排序。相同 embedding 在四个任务上的最佳模型、维度、度量和评估可能完全不同。

## 场景选择

**分类**有充足标签时，直接微调编码器加分类头通常优于冻结通用向量；若标签少或需快速迭代，可用 embedding + 线性模型/kNN，并检查类别不均衡与 OOD 拒识。

**聚类**应优先选择能表达目标粒度的句/文档向量，归一化后比较 spherical k-means、HDBSCAN 等；簇数未知、密度不均时普通 k-means 的球形假设可能不适用。先降维用于可视化不等于应在降维空间正式聚类。

**去重**要区分精确、近似和语义重复。先用哈希处理完全相同，再用 embedding 召回候选，依据人工正负对标定阈值；高 precision 场景可用交叉编码器或规则复核。不同文本长度和模板需分桶阈值。

**检索**通常需要针对 query-document 对比训练的双编码器、可靠 hard negatives 和 ANN。模型是否对称、是否要求 query/document 前缀、用 cosine 还是内积必须遵循训练协议。

## 系统约束

维度越高，存储和延迟越大；多语言、长文本、更新频率、端侧/云端会改变选型。先以高精度模型做 exact 小规模基线，再逐步引入降维、量化和 ANN，分别测语义损失与系统收益。不要仅凭公开榜单，因为领域、候选规模和负例难度可能完全不同。

## 决策流程

定义业务错误成本和标注集；选两三个契合训练目标的候选模型；固定预处理比较离线指标；绘制质量—延迟—内存 Pareto 曲线；对最终方案做切片、压力与线上实验。发布时绑定模型和索引版本。

面试回答若能先指出四种任务的评价目标不同，再给出模型、metric、索引和阈值的证据化选择，会比“都用余弦相似度”更成熟。
