# 02. Embedding 矩阵的形状、查表和 one-hot 乘法如何对应？

## 结论与形状

词表大小为 \(V\)、模型宽度为 \(d\) 时，常把 embedding 表写成 \(E\in\mathbb{R}^{V\times d}\)：每一行对应一个 token id。输入 id 张量形状若为 \([B,L]\)，查表后得到 \([B,L,d]\)。有些框架或论文把线性层权重存为 \([d,V]\)，那通常是输出投影的布局；理解时应看乘法方向，而不要死记维度顺序。

## 查表为何等价于矩阵乘法

把 \([B,L]\) 的 id 展开为 \(N=BL\) 个 one-hot，组成 \(X\in\{0,1\}^{N\times V}\)，则

\[
H=XE\in\mathbb{R}^{N\times d}.
\]

由于 \(X\) 每行只有一个 1，结果恰好选择 \(E\) 的对应行。实际 embedding 算子用 gather 完成，复杂度近似 \(O(Nd)\)，而显式稠密乘法会达到 \(O(NVd)\) 并产生 \(NV\) 大小的无意义中间量。重复 id 会重复读取同一行；反向传播时这些位置对该行的梯度相加。

## 具体例子

若 \(V=4,d=3\)，输入 id 为 \([2,0,2]\)，输出就是 \([E_2,E_0,E_2]\)。设三个位置上游梯度分别为 \(g_1,g_2,g_3\)，则

\[
\frac{\partial \mathcal L}{\partial E_2}=g_1+g_3,\qquad
\frac{\partial \mathcal L}{\partial E_0}=g_2,
\]

本批没有出现的 \(E_1,E_3\) 梯度为零。分布式训练或稀疏优化器正是利用了这种访问模式，但在大语言模型里如果输入、输出权重共享，输出 softmax 通常又会给整张矩阵产生稠密梯度。

## 工程检查点

需要同时核对 padding_idx、词表 id 范围、dtype、设备以及是否共享输出权重。词表扩容但模型配置仍保留旧 \(V\)，会越界；tokenizer 与权重行顺序不一致则不会报错，却会产生灾难性的语义错位。计算参数量时还要看是否带输出 bias：纯输入表是 \(Vd\)，不共享的输出投影再增加约 \(Vd\)。

面试时应能从 id 形状一路推到输出形状、复杂度与梯度聚合，并指出“查表等价于 one-hot 乘法，但不是按稠密乘法实现”。
