# 11. 输入 embedding 和输出权重共享是什么，为什么有效？

## 定义

语言模型输入用 \(E\in\mathbb{R}^{V\times d}\) 将 token id 映射为向量，输出通常用 \(W_{\text{out}}\in\mathbb{R}^{V\times d}\) 将隐藏状态映射到词表 logits：

\[
z=hW_{\text{out}}^\top+b.
\]

权重共享（weight tying）就是令 \(W_{\text{out}}=E\)，同一张表既是“读入 token 的表示”，又是“用隐藏状态给 token 打分的原型”。若尺寸不一致，可加一层投影把隐藏状态变到 embedding 维度后再共享。

## 为什么可能有效

不共享时两张 \(V\times d\) 大矩阵各自学习，参数量翻倍，并且输入、输出语义空间没有显式联系。共享相当于施加结构化约束：能作为输入表达某 token 的方向，也用于判断该 token 是否应被预测。它减少约 \(Vd\) 参数，尤其大词表时明显；约束还可能起正则化作用，提高参数效率与泛化。

反向传播时共享矩阵同时接收两条信号。输入查表路径只累积本批出现 id 的梯度；输出 softmax 路径对所有词表行通常有稠密梯度。因此不能把共享表当成只受稀疏更新的普通 embedding。若训练框架错误地复制参数而非引用同一 Parameter，数值初始相同但后续会分叉，并不算真正共享。

## 代价和实现

共享要求输入表与输出分类器维度兼容，也把两个角色耦合起来。输入更关心“作为条件如何表示”，输出更关心“作为类别边界如何区分”，二者最优几何不一定完全相同。输出 bias 通常仍可独立保留，用来吸收词频先验。模型并行时共享还能减少存储，但要确保两处采用相同的词表分片或正确通信。

## 常见误区

- 权重共享不意味着输入向量和最终隐藏状态处在完全相同分布；中间网络及最终 norm 仍会变换它。
- 共享不会减少 full softmax 的 \(V\) 类计算，只减少参数及相关状态。
- encoder-decoder 可能有源、目标两个词表；能否三方共享取决于词表和语言设置。

面试回答应写出 \(z=hE^\top+b\)，说明参数节省、正则化和双路径梯度，再补充词表/维度兼容条件。
