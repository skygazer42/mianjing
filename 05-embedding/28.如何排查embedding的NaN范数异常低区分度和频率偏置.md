# 28. 如何排查 embedding 的 NaN、范数异常、低区分度和频率偏置？

## 从流水线分段定位

先固定少量 golden 输入，在 tokenizer、模型隐藏状态、pooling、归一化、量化和索引入口逐段保存统计。单条与 batch 结果应一致；若只在混合长度 batch 出错，优先检查 attention mask、padding 和 pooling 分母。不要一看到近邻异常就直接重训模型，很多问题来自服务预处理或索引版本错配。

## NaN 与范数

检查原始隐藏状态是否有限、L2 归一化前范数最小值、epsilon、混合精度溢出以及全 PAD/空字符串。Masked mean 若 \(\sum m_t=0\) 会除零；FP16 中极大激活或不稳定 softmax 会先产生 Inf 再变 NaN。记录每层 activation RMS 和首个非有限位置，比只在最终输出断言更易定位。

范数异常大可能来自漏掉 norm、模型权重损坏或点积训练无尺度约束；全部范数近零可能是错误加载、量化 scale 为零或输出被 mask。按模型版本、语言、长度和输入类型画范数分布，不能只看全局均值。

## 低区分度与频率偏置

随机采样非匹配文本，统计 pairwise cosine 分布、每维方差和有效秩；若所有向量近乎相同，检查是否错误地总取 PAD/第一个位置、是否使用未训练 pooling head。高频/热门文本成为所有查询近邻时，比较候选范数、进入 top-k 次数与文档频率；分别测试 cosine 和内积可判断是否由范数主导。

词表 token embedding 的频率偏置还可能来自训练更新次数不均。可按 token 频率看行范数和梯度，但句向量服务更应关注最终输出，不能把输入表统计直接当结论。

## 修复与回归

修复后建立属性测试：非空输入输出有限、维度固定、cosine 模式范数近 1、同输入跨 batch 差异在容差内、新旧版本不能混建索引。用 exact brute-force 与 ANN 对账，区分编码错误和搜索近似。

面试回答最好按“输入/mask → 模型层 → pooling → normalize → index”顺序讲，并为四类症状给出可观测量，而不是只列调学习率、加 epsilon 等零散办法。
