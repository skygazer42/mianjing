# 01. one-hot 和 embedding 有什么区别？

## 结论

one-hot 是对离散编号的无参数表示：词表大小为 \(V\) 时，第 \(i\) 个 token 是仅第 \(i\) 维为 1 的 \(V\) 维向量。Embedding 是可训练矩阵 \(E\in\mathbb{R}^{V\times d}\) 中的一行，通常 \(d\ll V\)。前者只表达“是不是同一个符号”，后者能在训练目标约束下学习可比较、可组合的连续特征。

## 数学关系

令 \(e_i\) 为 token \(i\) 的 one-hot 行向量，则

\[
h_i=e_iE=E_{i,:}.
\]

所以 one-hot 乘 embedding 矩阵与按 id 查表在数学上完全等价；工程实现不会真的构造巨大稀疏 one-hot，而是用 gather/index-select 读取所需行。假设 \(V=50\,000,d=4096\)，一个 one-hot 有五万维，而查表结果只有 4096 维；批量查表的成本与出现的 token 数相关，不必对整张表做稠密矩阵乘法。

## 表达能力与训练

任意两个不同 one-hot 的点积都是 0、欧氏距离都是 \(\sqrt2\)，无法表达“猫”比“汽车”更接近“狗”。Embedding 的坐标不是预先赋予语义，而是由语言建模、对比学习等损失反向传播得到。经常出现在相似上下文、对预测有相似作用的 token，梯度更新方向往往相近，于是可能形成邻近结构；这只是训练目标诱导出的统计结构，不保证每个坐标都有可解释含义。

## 工程取舍与误区

- embedding 并不等于降维算法；它是模型参数或编码器输出，维度和几何由目标决定。
- 查表只节省计算，不会自动省掉参数存储，参数量仍是 \(Vd\)。
- token embedding 是静态行；经过 Transformer 后，同一 token 在不同上下文会得到不同隐藏状态。
- one-hot 也不是“完全没用”：标签、稀疏类别特征以及推导 softmax 时仍常用它描述目标。

面试回答可先给出“one-hot 负责身份，embedding 学习连续特征”，再写出 \(e_iE=E_i\)，最后补充查表实现、参数量和上下文化表示的区别。
