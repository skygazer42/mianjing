# 07. PAD、UNK、BOS 等特殊 token 的 embedding 应如何处理？

## 核心结论

特殊 token 仍是词表中的 id，通常拥有 embedding 行，但它们的语义、是否参加损失以及是否允许更新各不相同。关键不是把所有特殊行都置零，而是让 tokenizer、attention mask、label mask、模型配置和 checkpoint 对同一 id 保持一致。

## 分别处理

- PAD 只用于对齐 batch，常设置 padding_idx，使其输入行保持零或不更新；更重要的是在注意力中屏蔽 PAD key，并把对应监督标签设为 ignore index。仅把 PAD embedding 置零不能阻止它通过位置编码、bias 或残差产生非零状态。
- UNK 表示 tokenizer 无法覆盖的片段，应可训练，因为模型要从上下文学会处理未知输入。但 byte fallback 等方案可能极少使用 UNK，训练不足会使它质量较差。
- BOS/EOS/SEP/CLS 等承担序列边界、分隔或汇聚角色，通常必须正常训练。它们出现频率和位置固定，模型会把协议语义写入相应向量。
- MASK 用于掩码语言模型预训练，应与真实词不同；若下游从未使用，仍不能随便复用其 id。

## 一个常见故障链

假设 tokenizer 把 PAD 设为 0，而加载的模型认为 0 是 BOS。若批处理代码以 0 做 attention mask，真实 BOS 会被屏蔽；若又把 0 的 embedding 清零，生成起始协议被破坏。此类错误通常不报异常，只表现为输出退化。因此加载模型后应检查 special_tokens_map、每个 token 的 id、词表行数和 generation config，并用编码—解码小样例验证。

## 训练与扩词

新增特殊 token 后要 resize embedding/输出层，并决定初始化。可用相关旧 token 均值加小噪声，随后用包含该协议的大量样本训练；仅随机初始化而马上推理不会让模型理解新标记。若输入输出共享，新行也会作为输出类别参与 softmax。训练聊天模板时，还要确认特殊串由单个 special token 编码，而不是被普通子词拆开。

面试回答应覆盖“有行不代表都参与训练”、PAD 的三重屏蔽、id 协议一致性和新增 token 的训练。最常见误区是把零向量当作完整的 padding 处理。
