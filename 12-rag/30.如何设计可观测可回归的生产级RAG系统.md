# 30. 如何设计可观测、可回归的生产级 RAG 系统？

## 结论先行

生产级 RAG 要把每次回答视为跨离线数据版本和在线多阶段的可回放事务。设计核心是稳定 id 与版本贯穿 ingest→index→query→candidate→prompt→claim/citation；每阶段有质量、延迟、成本与安全指标；发布前跑固定/新鲜度评测，发布后 shadow/canary 和告警，失败能按 trace replay、归因并一键回滚。只有最终 prompt/答案日志远远不够。

## 版本与 trace schema

一次 request trace 至少包含：认证后的安全域（脱敏）、原/改写/子查询、filters；corpus/index/chunker/embedding/ANN 版本；各路候选 id、分数、rank、耗时；fusion/rerank 排名与删除 reason；最终证据 token、版本、顺序、引用映射；generator/模板/采样版本、claims、校验与 stop reason。离线文档记录 source hash、解析器、ACL、父子和事件时间。所有 span 用 trace/span id 串联。

## 指标与 SLO

离线：抓取/解析成功率、源到可见 freshness、chunk/embedding 覆盖、ACL 缺失、tombstone backlog。在线：各阶段 P50/P95/P99、错误/超时/降级、Recall/nDCG 抽样、rerank uplift、context duplication/token、答案正确/faithfulness/citation/refusal、安全攻击成功率、每成功答案成本。按 tenant、query 类型、语言、版本和输入长度分桶，避免总体均值掩盖回归。

## 回归与发布

建立三层测试：确定性单测/契约（parser offset、ACL、cache key、引用 id）；固定 snapshot 的离线 gold + adversarial set；真实流量 shadow replay。任何 embedding/chunker/reranker/template 更新一次只改少数变量，输出 paired diff。通过后 canary 按稳定 tenant/request hash 切流，设质量/延迟/error budget 自动停止，旧 index/model 保留回滚。

## 在线故障处理

告警先看数据 freshness、候选和 prompt gate，使用 gold injection、固定 generator 和阶段 bypass 做 counterfactual。依赖超时有明确降级：dense 失败可用 BM25，reranker 超时回退融合序，授权服务失败必须 fail-closed。队列、限流、熔断和 backpressure 防止重试风暴；索引切换和 cache invalidation 要原子/版本化。

## 隐私与成本

日志默认最少化、加密、访问审计并设置保留期；敏感 query/文档可存 hash/id，通过受控工具回放。采样完整 trace，聚合所有请求指标。成本按 embedding、搜索、rerank、LLM token、存储和人工复核分摊到 query class，优化才有方向。

## 常见误区与面试要点

dashboard 多不等于可观测，关键是能从异常指标定位具体版本和候选决策；离线分高也不等于发布安全。回答按 versioned pipeline—trace—layered metrics—replay/canary—rollback—security/cost 展开。
