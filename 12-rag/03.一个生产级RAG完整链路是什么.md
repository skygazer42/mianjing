# 03. 一个生产级 RAG 的完整链路是什么？

## 结论先行

生产级 RAG 不是“文档向量化后 top-k 拼 prompt”三步，而是两条可版本化流水线：离线侧负责采集、解析、切块、索引、权限和质量；在线侧负责鉴权、查询理解、候选召回、重排、上下文构建、生成与引用校验。每个阶段都要保留可追踪 id 和独立指标，才能定位错误。

## 离线知识摄取链路

```text
数据源连接
 -> 抓取与版本检测
 -> 解析/OCR/结构恢复
 -> 清洗、去重与语言识别
 -> 语义切块和父子关系
 -> embedding / 稀疏索引 / 图或结构化索引
 -> 写入正文、向量、元数据、ACL、版本
 -> 质量检查与发布索引版本
```

### 1. 数据源与版本

连接文件系统、Wiki、数据库、工单或对象存储时，应生成稳定的 `document_id`，记录 source URI、内容哈希、更新时间、业务版本和删除状态。没有版本信息，就无法解释为什么用户今天和昨天检索到不同规则。

### 2. 解析与清洗

PDF 需要恢复页码、标题、表格和阅读顺序；扫描件需要 OCR；网页要去导航与重复模板。清洗不能丢失引用所需的原始 offset，也不能把不同权限文档误去重为一份。

### 3. 切块与索引

chunk 不只是字符串，还应带：

```text
chunk_id, document_id, parent_id, text,
title_path, page/offset, version, timestamp,
tenant_id, ACL, language, content_hash
```

根据数据和查询同时建立稠密向量、BM25 倒排、metadata 或结构化索引。embedding 模型、切块算法和索引参数必须写入 `index_version`，否则无法安全升级或回滚。

## 在线查询链路

```text
请求鉴权
 -> 查询分类、改写或分解
 -> ACL/时间/租户过滤
 -> 多路召回
 -> 融合、去重、rerank
 -> 父块扩展与 token budget 组装
 -> 带证据提示词生成
 -> 引用/忠实度/策略校验
 -> 返回答案、来源和 trace
```

### 1. 先鉴权，再检索

权限条件应尽可能下推到检索层，而不是先跨租户召回、再在应用层删除。后者不仅有泄漏风险，也会让无权结果占满 top-k，导致合法证据召回不足。缓存键同样必须包含租户、权限和索引版本。

### 2. 查询理解与多路召回

系统可识别查询语言、时间范围、实体和意图，决定是否改写、拆成多个子问题或走 SQL/图查询。然后并行调用 BM25、dense retriever 或专用数据源，获得较大的候选集。

### 3. 融合与重排

不同检索器的原始分数通常不可直接相加，可用 RRF 等 rank fusion 合并，再由 cross-encoder/LLM reranker 在较小候选集上做更精确相关性判断。去重时要保留不同版本、来源和相邻块关系，不能只按字符串相似度粗暴删除。

### 4. 上下文组装

把 rerank 后的 chunk 扩展为必要的父段、标题或表头，在 prompt token budget 内选择证据。要处理重复、冲突、时间优先级、来源可信度和“中间位置遗失”风险；每段分配不可伪造的引用 id，并明确外部内容是数据而不是指令。

### 5. 生成与校验

提示模型只依据证据回答、证据不足时拒答，并要求结论绑定引用。生成后可检查引用 id 是否存在、引用片段是否蕴含相应 claim、结构化输出是否合规。高风险业务还需规则引擎或人工复核，不能把 LLM 自检当成确定性保证。

## 需要贯穿全链路的 trace

一次请求至少应能回放：

- 原查询、改写查询和子查询；
- 应用的 ACL/metadata filter；
- 各 retriever 候选 id、原始分数、rank 与耗时；
- 融合和 rerank 前后顺序；
- 最终进入 prompt 的 chunk、版本、位置和 token 数；
- 模型、模板、采样参数、输出与引用校验结果；
- `index_version`、embedding 版本和代码发布版本。

日志要脱敏并遵守数据保留策略。没有这些字段，出现幻觉时只能看到最终答案，无法判断是哪一级失效。

## 指标如何分层

离线侧关注解析成功率、索引延迟、重复率、ACL 完整率、embedding 覆盖和更新新鲜度。在线检索关注 Recall@k、MRR/nDCG、filter 命中和 rerank 提升；生成关注答案正确性、faithfulness、引用精度/召回与拒答质量；系统关注 P50/P95/P99、错误率、token/检索成本和缓存命中率。

端到端答案分数不能替代阶段指标：相同低分可能来自文档没入库、召回失败、重排丢证据或模型忽略证据，修复方式完全不同。

## 面试回答要点

先画离线 ingest/index 与在线 retrieve/generate 两条链路，再强调 ACL、版本、引用和 trace 是生产级与 demo 的分界。最后为解析、召回、重排、生成和系统延迟各给一组指标，并说明所有产物都要能通过 document/chunk/request id 串起来。

## 延伸追问

1. 为什么权限过滤应该下推到检索，而不是召回后再过滤？
2. embedding 模型升级时怎样双写索引并安全切流？
3. 如何从一条错误答案的 trace 判断故障发生在哪个阶段？
