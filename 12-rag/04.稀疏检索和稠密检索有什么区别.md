# 04. 稀疏检索和稠密检索有什么区别？

## 结论先行

稀疏检索以词项匹配为主，典型实现是倒排索引与 BM25，擅长产品编号、人名、错误码和原文关键词；稠密检索把 query 与 chunk 编码成低维向量，按向量相似度寻找语义近邻，擅长同义改写和没有字面重合的表达。二者不是替代关系：生产 RAG 常并行召回后融合，因为它们的失败样例互补。

## 核心机制

BM25 可简化写为：

$$
\operatorname{score}(q,d)=\sum_{t\in q}\operatorname{IDF}(t)
\frac{f(t,d)(k_1+1)}{f(t,d)+k_1(1-b+b|d|/\operatorname{avgdl})}
$$

其中 $f(t,d)$ 是词项 $t$ 在文档 $d$ 中的频次，$|d|$ 与 $\operatorname{avgdl}$ 分别是当前和平均文档长度，$k_1$ 控制词频饱和速度，$b$ 控制长度归一化强度。该公式利用词频、逆文档频率和文档长度归一化；表示维度接近词表规模，但每篇文档只有少数非零项，倒排表可快速跳到含目标词的文档。稠密检索则计算 $e_q=f(q)$、$e_d=g(d)$，用 cosine、dot product 或 L2 距离排序。双塔模型可离线编码文档，在线只编码 query，代价是 query 与文档在召回阶段没有细粒度 token 交互。

## 具体例子

查询“数据库报错 ORA-01555”时，错误码的精确匹配非常关键，BM25 往往更稳；查询“员工离职后还能报销多久”而制度原文写“劳动关系终止后的费用申报期限”，dense 模型更可能跨措辞召回。若把两路 top-100 合并再重排，可以同时保住精确实体与语义改写。

## 工程取舍

稀疏索引易解释、增量更新快，对分词、大小写、同义词和多语言 normalization 敏感；dense 索引容量较大，质量依赖 embedding 训练域和切块，升级模型常需重建向量。两路原始分数分布不同，不能直接把 BM25 分数与 cosine 相加，通常用 RRF、分数校准或学习融合。ACL 与时间过滤应下推到两路检索，避免无权候选占满配额。

## 常见误区

“dense 一定比 BM25 先进”不成立；精确标识、稀有实体和新词常是稀疏检索强项。“没有关键词重合就一定召回不到”也不绝对，同义词扩展和 learned sparse retrieval 能缓解。评测必须按 query 类型分桶，否则平均指标会掩盖某一路的关键价值。

## 面试回答要点

按表示、索引、优势、失败模式与融合方式对比，并给一个错误码和一个语义改写例子。最后强调先扩大候选召回，再用 reranker 精排，而不是强迫单一 retriever 解决所有问题。
