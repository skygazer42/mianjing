# 19. SQL 和知识图谱何时优于向量检索？

## 结论先行

向量检索适合从非结构化文本中找语义相近证据；SQL 适合有明确 schema 的精确过滤、聚合、排序和数值计算；知识图谱适合实体关系、路径、多跳连接和全局拓扑查询。生产 RAG 应按问题路由并组合：文本解释走检索，精确数值由数据库计算，关系路径由图查询，最终把结果与来源交给模型表达。

## SQL 的优势

“本季度华东区已退款订单总额”需要时间、地区、状态过滤与 `SUM`。向量 top-k 只能找若干相似订单，不能保证全量、唯一和算术正确。SQL 可在事务/快照语义下执行：

```sql
SELECT SUM(amount) FROM orders
WHERE region='EAST' AND status='REFUNDED'
  AND refunded_at >= :start AND refunded_at < :end;
```

模型应生成受限 AST/参数化查询，经 schema/权限验证和只读执行，而不是直接执行任意文本 SQL。结果需带查询版本、时间和行级 ACL。

## 知识图谱的优势

问题“与供应商 A 共享最终受益人且参与项目 B 的公司有哪些”涉及实体消歧和多条边约束。图数据库能用确定性路径模式遍历、去重并返回完整关系链；文本向量相似不保证两实体真的有该关系。图的难点是 entity linking、ontology/schema、边来源和更新成本。

## 混合数据流

query router 先判断事实查找、聚合、关系或开放文本；必要时 planner 生成多个工具调用。SQL/图结果以结构化表和 provenance 注入上下文，同时召回政策定义解释字段。模型负责叙述与引用，不负责把采样文本当全库聚合。

## 工程取舍与误区

SQL/图也可能因 schema 映射、脏数据或生成查询错误失败，需要 allowlist、成本上限、超时与结果验证。知识图谱不是所有文档先抽三元组就自然变准，抽取误差会系统性传播。向量库 metadata filter 也不是完整 SQL 引擎。

## 面试回答要点

用“语义近邻 vs 精确集合计算 vs 关系路径”划边界，并说明路由、受控执行、ACL 和 provenance。

2. 图中的每条边如何绑定原始证据？
