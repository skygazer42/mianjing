# 28. 多模态 RAG 有哪些特殊难点？

## 结论先行

多模态 RAG 不只是给图片生成 caption 后照搬文本检索。它要处理版面与阅读顺序、图像局部区域、表格结构、OCR 错误、音视频时间段，以及文本 query 与视觉/音频证据的跨模态对齐；引用也要精确到页码、bounding box 或时间区间。实践常采用结构化解析 + modality-specific embeddings + late fusion/多模态 rerank。

## 摄取与表示

PDF 页面同时含标题、两栏正文、表格和示意图。先恢复 layout graph：块类型、坐标、阅读顺序、页码和父子结构；OCR 保存文字及置信度/bbox；表格保留行列、合并单元格、表头和单位；图片可存全局向量、区域向量及与 caption/邻近文字的链接。视频按镜头/时间窗口切分，并关联 ASR、关键帧和时间戳。

## 检索路线

文本 query 可同时搜索 OCR/caption 的 sparse+dense 文本索引和跨模态 image embedding；结果用 rank fusion，再让能联合看 query、图片/页面的 reranker 判断。只检索 caption 会漏视觉关系、细小文字和图表趋势；只用视觉向量又可能弱于精确型号/数字。对于表格聚合，应将候选表交给结构化执行，而不是让模型从若干行截图猜总和。

## 具体例子

用户问“图 4 中温度超过 80℃ 后效率怎样变化？”需要先定位带“图 4”的页面，再裁剪正确图表区域、关联图注与坐标轴，最后让多模态模型读取曲线。引用应返回 page + bbox 高亮，而不是只给整份 200 页 PDF。若 OCR 将 `80` 识别为 `B0`，文本召回可能失败，视觉/邻段路线可互补。

## 工程与安全

多向量使索引和 rerank 成本增加，需要记录 modality、encoder/version、坐标变换和原始 asset hash。图片中也可藏提示注入、二维码或敏感信息；OCR/caption 属不可信派生文本，沿用 ACL 与安全扫描。压缩/resize 不能让引用 bbox 与原图错位。

## 评估与误区

按 modality 测 region/page Recall@k、OCR/表格结构准确、跨模态 rerank、回答/引用 bbox IoU 与端到端质量。不要用 caption 当权威证据；它是模型生成的索引辅助，最终应回到原资产。

## 面试回答要点

覆盖解析结构、跨模态召回、区域/时间引用、结构化表格与成本安全，并给图表例子。
