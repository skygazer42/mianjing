# 11. query rewrite、query expansion 和 HyDE 分别解决什么问题？

## 结论先行

三者都在原 query 难以直接召回时改善检索表达，但方式不同：rewrite 将含糊、多轮或口语问题改成自包含查询；expansion 生成若干同义词、实体别名或多角度子查询，扩大覆盖；HyDE 先生成一段“假想答案/文档”，再用它的 embedding 检索真实文档，缩小短 query 与文档体裁之间的表示差距。它们可能引入错误假设，因此原 query 必须保留并可并行召回。

## 机制与数据流

多轮 rewrite 会把“那北京呢？”结合受控对话状态改成“2026 年北京地区差旅酒店报销上限是多少”，补齐实体、时间和意图，但不应把模型猜测的金额写入查询。expansion 可产生“差旅住宿标准、酒店限额、lodging cap”等等，分别检索后用 RRF/去重融合。HyDE 生成类似知识库 passage 的文本 $\tilde d=G(q)$，使用 $f(\tilde d)$ 作为 query 向量；它不是把假想答案交给用户，也不能当证据。

## 具体例子

用户输入“容器老是被杀怎么查”。rewrite 可规范为“Kubernetes Pod 被 OOMKilled 的排查步骤”；expansion 加入 `OOMKilled`、memory limit、exit code 137；HyDE 可生成一段含这些诊断术语的假想运维手册，从而靠近真实文档 embedding。如果模型错误假设为 OOM，而实际是 eviction，单路 HyDE 可能把召回带偏，因此应同时保留原始、关键词和改写结果。

## 工程取舍

先做 query 分类，只对省略、多轮、零结果或低置信查询触发增强，避免每次增加 LLM 延迟。输出应是结构化字段：standalone query、filters、expansions、不得假定的实体；设置最大数量并对近重复 query 去重。缓存键要包含对话摘要、语言和 rewrite 模型版本，日志中保留原 query 与每个变体的独立候选贡献。

## 评估与常见误区

比较原 query baseline 与增强后的 Recall@k、zero-result rate、端到端正确率和延迟，并统计 query drift：新增实体/时间是否被证据支持。HyDE 文本再逼真也只是检索探针，绝不能引用；expansion 越多不一定越好，会召回大量宽泛噪声。

## 面试回答要点

用“补全意图、扩大表达、生成文档视角”区分三者，再说明多路融合、漂移控制和条件触发。
