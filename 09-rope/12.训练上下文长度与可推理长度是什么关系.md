# 12. 训练上下文长度与可推理长度是什么关系？

## 结论

训练上下文长度 (L_{train}) 是模型实际接受监督的最大或典型序列范围；配置中的 `max_position_embeddings` 是实现允许的范围；推理时“能送进去”的长度又受 RoPE 表、attention kernel 和 KV 内存限制。三者不等价，真正可用长度还必须由质量评测定义。

## 四个层次

第一是 tokenizer 与接口是否接受该长度；第二是位置函数和 mask 能否构造；第三是显存/计算是否承受；第四才是模型在该距离上是否保持任务能力。RoPE 让第二层理论上容易扩展，但不会自动解决第三层二次 prefill 成本和第四层分布外泛化。

例如一个在 4k 序列上预训练的模型，把 cos/sin cache 扩到 32k 后可能不报错，也能输出流畅句子，却在 20k 处无法找回关键事实。此时“支持 32k”若只指 API 不报错会误导用户。工程文档应分别报告最大接受长度、推荐质量长度与测试条件。

## 如何扩展

常见做法是先选择 PI、NTK-aware、YaRN 或其他 scaling，把目标位置映射/频率调整到可学习范围，再用一部分长序列继续训练或微调；还要扩展训练 batch 的长度分布，并处理 attention 内存。仅在短样本上微调扩长配置，模型未必见过足够的远距离监督。

## 评估边界

短上下文回归也很重要：某些 scaling 改变原范围内频率，扩长后虽通过 needle test，却让常规对话或短文本 PPL 退化。测试应覆盖 1k 到目标长度多个桶、不同信息位置与真实长文任务，而不是只测最大长度的单根 needle。

## 面试回答要点

用“配置可运行 ≠ 模型会利用 ≠ 系统装得下”回答最稳妥。延伸追问可以讨论为什么长上下文继续训练需要 length curriculum，以及为什么声明 128k 不能只看 position table 大小。
