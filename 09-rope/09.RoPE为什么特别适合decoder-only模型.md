# 09. RoPE 为什么特别适合 decoder-only 模型？

## 结论

RoPE 与 decoder-only 的契合点在于：它直接作用于每层自注意力的 Q/K；位置可按整数在线生成，不需要固定长度位置表；增量生成时新 query/key 只需按当前逻辑位置旋转，历史已旋转 K 可复用。相对位移性质也符合语言中大量依赖距离的模式。

## 自回归数据流

prefill 对位置 (0\ldots S-1) 的 Q/K 并行旋转，并使用 causal mask。生成第一个新 token 时，当前位置为 (S)，只计算该 token 的 Q/K/V；(R_Sq) 与历史 (R_nk) 的点积自动得到相位差 (n-S)。无需把一个新的绝对位置 embedding 加回所有历史状态，也无需重算历史旋转。

## 相比 learned absolute embedding

learned position table 需要为最大长度分配参数，超出表长没有已训练行；扩表通常要插值或再训练。RoPE 的三角函数可对任意 position 求值，参数开销几乎为零，并且每层都通过 Q/K 重新利用位置。可计算不等于可泛化：训练只见 4k 时直接跑 128k，模型会遇到未见相位和注意力分布，因此仍需 scaling 与长上下文训练。

## 工程优势与约束

sin/cos 可缓存，额外计算较小；与 fused attention、GQA 和 KV cache 都容易集成。约束是必须维护准确 position id，checkpoint 的 base、布局、rotary dimension 必须一致；变长 batch、prefix cache、滑窗和 speculative decoding 都可能让“当前位置=张量长度”失效。

## 面试回答要点

不要只说“RoPE 能表达相对位置”。还应把增量步骤讲清：新 Q/K 旋转、历史 K 已旋转、相对点积自然成立。RoPE 也可用于 encoder 或视觉 Transformer，“特别适合”不是“只能用于 decoder”。
