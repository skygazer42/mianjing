# 29. 如何为 RoPE 实现设计正确性测试？

## 结论

RoPE bug 往往不报错且输出仍流畅，因此需要同时测试数学不变量、布局兼容、batch position 与 full/cached 推理一致性。只检查输出 shape 或范数远远不够，最强验证是与 checkpoint 官方实现逐层/logits 对齐。

## 数学单元测试

随机生成 FP64 小向量，验证 \(\lVert R_mx\rVert=\lVert x\rVert\)；验证同一旋转保持点积；验证

\[
(R_mq)^T(R_nk)=q^TR_{n-m}k

\]

在多个正负位置差上成立。对位置 0，cos 应全 1、sin 全 0，输出应等于输入。用手写 2D 例子检查旋转符号，例如 `[1,0]` 旋转 (pi/2) 应按约定得到 `[0,1]`。

## 实现与布局测试

分别构造 interleaved 和 split-half 参考，确认目标 checkpoint 只匹配正确一种；partial rotary 的 pass-through 通道必须逐元素不变。比较向量化实现、fused kernel 与纯 Python/PyTorch 参考，覆盖非连续 tensor、不同 head 数和多 dtype。

## 序列测试

同一句单独运行与左 padding 变长 batch 的有效 logits 应一致；full forward 与逐 token KV cache forward 应对齐；prefix cache 命中/未命中应一致；跨原长度阈值测试 dynamic scaling，检查是否有突变。position 0、1、原最大长度、最大长度+1 和目标最大位置都应覆盖。

## 精度与回归

FP32 作为参考，BF16/FP16 按合理绝对/相对容差；超长 position 特别检查相邻位置 cos/sin 不被错误折叠。保存少量固定输入的 logits golden tests，升级库或 kernel 后检测 layout/scaling 语义漂移。

## 面试回答要点

至少说出“范数不变、相对点积恒等式、position 0、full=cache、padding batch=单样本”五类测试，体现既懂数学也懂服务路径。
