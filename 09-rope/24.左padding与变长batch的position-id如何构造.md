# 24. 左 padding 与变长 batch 的 position id 如何构造？

## 结论

position id 应按每条样本的有效 token 顺序构造，而不是直接使用 batch 张量列号。左 padding 把不同长度序列的最后一个 token 对齐到同一列，如果按列号位置，短样本会从较大的绝对位置开始，full batch 与单独运行的结果不一致。常用方法是由 attention mask 的累积和生成有效位置。

## 构造方法

设 `attention_mask` 中有效 token 为 1、pad 为 0：

```text
position_ids = cumsum(attention_mask, dim=-1) - 1
position_ids = where(attention_mask == 1, position_ids, 0)
```

例如 batch 宽度 5，样本 mask 为 `[0,0,1,1,1]`，有效 position 应为 `[0,1,2]`，padding 位置填 0 只是占位且必须被 attention/loss mask 屏蔽。另一条长度 5 的样本则为 `[0,1,2,3,4]`。

## decode 更新

首轮 prefill 后，每条请求维护自己的有效长度或 cache position。即使它们在连续批处理中同一轮各输入一个 token，新 positions 也可能分别是 3 与 5。请求结束、插入新请求或 beam reorder 时，都要随 sequence state 更新 position，而非用全局 decode step。

## 特殊情况

有的模型训练时故意使用左 padding 后的绝对列位置，或采用 padding-side 相关约定，此时应遵循官方实现；上述累积和是常见但不是可任意替换 checkpoint 语义的法则。position 还可能包含 prefix 长度、模态轴或 packed 文档重置，需由模型接口生成。

## 常见 bug 与回答要点

症状包括 batch size 1 正常、变长 batch 质量下降，或同一句单独推理与批量推理 logits 不同。测试应比较两种执行并检查有效 token 输出。面试回答要区分 attention mask（可见性）与 position id（旋转角），前者正确不会自动修复后者。
