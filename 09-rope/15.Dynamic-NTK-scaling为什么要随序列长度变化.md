# 15. Dynamic NTK scaling 为什么要随序列长度变化？

## 结论

静态 NTK-aware scaling 从最短输入开始就使用扩展后的频谱，可能损伤模型最常见的原长度内表现。Dynamic NTK 的思路是：序列未超过原训练长度时保持原 RoPE；只有当前上下文变长后，才按实际长度逐步增大有效 scaling/base，以减少短上下文分布偏移，同时覆盖所需长程。

## 概念流程

设原长度 (L_0)，当前需要的最大逻辑位置对应长度 (L)。可定义有效倍率 (s_{eff}(L))：当 (L\le L_0) 时为 1，超过后随 (L/L_0) 增长，再将它代入 NTK-aware base 公式。不同框架对 (s_{eff}) 的线性项、上限和舍入定义不同，不能仅凭“dynamic”名称判断数值完全兼容。

## 隐蔽的一致性问题

若在同一会话 decode 过程中，当长度跨过 (L_0) 才突然改变 inv_freq，那么历史 K 是用旧频谱旋转的，新 Q/K 用新频谱，(R_m^TR_n=R_{n-m}) 的同频率前提被破坏。实现可在 prefill 时按整段目标长度选定频率、跨阈值时重算历史 K，或使用框架规定的策略；不应想当然地每一步改 base 而不处理缓存。

## 适用场景与代价

动态方案适合输入长度跨度很大、又重视原长度质量的部署。但同一 token 在不同最终序列长度下可能采用不同位置表，使 prefix cache 的共享键需要包含 scaling 状态；CUDA graph 和 cos/sin cache 也要按有效长度分组，增加服务复杂度。

## 评估方法

分别测试 (L_0) 以下、刚跨阈值、多个扩展倍率和最大长度，观察 PPL 是否有不连续跳变；full forward 与增量 cache 输出要对齐。若只测试最终 128k 而不测 4k 回归，就无法证明动态策略的主要价值。

## 面试回答要点

回答要包含“短序列保持原频率、长序列按需扩展”和“历史缓存频率一致性”两点。后者往往是区分算法概念与可部署实现的关键。
