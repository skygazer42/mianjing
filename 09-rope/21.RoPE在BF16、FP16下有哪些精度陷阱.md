# 21. RoPE 在 BF16、FP16 下有哪些精度陷阱？

## 结论

RoPE 的矩阵乘本身简单，真正的精度风险在“位置 × 频率”的相位生成。长位置用 BF16/FP16 表示时，相邻整数可能舍入成相同值；大相位的 sin/cos 参数归约也会放大误差，导致不同 token 获得近似甚至错误的位置旋转。因此常用 FP32 计算 position、inv_freq 外积与三角函数，再把 cos/sin 转为 Q/K dtype 做乘加。

## 为什么长位置危险

浮点数有效位有限。BF16 只有 7 位显式尾数，在较大数量级上相邻可表示数间隔远大于 1；若先把 position id cast 成 BF16，位置 100000 与 100001 可能映射到同一数。FP16 尾数稍多但指数范围小，大相位更可能溢出或在库函数中精度差。问题不是 RoPE 理论周期，而是有限精度输入在求 sin/cos 前已经丢信息。

## 稳健流程

```text
pos_fp32 = position_ids.float()
freq_fp32 = outer(pos_fp32, inv_freq.float())
cos, sin = cos(freq_fp32), sin(freq_fp32)
q_rot = q * cos.to(q.dtype) + rotate_half(q) * sin.to(q.dtype)
```

某些框架在 autocast 下会自动把外积降精度，需要显式禁用 autocast 或指定 FP32 区域。inv_freq 本身也应从高精度 base 计算并缓存，不能先低精度生成后再 cast 回 FP32。

## 其他陷阱

超长 scaling 下频率非常小，FP16 中可能下溢；动态扩容 cos/sin cache 若一部分由旧 dtype 生成、一部分由新 dtype 生成，会造成位置边界不连续。跨设备/不同数学库的三角函数可能有细微差异，通常按容差比较，而不是要求 bitwise 一致。

## 面试回答要点

指出“Q/K 可低精度，角度生成最好 FP32”，并用大整数相邻位置不可分辨解释原因。不要声称 BF16 动态范围大就一定安全，它的尾数更短，位置整数精度仍是核心风险。
