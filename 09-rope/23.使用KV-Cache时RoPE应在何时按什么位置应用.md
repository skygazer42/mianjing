# 23. 使用 KV Cache 时 RoPE 应在何时、按什么位置应用？

## 结论

最常见实现是在 K 写入缓存前就按其逻辑 position 应用 RoPE，Q 在每次计算时按当前 query position 旋转；缓存中保存“已旋转 K + 未旋转 V”。这样历史 K 无需每步重新旋转，新 Q 与历史 K 的点积自动表达相对位移。

## prefill 与 decode

prefill 长度为 (S) 时，对 positions `0..S-1` 的 Q/K 批量旋转，K/V 写入各自逻辑槽。随后生成步骤的新 token position 是 (S,S+1,ldots)。其输入 tensor 即使长度为 1，position id 也不能重置为 0。若从 prefix cache 复用 (P) 个 token，新 suffix 的首位置应是 (P)，且 prefix 的 scaling/base 必须与当前请求一致。

## rotated cache 与 unrotated cache

缓存旋转后的 K 读取最快，是主流选择；缓存未旋转 K 可在读取时按位置旋转，便于某些位置平移或动态 scaling，但每一步会重复处理全部历史 K，带来额外带宽与计算。也可在 changing-base 时一次性重建缓存，复杂度与一致性要明确。

## 滑窗与位置平移

淘汰最旧 token 后，物理 cache 索引会变化，但逻辑位置不一定重编号。若保留原位置，直接继续旋转即可；若某算法把窗口 positions 重置到 0，则历史已旋转 K 必须做相对旋转修正或重算，不能只改 metadata。Paged cache 的 block id 更不是 position id。

## 正确性测试与面试要点

对同一序列比较一次 full forward 与逐 token cached forward，每个位置 logits 应在数值容差内一致；再测试左 padding、prefix 复用和跨 block。回答时抓住“写前旋转 K、当前 position 旋转 Q、V 不旋转、逻辑位置不等于槽位”，即可覆盖大部分工程风险。
