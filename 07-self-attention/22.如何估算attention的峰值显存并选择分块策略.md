# 22. 如何估算 attention 的峰值显存并选择分块策略？

## 先拆组成

对 batch \(B\)、heads \(H\)、长度 \(L\)、每头维 \(d_h\)、每元素 \(s\) 字节，Q/K/V 合计约 \(3BHLd_hs\)，输出约 \(BHLd_hs\)。朴素 score 或 probability 单个就约

\[
BHL^2s.
\]

训练若同时保存 score、softmax、dropout mask、梯度与临时 workspace，峰值可为这一项数倍。再加残差、FFN 激活、参数、梯度和优化器状态，不能把 attention 矩阵当全部显存。

## 一个量级例子

\(B=1,H=32,L=8192\)，FP16 单个 \(H L^2\) 矩阵约 \(32\times8192^2\times2\) 字节，约 4 GiB；若多个中间量同时存在，很快 OOM。QKV 本身约 \(3Ld\) ，对 \(d=4096\) 仅约 192 MiB，二次项差异明显。

## 分块选择

Flash 风格 tile 需让 Q/K/V block、score tile 和累积状态装入片上内存，同时保证 tensor core 对齐与足够 occupancy。块太大超 SRAM/寄存器导致 spill，太小则循环和加载开销高。最佳大小依 GPU、dtype、head_dim、causal/window mask，通常交给成熟 kernel autotune，而不是业务代码硬编码。

若无法使用融合 attention，可 query chunking 降低瞬时 score 从 \(L^2\) 到 \(C L\)，逐块输出；训练反向还需 checkpoint/recompute，否则保存所有块仍回到二次激活。Sequence parallel 可分散激活，但增加通信。

## 实测

公式提供上界与趋势，最终用框架 peak allocated/reserved、kernel profiler 和不同长度曲线验证；预热后测，区分 allocator cache 与真实活跃内存。记录是否实际走 Flash kernel及 workspace。

面试回答应先算 \(BHL^2s\)，再说明训练倍数、Flash 不物化矩阵、tile 的 SRAM/occupancy 折中，并强调全模型峰值需包含 FFN 和优化器。
