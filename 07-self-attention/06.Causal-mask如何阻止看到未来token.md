# 06. Causal mask 如何阻止看到未来 token？

## 机制

自回归位置 \(i\) 只能读取 \(j\le i\)。在 softmax 前给未来 score 加 \(-\infty\)：

\[
M_{ij}=
\begin{cases}
0,&j\le i\\
-\infty,&j>i
\end{cases},
\qquad
A=\operatorname{softmax}(QK^\top/\sqrt{d_k}+M).
\]

于是未来位置指数为 0，权重严格为 0，当前位置的隐藏状态和 next-token logit 不依赖未来 token。矩阵通常是保留下三角（含对角线），但布尔 mask 中 True 代表“保留”还是“屏蔽”由 API 决定。

## 训练为何能并行

Teacher forcing 时整条目标序列同时输入，causal mask 保证第 \(i\) 位只使用前缀，因此所有位置的 loss 可以一次矩阵计算，不需要像推理一样串行生成。标签通常右移：位置 \(i\) 的输出预测 token \(i+1\)。Mask 正确但标签未移位，或标签正确但 mask 泄漏，都会训练错误。

## 与 padding 的组合

Causal mask 针对 query-key 先后关系，padding mask 针对无效 key；组合应取逻辑“任一需要屏蔽即屏蔽”。Left padding 下不能仅按有效 token 数生成一个小三角再错误广播；应在实际 \(L_q,L_k\) 坐标中构造，并考虑增量解码时 query 可能只有 1、key 是完整前缀。

## 常见边界

是否允许看自身取决于输入/标签定义。标准 decoder hidden state 位置可看当前输入 token，并用于预测下一个 token，所以保留对角线。若某特殊任务要求预测当前被遮 token，mask 可能不同。全 mask query 行会导致 softmax NaN，应避免或定义输出为零。

## 验证

最强测试是未来扰动：固定前缀，随机改变后缀，比较前缀位置 logits 必须不变；再检查 attention 概率上三角为 0。使用融合 kernel 时也要做该差分测试，因为 mask orientation 错误可能仍生成看似流畅文本。

面试回答应写出三角加性 mask、说明训练并行和标签右移，并提醒布尔语义、对角线与 padding 组合。
