# 29. 如何正确评测和 profile 一个 attention 实现？

## 正确性先行

以清晰 FP32 实现为 oracle，比较候选 kernel 的前向、反向和参数梯度；低精度用合理 atol/rtol，并报告最大/分位误差。覆盖 causal/padding、\(L_q\ne L_k\)、GQA、dropout、非连续布局和全边界。检查屏蔽位为零、概率/输出有限、未来扰动不影响前缀。

## 性能维度

分别测 prefill 与 decode，记录 batch、query/key 长度、heads、KV heads、head_dim、dtype、mask 和硬件。预热编译与缓存，GPU 计时前后同步，进行多轮并报中位数/p95。指标包括 latency、tokens/s、TFLOP/s、HBM 带宽、峰值 active/reserved memory 和 kernel launch 数。

长度应覆盖真实分布而非只测 2 的幂；短序列可能 launch/投影主导，长序列才体现 Flash IO收益。Decode 的 \(1\times L\) 与 prefill 的 \(L\times L\) 瓶颈不同，平均成一个数字没有意义。

## Profile 解释

用硬件 profiler 判断是 tensor core、HBM、transpose/copy、通信还是低 occupancy。确认框架实际选择 Flash/memory-efficient/math 哪个 backend；自定义 mask 或需要返回 attention weights 可能导致静默回退。融合 kernel 更快不代表 attention 子模块之外端到端一定加速，应在完整层/模型复测。

## 公平比较

固定数学功能、dtype、dropout、是否含 QKV/O 投影和是否保存反向激活。不能拿只测核心 kernel 的结果与含数据搬运的实现对比。显存测试清理峰值统计并区分 allocator cache。

面试回答可用“oracle 正确性—shape 矩阵—同步计时—profiler 找瓶颈—端到端复测”流程，最后把结果画成长度/批量的吞吐与显存曲线。
