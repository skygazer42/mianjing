# 30. 如何在 MHA、GQA、MQA、Flash 与局部 attention 之间选型？

## 先分两个维度

MHA/GQA/MQA 决定 K/V 头共享，是模型架构；FlashAttention 决定同一数学 attention 如何高效执行，是 kernel；局部/稀疏 attention 改变可见连接图。它们可组合，例如 GQA + causal sliding-window + Flash kernel，不能当成互斥选项排一个总榜。

## 场景判断

从头训练、追求最大质量且解码资源充足，可用 MHA 基线；大模型生成受 KV 带宽/内存限制时，GQA 常在质量与吞吐间平衡；极致服务吞吐、能接受更强共享并有训练验证时考虑 MQA。已有 MHA checkpoint 直接改头数通常需转换与继续训练。

数学上需要全局精确 attention、长度在资源范围内时优先兼容的 Flash kernel，它省 IO/激活而不改结果。目标序列极长且任务以局部关系为主，可用滑动窗口/块稀疏真正减少 pair，但要设计全局通路并重新训练/验证。线性方法改变函数更多，应作为架构选择而非部署开关。

## 工程约束

检查 head_dim、dtype、mask/bias、GPU 和 tensor parallel 对 kernel/GQA 的支持；KV heads 少于设备数会影响分片。分别 profile prefill 与 decode：Flash 通常改善前者和训练，GQA/MQA尤其改善后者带宽，局部 attention在超长两阶段都可降配对。

## 决策流程

先用 MHA + 精确高效 kernel 建质量基线；绘制 KV heads 数对困惑度、任务指标、状态内存和 token/s 的曲线；再按长度比较全局与窗口方案；最后做部署 shape 分布的端到端测试。保留 mask 泄漏、full/decode 一致性和长程能力回归。

面试回答若先澄清三种变化位于“头共享—实现—连接图”不同层级，再给出质量、带宽、长度与兼容性的条件选择，就不会陷入“Flash 比 GQA 快多少”这类错误比较。
