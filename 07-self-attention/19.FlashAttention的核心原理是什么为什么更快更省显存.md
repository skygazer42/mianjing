# 19. FlashAttention 的核心原理是什么，为什么更快更省显存？

## 核心结论

FlashAttention 是精确 attention 的 IO-aware 实现。它不近似、不稀疏，而是把 Q、K、V 分块搬入 GPU 片上 SRAM，边计算 score、在线 softmax、边累积输出，避免把完整 \(L\times L\) score 和概率矩阵反复写入/读出高带宽显存 HBM。Attention 常受内存 IO 限制，少搬数据会更快并显著降低激活峰值。

## 分块与在线 softmax

对一个 Q block，依次遍历 K/V blocks。每读一块计算局部 \(S_b=Q_bK_b^\top\)，维护每个 query 行的运行最大值 \(m\)、指数和 \(\ell\) 和未归一化输出累积。遇到新块若最大值变化，旧累积按 \(e^{m_{old}-m_{new}}\) 重缩放，再加入新块贡献。遍历完后除以最终 \(\ell\)，结果等价于对整行做 stable softmax 再乘 V。

Causal、padding 或窗口 mask 可在每块 score 内应用，跳过完全不可见块还可省计算。反向通常不保存完整概率，而保存输出和行归一化统计，重新计算分块 score，以额外 FLOPs 换更少内存 IO。

## 为何省显存

朴素训练要保留 \(O(L^2)\) score/probability 激活；Flash 不将其物化到 HBM，主要保存 Q/K/V、输出和 \(O(L)\) 行统计，激活存储接近线性。算术配对仍是 \(O(L^2d)\)，只是 IO 复杂度和常数显著改善。

## 工程限制

实际速度受 GPU 架构、head dimension、dtype、序列长度、mask、dropout 和布局影响；很短序列或不支持形状可能收益小。数值结果与参考实现会因运算顺序、低精度舍入不同而非逐 bit 相同，应按容差比较输出/梯度和任务质量。

面试回答要抓住“tiling + SRAM reuse + online softmax + backward recompute”，并明确它是 exact、改 IO/显存而非改变二次 FLOPs。
