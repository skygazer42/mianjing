# 25. 融合 QKV、张量布局和 kernel 选择为什么影响性能？

## 融合投影

分别计算 \(XW_Q,XW_K,XW_V\) 会三次读取 X、发起三次 GEMM。把权重拼成 \(W_{QKV}\)，一次 GEMM 输出 QKV，可减少 kernel launch 和内存读取，尤其短序列/小 batch 有利。GQA 的 Q 与 K/V 输出宽度不同仍可融合，只需正确切分。

## 布局

Attention kernel 常期望 \([B,L,H,d_h]\) 或 \([B,H,L,d_h]\)。Transpose 本身可只是 view，但后续若要求 contiguous 会触发大规模复制。选择从投影输出就匹配 kernel 的 packed/interleaved 布局，可避免 permute；反之错误 stride 甚至会把 head/sequence 混淆而不 shape 报错。

Head dimension 是否为 8/16 等硬件友好倍数、dtype、对齐和 sequence lengths 会影响 tensor core 利用率。QKV 融合省的是投影 IO，Flash 融合的是 score-softmax-AV IO，两者可同时使用。

## Kernel 分派

框架可能在 Flash、memory-efficient、math reference 间自动选择。自定义 float mask、特殊 bias、过大 head_dim、需要返回完整 attention weights 或旧 GPU，都会触发回退。结果仍正确但速度/显存突变，所以生产 benchmark 要记录实际 kernel，而非只看 API 名称。

## 测量

预热、同步设备、按实际 batch/长度分布测 p50/p95；用 profiler 看 GEMM、transpose/copy、softmax 和 kernel launch。分别测 prefill 与 decode。融合可能增加寄存器压力，特定小 shape 不一定更快，需以端到端数据为准。

## 正确性

用参考实现比较输出/梯度，覆盖非连续输入、GQA、causal/padding、奇特长度和 dropout。面试回答应说明性能来自减少 X/HBM 读取、避免布局复制和选择兼容 kernel，而不只是“融合后 kernel 数少”。
