# 13. MHA、MQA 和 GQA 的结构及取舍是什么？

## 结构

设 query 头数 \(H_q\)、KV 头数 \(H_{kv}\)。

- MHA：\(H_{kv}=H_q\)，每个 query head 有独立 K/V。
- MQA：\(H_{kv}=1\)，所有 query heads 共享一组 K/V。
- GQA：\(1<H_{kv}<H_q\)，每组 \(g=H_q/H_{kv}\) 个 query heads 共享一个 KV head。

三者通常保持 query 总宽度与输出宽度不变，因此仍有多套 query/attention 分布；变化主要在 K/V 投影参数、状态体积和读取带宽。

## 为什么能加速

逐 token 解码时 query 只有一个位置，却需读取历史 K/V。MHA 每层读取 \(H_qLd_h\) 的 K 和 V；MQA 降为 \(Ld_h\)，GQA 降为 \(H_{kv}Ld_h\)。在内存带宽受限阶段，共享能明显提升吞吐并减少状态内存。Prefill 的 QK/AV 总输出仍按 \(H_q\) 计算，算术二次项不按 KV 头数同倍下降。

## 质量折中

MHA 给每头独立的 key/value 子空间，容量最大；MQA 共享最强，可能让不同 query heads 接收到相同 value 表达，质量风险更高；GQA 在二者之间，常以较少 KV heads 保留大部分质量。实际差异取决于从头训练还是将 MHA uptrain/转换、模型宽度、任务和 KV group 数。

## 实现要点

要求 \(H_q\) 通常可被 \(H_{kv}\) 整除，映射可写为 kv_head = floor(q_head / g)。K/V 应以 stride/broadcast 被各 Q 组使用，显式 repeat 会吃掉内存收益。Tensor parallel 下 KV heads 太少时可能不能均匀分到设备，需要复制少量 KV 头或调整并行策略。

## 面试回答

先给 \(H_{kv}\) 三种关系，再从“解码带宽/内存—表示容量—并行便利”比较。不要说 MQA 只有一个 attention head，它仍有多个 Q heads 和多套权重；共享的是 K/V 投影头。
