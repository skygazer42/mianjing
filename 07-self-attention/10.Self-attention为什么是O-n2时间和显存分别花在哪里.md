# 10. Self-attention 为什么是 \(O(n^2)\)，时间和显存分别花在哪里？

## 复杂度来源

序列长度 \(n\)、每头维 \(d_h\)、总宽度 \(d\) 时，每个 query 要与 \(n\) 个 keys 比较，共 \(n^2\) 对。QK 矩阵乘和 AV 矩阵乘各约 \(O(n^2d)\)；显式 score/softmax 矩阵大小为 \(O(Hn^2)\)。因此长序列翻倍时，attention 配对计算约四倍。

完整 Transformer 层还包含 QKV/输出投影 \(O(nd^2)\) 与 FFN \(O(ndd_{ff})\)。当 \(n\ll d\) 时线性层可能更贵，不能看到 attention 就断言总耗时被 \(n^2\) 主导；当 \(n\) 很长时二次项逐渐占主导。

## 训练显存

朴素实现为反向保存 Q、K、V、score、softmax 概率、dropout mask 和输出等。最大问题常是 \([B,H,n,n]\) 概率矩阵，随 \(n^2\) 增长。混合精度虽让元素字节减半，无法改变阶数。梯度与激活、框架临时 workspace 也要计入峰值。

FlashAttention 通过分块和在线 softmax 不把完整 score/概率写回 HBM，显著降低中间显存到近似线性级激活，但仍计算所有 \(n^2\) 配对，所以算术复杂度依旧 \(O(n^2d)\)。稀疏/局部 attention 才通过少算配对改变复杂度。

## 推理形状

整段 prefill 仍是 \(n\times n\)（因果情况下只需有效三角，但量级不变）；逐 token 时 query 长度为 1，与前缀 \(n\) 个 keys 比较，单步 attention 是 \(O(nd)\)，生成多个 token 累积仍随总长度增长。本题不展开 KV-cache 的存储设计。

## 面试要点

应分别报：算术 \(O(n^2d)\)、显式矩阵显存 \(O(Hn^2)\)、线性投影 \(O(nd^2)\)。再解释 FlashAttention 优化 IO/显存而不改二次算术，局部/稀疏方法才减少 pair 数。实际判断要用 profile，而非只看渐进符号。
