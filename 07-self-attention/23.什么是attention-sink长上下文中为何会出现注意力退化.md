# 23. 什么是 attention sink，长上下文中为何会出现注意力退化？

## 现象

Attention sink 指某些位置，常是序列开头或特殊 token，即使内容不相关也吸收大量注意力。Softmax 权重必须和为 1，当某个 query 没有明显相关 key 时，模型可能把多余概率放到一个稳定“汇点”；训练中首 token 对所有后续位置都可见，容易形成这种角色。

## 长上下文退化原因

序列变长后候选 keys 更多，softmax 分母和极值统计变化，干扰项增多；位置机制进入训练外范围；局部训练让模型缺少远距路由；有限精度和 mask/窗口策略也可能造成问题。Sink 本身有时是模型维持稳定计算的机制，但在滑动窗口中若把早期 sink token 移出，attention 分布会突变、困惑度上升。

这不意味着“首 token 权重高就是 bug”。它可能承载全局边界/归一化功能，也可能是无内容的概率泄压。需要通过移除、替换、保留少量 sink tokens 的受控实验，看 loss 与输出是否变化。

## 诊断

按层/头/位置统计接收注意力总量、熵和随长度的变化；将同一内容整体平移、改变 BOS 内容或截断前缀，观察模式。结合 value norm 和输出贡献，避免只看 A。长上下文同时测位置分桶 loss、远距任务和局部质量，区分 sink、位置外推与单纯干扰。

## 工程应对

流式/窗口推理若模型依赖开头 sink，可保留最初少量 token 加最近窗口；但具体策略必须在该 checkpoint 上验证。训练层面可覆盖多长度、窗口模式与边界位置，或采用更适合流式的架构。不要随意把 sink 权重归零，可能破坏已学习平衡。

面试回答应说明 softmax 归一化、首 token 永久可见和滑窗移除的关系，并把 sink 视为可测行为而非单一故障标签。
