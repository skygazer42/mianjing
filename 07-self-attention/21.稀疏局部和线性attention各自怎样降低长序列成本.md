# 21. 稀疏、局部和线性 attention 各自怎样降低长序列成本？

## 局部与稀疏

局部 attention 让每个 query 只看宽度 \(W\) 的邻域，配对从 \(L^2\) 降为约 \(LW\)。它适合语言、音频等强局部性数据，但单层无法直接连接远端；堆叠层、dilation、全局 token 或跨块记忆可扩大感受野。

一般稀疏 attention 预定义或学习若干连接，例如窗口 + 全局、块稀疏、随机边。复杂度取决于非零 pair 数。结构化 block sparsity 更容易被 GPU 利用；理论很稀疏但索引不规则可能因 gather/调度开销不比稠密 Flash 快。

## 线性 attention

尝试用核特征分解 softmax：

\[
\operatorname{Attn}(Q,K,V)
\approx D^{-1}\phi(Q)(\phi(K)^\top V),
\]

其中 \(\phi(\cdot)\) 是将 query/key 映射到非负核特征空间的特征映射，\(D\) 是逐 query 的归一化对角矩阵；例如非因果情形下可写成 \(D=\operatorname{diag}(\phi(Q)(\phi(K)^\top\mathbf 1))\)。没有这个分母，结果不是对 value 的归一化加权。

利用结合律先算 \(\phi(K)^\top V\)，把序列复杂度降到近似线性。代价是 softmax 核近似、数值归一化和因果前缀累计更复杂，表达与精确 attention 不同；某些线性/状态空间变体需要专门训练，不能把已有模型 kernel 直接替换。

## 信息与硬件折中

局部稀疏少算 pair，可能漏掉任意远程关系；线性方法全局聚合，却压缩到固定统计，可能丢失细粒度检索能力。FlashAttention 则保留所有 pair 和精确结果，只优化 IO，所以仍二次。三者解决层级不同。

## 选择与评估

比较同参数、同训练预算下的困惑度、长程任务、吞吐与峰值内存；检查实际 kernel 利用率，而非只报渐进复杂度。文档任务可用局部 + 少量全局 token，流式任务偏因果线性/状态方法，要求任意 token 精确匹配且长度可控则 Flash 更稳。

面试回答应给 \(O(LW)\) 与核结合律，并指出“更低复杂度通常改变可见图或 attention 函数”，需要训练适配和任务验证。
