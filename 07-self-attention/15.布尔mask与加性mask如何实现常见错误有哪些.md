# 15. 布尔 mask 与加性 mask 如何实现，常见错误有哪些？

## 两种表示

布尔 mask 直接表示某个 query-key pair 是否允许；加性 mask 则在 logits 上加 0（允许）或 \(-\infty\)/足够负值（屏蔽）：

\[
A=\operatorname{softmax}(S+M).
\]

高效 attention API 可能接收 bool、float bias 或单独的 is_causal。最危险的是不同库对 True 的定义相反：有的 True=keep，有的 True=mask out，迁移时必须查接口并做小测试。

## 常见错误

1. 把 0/1 mask 直接加到 logits，只差 1 并未屏蔽。
2. 在 softmax 之后把权重乘 0，却不重新归一化；输出总质量缩小，dropout 之外通常不等价。
3. 使用 -1e4 在某些 dtype/极端 logits 下仍不够负，或用 -1e30 转 FP16 产生 Inf 并触发异常 kernel。
4. Mask shape 从 \([B,L]\) 错广播到 query 轴，屏蔽了 PAD query 却没有屏蔽 PAD key。
5. Causal 三角方向反了，模型只能看未来。
6. 一行全部被屏蔽，减 max 时出现 \(-\infty-(-\infty)\) 导致 NaN。

## 组合与数值

先在逻辑域合并 padding、causal、segment，再一次转 additive 通常更安全。若必须合并多个 float bias，确认不会把可见位置误加大负值。Stable softmax 可对全 mask 行定义输出全零，或者从数据层确保每个有效 query 至少可看一个 key。

## 测试

用 \(QK=0\)、V 为单位基向量，输出会直接显示可见位置的均匀平均，容易手算。对被屏蔽 token 做极大扰动，目标输出必须不变；检查概率和梯度都为 0。融合 kernel 与 reference 实现要覆盖 bool/additive、左右 padding、cross-attention 和 \(L_q\ne L_k\)。

面试回答应说清 mask 必须在 softmax 前作用于 logit，指出 True 语义、广播轴与全 mask 行三大坑。
