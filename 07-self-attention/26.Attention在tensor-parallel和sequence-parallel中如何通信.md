# 26. Attention 在 tensor parallel 和 sequence parallel 中如何通信？

## Tensor parallel

常见 head parallel 把 Q/K/V 的 heads 沿设备分片，每张卡在本地计算所属 heads 的 attention；拼头后的输出投影按列/行并行，通常需要一次 all-reduce 或 reduce-scatter 合并 residual 结果。只要每个 head 的完整 \(d_h\) 和所需序列 K/V 在本地，QK/softmax/AV 不必跨卡通信。

GQA/MQA 带来特殊问题：KV heads 可能少于 TP 设备数，无法均匀分片。可复制 KV heads 到多卡以减少通信，或让设备在组内共享/通信；复制增加存储但常比每步传 K/V 更划算。Checkpoint 切分必须保持 query group 到 KV head 的映射。

## Sequence/context parallel

若沿序列分片，每卡只持部分 tokens。每个 query 要看全局 keys 时，需要 all-gather K/V、环形交换 blocks，或在线累计局部 softmax。分布式 softmax必须合并全局行最大值和指数和：先 all-reduce max，再按新最大值重标定并合并 sum/输出；不能对每卡局部 softmax 后简单平均。

Sequence parallel 也常指把 LayerNorm/dropout 等激活沿序列分散，并在进入 tensor-parallel线性层前后用 all-gather/reduce-scatter，具体术语因框架而异。面试应先说明分片轴和每个算子需要的数据，而非只背名称。

## 通信—计算折中

长序列 attention 计算大，可用 ring attention 将 K/V blocks 流过设备并与本地 Q 计算重叠，降低单卡内存；代价是通信量和同步。网络拓扑、batch、head 数与 causal 跳块决定收益。Flash tiling 是单卡 IO 优化，context parallel 是跨卡数据分布，可组合。

## 验证

与单卡参考比较前向/梯度；覆盖不整除的 heads/长度、GQA、causal 和 dropout RNG。Profile all-reduce/all-gather 占比及 overlap，而非只看 FLOPs。

面试回答可概括：头分片让 attention 本地、输出需归约；序列分片让 K/V 跨卡，softmax统计必须全局合并。
